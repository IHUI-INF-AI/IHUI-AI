# @ihui/tool-contract · ITCP v0.1

工具契约协议（IHUI Tool Contract Protocol）的**独立采纳包**。零依赖、零运行时：只有类型声明、派生谓词与一份可对照的规范正文。

## 这是什么

一个工具怎样声明自己，才不是"注释里的君子协定"，而是**可机检的契约**。四件套：

一份声明（`ToolContract`）+ 一个守门（棘轮只降不升）+ 一份消费账（字段 → 消费者 → 行为 → 测试）+ 一个一致性运行器（五项读数）。

判据只有一条总原则：**声明必须有人读**。写了字段却没有任何生产路径消费它，等价于空支票。

## 包含

- `src/tool-contract.ts` — 契约类型（`shape` / `permission` / `resultBudget`）、值域常量、派生谓词（`mayWriteWorkspace` / `touchesExternalWorld` / `humanApprovalMandated`）、路由身份键清单。**零 import**，可单独编译。
- `docs/tool-contract-protocol.md` — ITCP v0.1 规范正文：字段表、三级状态机（声明 → 消费者 → 基线锁）、守门判据、conformance 三态、兼容规则、采纳三步、非目标。

## 三步采纳

1. **声明**：在工具上写 `contract`（三组字段）；`write` / `dangerous` 档必须补 `confirmation`。
2. **接消费者**：让生产路径真正读该字段，并把位置（`文件:行`）写进你的消费账。没接消费者的字段只能标"保留位"，不得说成已启用。
3. **锁基线**：一条测试钉住行为（声明 → 消费者 → 行为变化），防回退。

## conformance 只有三态

- `ok` — 五项读数全零 + 自检 0 失败。
- `not-ok` — 任一读数非零。
- `unknown` — 判定方**拒绝回答**（例如守门与被判修订不同代）。

`unknown` 不读成通过。跨代模式（新判据去判旧树）的读数属失真读数，不进发布账。

## 与本仓的关系

本仓是参考实现：类型与谓词在 `packages/types/src/tool-contract.ts`，守门在 `scripts/check-tool-contract-declared.mjs`，读数在 `scripts/tool-contract-conformance.mjs`，消费账在 `docs/engineering/tool-contract-consumers-2026-11-27.md`。

本包内容由 `scripts/sync-itcp-package.mjs` 从上述源**逐字节同步**生成（首部只多一行 AUTO-SYNCED 提示）。不要手改本包；要改请改源文件并重跑同步，`--check` 会把"两边不一致"判红。
