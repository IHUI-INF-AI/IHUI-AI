# WorkBuddy 会话搬家设计定案(⑦第二刀前置 · 2026-10-27)

> 本文是⑦「会话搬家」写操作链的**设计定案**。取证事实见
> `docs/RELAY_SESSION_MIGRATION_EVIDENCE.md`(本目录,同日)。
> 定案前决不施工任何写面;本文批准前,仓内只有只读盘点(`pnpm relay:sessions`)
> 与备份(`pnpm relay:sessions:backup`)两腿,二者对会话库**零写入、零删除**。

## 1. 目标与范围

把 WorkBuddy 助手本机会话库(`~/.workbuddy/workspace/sessions/`、
`~/.workbuddy/projects/` 下转写)按账号隔离/搬移,对标 wb-switch 的能力面:

- 备份(已落地):全量快照到 `~/.wb-switch/backups/sessions/<时间戳>/`,带 sha256 清单。
- 恢复(设计票):从快照回填,`manifest.json` 逐文件 sha256 校验,任何 mismatch 拒绝继续。
- 搬移/隔离(设计票,依赖恢复腿 + 账号关联模型):按账号建会话分桶台账。

## 2. 红线(任何写面实现必须全部满足,违一即停)

1. **备份先行**:任何改动会话库的命令,第一步必须产出当日快照;当日快照已存在则校验后复用,不重复拷贝。
2. **预览先行**:所有写面命令默认 dry-run,只打印将动文件清单(路径+字节数,不打印内容);真写必须显式 `--apply`。
3. **逐条可撤**:每轮写操作生成操作日志(`manifest.json` + `ops.jsonl`),记录动前动后状态;恢复腿必须能按单条操作回退。
4. **零内容回显**:日志/预览/错误信息永不包含 token、消息正文;只出现路径、字节数、sha256。
5. **校验后收工**:拷贝/回填后逐文件 sha256 对账,数量与字节双重核对;对不上即报错退出,不留半写状态(先写临时名,全量校验过后再原子改名)。
6. **源只读**:盘点/备份腿对源目录只 `readFileSync`/`statSync`,绝不 `write`/`unlink`/`rename` 源侧任何路径。

## 4. 恢复腿设计(已施工:含逐条可撤)

- 输入:快照目录 + 目标根(默认原源根;`--dest` 可指他处做"搬家到另一台机/另一目录")。
- 流程:dry-run 列差异(目标缺失/内容不一致,按 sha256 比)→ `--apply` 时逐文件先写
  `<file>.restoring-<ts>` 临时名 → sha256 校验 → 原子 rename 覆盖 → 全量对账收工。
- 拒绝场景:目标存在且 sha 不一致且未显式 `--force`(宁可拒做,不静默覆盖);
  manifest 缺失或 sha256 字段缺失(旧格式快照不认)。

## 5. 搬移/隔离设计(已施工:move/restore/undo + 台账)

- 前置一:恢复腿收工(可撤能力的载体)。
- 前置二:**账号↔会话关联模型定案**——当前会话库无按账号分桶标记(取证记录 §4);
  候选方案 A:按 `accounts.json` + 切换时刻分桶(切换后新增会话归新账号,存量归"未归属");
  方案 B:人工标注台账。两者都要求隔离台账(`*_session_links.json` 同形)先建、后动。
- 施工顺序:台账建 → 试运行单会话搬移(可撤) → 抽样校验 → 全量。任一步失败按操作日志回退。

## 6. 开放问题(已拍板)

1. 方案 A/B → **方案 A**(机器可判,存量显式标"未归属"不猜)。
2. 搬移粒度 → **最小粒度单会话**;批量入口 `move --account` 只是"逐会话计划的循环",
   每条仍各自记账、各自 undo。
3. 关联键 → **conversationId 文件名主干**(真实数据抽样已核,见取证记录)。

## 7. 账号时间线自动推导(2026-10-27 增补)

`rebuild --auto` 的机器证据面 = 登录态快照库
`~/.wb-switch/backups/workbuddy-desktop.<ts>.info`:

- 每份快照记录"**ts 时刻切换前活跃的账号**"(`account.uid`),故该账号活跃区间 =
  `[上一份快照时刻, 本份快照时刻)`;当前 auth 文件账号 = `[最后快照时刻, now)`。
- **最早一段无下界** ⇒ 默认标未归属(方案 A 不猜:快照只证明"ts 时活跃",不证明更早);
  确认最早账号即唯一账号时加 `--trust-earliest` 归它(放宽须显式给旗)。
- 账号不可判的快照(坏文件/缺 uid)⇒ **该段整段标未归属**,绝不借邻居账号。
- 相邻同账号段合并;`--auto` 与 `--since/--account` 互斥;当前登录态不可判或快照库为空
  ⇒ exit 2,不产出半残台账。
- 输出零 token、手机号打码,段清单只出现 uid 前 8 位与标签。

**真机实证(2026-10-27)**:本机快照序列推出 3 段(14f9 → 2591 → 14f9),271 条台账
记录中 11 条归当前账号、260 条为"最早快照前的存量"如实未归属;9 个可搬会话、
2 个 `editor-sdk-<pid>-*` 临时目录已随客户端进程消失(跳过并点名)。

**搬移写面真机闭环(2026-10-28 更正原「未做」条)**:实测 WorkBuddy 有**自启守护**
(taskkill 优雅/强制各一次,8 进程换 PID 重启为 9),"先退出客户端"结构上做不到;
故 `--apply` 存续闸改为**定向理由可放行**(`--force-running-reason "<≥10字>",
无理由/短理由仍 exit 2)。在此前提下单会话 `move → undo` 真机往返逐字节全等、
`swap` 走「换出 9 → 切 auth → 换入 9 → 切回 auth」终态 sha 全等且桶内零残留。

## 8. 并发/跨客户端强化(2026-10-28)

1. **会话库共享锁**:备份(读全库)、恢复(写全库)、搬移/复制/换桶(读写单会话)
   争的是同一棵树 ⇒ 共用一把 `session-store.lock`(O_EXCL;活持有者拒绝、死/超 30min
   TTL 归档 `.stale` 后抢占、`release` 只删自己那份)。只读档(dry-run/`--list-ops`/`stats`)
   不取锁。台账只写 `session_links.json`,与文件树不冲突,单用 `session-links.lock`。
   接线锁测试证明 move/links/backup/restore 的 `--apply` 真取锁(外部持锁即整批拒)。
2. **客户端镜像名可配**:`detectClientProcesses` 取值次序 = 显式入参 >
   env `IHUI_RELAY_CLIENT_IMAGE`(逗号分隔)> `WorkBuddy.exe`。Qoder/Trae 搬家**必须**
   先把各自进程名传进来 —— 失效方向是"名字没配 = 探测不到 = 存续闸形同虚设",
   不是安全默认。`detectWorkbuddyProcesses` 留作兼容别名。
3. **undo 号跨归档**:`ops rotate` 把老条目移出主日志 ⇒ 主日志行号前移,
   用户手里的旧号会撤错。现 `ops` 号按「归档(日期升序)⊕ 当前」全序解释,
   `ops` 命令对归档条目标 `[归档]`,缺条报错点名归档计数。
