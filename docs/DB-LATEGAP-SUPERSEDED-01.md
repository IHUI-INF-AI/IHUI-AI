# DB-LATEGAP-SUPERSEDED-01 lateGap 覆盖注记（裁定二落地）

> 状态：2026-11-07 实现并配夹具；门未改判据结构，只加注记桶与输出字段。

## 1. 立因

`20260916170000_api_subscription_windows_and_peak_pricing` 是 lateGap：它**从未实际执行**
（窗口前 3 表 / 8 列 / 7 索引全缺，全 376 个迁移无 DROP 指向它们），但全部效果已由
`20261107000000_repair_api_subscription_drift`（#2）逐条同文重建并入账。
工具原先只有「账本有行才算绿的」一个出口，逼得要么长期红、要么补一条假账本行。
裁定二给出第三个出口：**覆盖注记**。

## 2. 三条硬条件（写死）

1. **结构上永不进 `applied`**：`classifyMigrationGaps` 不改；注记只对 `lateGap` 分组，
   条目仍留在 `lateGap` 桶与 `lateGapTotal` 计数里。
2. **输出必须带 `coveredBy` 与 `effectiveAt`**：`--json` 的 `lateGapSuperseded[]` 逐条给出。
3. **`--json` 里与 `lateGap` 分开，且条目仍可被数到**：`lateGap` 保留原始全量列表，
   另加 `lateGapSuperseded` / `lateGapUnresolved`；**不允许**出现「被覆盖条目从 lateGap 消失」的读数。

附加纪律：

- 有注记的条目**不会被 `--repair` 补账本行**（那等于断言一件没发生过的事）。
- 清单不合法（`coveredBy` 不在 journal、`coveredBy` 的 when 不大于本条目、日期非法、重复条目、
  缺 `reason`）⇒ **exit 2**，不静默降级。
- 红只由「无注记的 lateGap」与「未豁免 hashDrift」触发。

## 3. 实现位置

| 位置 | 内容 |
|---|---|
| `scripts/data/late-gap-superseded.json` | 注记清单（当前 1 条：`20260916170000…` ← `20261107000000…@2026-11-07`） |
| `scripts/check-db-migration-gaps.mjs` | `loadLateGapSuperseded()`（清单校验）、`partitionLateGap()`（分组）、`--superseded` 选项、`--json` 三个字段、人读输出、`--repair` 跳过逻辑 |
| `scripts/tests/check-db-migration-gaps.test.mjs` | 夹具：合法注记、无注记仍红、总数守恒（superseded + unresolved == lateGap）、非法清单逐条报问题 |
| `scripts/check-db-migration-gaps.mjs --self-test` | S11–S14 同口径 |

## 4. 输出契约

```
--json:
{
  "lateGap": [ { "tag": "...", "when": 1722377600000 } ],   // 原始全量,不消失
  "lateGapTotal": 1,
  "lateGapSuperseded": [ { "tag": "...", "when": ..., "coveredBy": "...", "effectiveAt": "2026-11-07", "reason": "..." } ],
  "lateGapUnresolved": []
}

人读:
应用账本: applied=... / lateGap=1(覆盖注记 1,无注记 0) / pending=... / hashDrift=...
  ℹ️ 中间缺口已被后续迁移逐条同文覆盖(不进 applied,仍计入 lateGap): tag ← coveredBy@effectiveAt
GAPS-RESULT state=ok lateGap=1 lateGapSuperseded=1 lateGapUnresolved=0 pending=0 ...
```

## 5. 关闭条件

- 若该 tag 在某个环境**真实执行**并产生自证账本行，则从注记清单移除（它已不是 lateGap）。
- 若该 tag 的迁移文件被删除 / 效果被回退，注记失效，须同步删除否则清单校验会报 `coveredBy` 或
  `journal` 缺项（exit 2）。
- 不需要这个出口时，删除整个清单文件会走「读不到 ⇒ exit 2」；如需静默关闭，应改代码而不是留空文件。
