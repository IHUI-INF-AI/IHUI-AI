# 考勤导入操作指引（HR 用）

> 适用对象：HR / 人事专员  
> 最后更新：2026-11-13  
> 功能入口：人事管理 → 考勤导入（需 `hr:attendance:manage` 权限）

---

## 一、功能说明

本功能用于把**飞书 / 钉钉 / 企业微信**导出的考勤表导入系统。支持四类记录：

| 记录类型 | `importKind` 参数 | 说明 |
|---|---|---|
| 打卡记录 | `attendance`（默认） | 上下班打卡时间、迟到/早退/缺卡状态 |
| 请假记录 | `leave` | 请假类型、开始/结束日期、天数、事由 |
| 加班记录 | `overtime` | 加班日期、时长、类型、事由 |
| 外出记录 | `outgoing` | 外出时段、地点、事由 |

**核心机制**：
- ✅ 自动识别飞书/钉钉表头（不用手动对列）
- ✅ 上传后**不直接改正式考勤**，先暂存等你核对
- ✅ 差异行（系统已有 vs 导入表）需**人工裁决**才落库
- ✅ 同月份同一份文件（按 SHA-256）重复上传会被拒绝

---

## 二、第一步：从飞书/钉钉导出考勤表

### 飞书导出步骤

**打卡记录**：
1. 登录 [飞书管理后台](https://feishu.cn) → 「考勤」
2. 左侧「考勤统计」→「打卡记录」
3. 选择月份（如 2026-11）→ 点击「导出」
4. 格式选 **Excel（.xlsx）**，下载到本地

**请假/加班/外出记录**：
1. 「审批」→「审批数据导出」
2. 勾选对应审批类型（请假/加班/外出）
3. 选择时间范围 → 导出 Excel

### 钉钉导出步骤

**打卡记录**：
1. 登录 [钉钉管理后台](https://oa.dingtalk.com) → 「考勤打卡」
2. 「考勤统计」→「打卡明细」
3. 选月份 → 「导出报表」→ Excel 格式

**请假/加班/外出**：
1. 「OA 审批」→「审批数据」
2. 筛选对应类型 → 「导出」→ Excel

### 企业微信导出步骤

1. 登录 [企业微信管理后台](https://work.weixin.qq.com) → 「应用管理」→「打卡」
2. 「打卡记录」→ 选月份 → 「导出」
3. 请假/加班在「审批」应用里导出

> 💡 **导出格式建议**：优先 `.xlsx`（Excel 2007+），避免 `.csv` 编码问题。

---

## 三、第二步：上传到系统

### 上传参数

| 参数 | 必填 | 说明 | 示例 |
|---|---|---|---|
| 考勤月份 `periodMonth` | ✅ | 格式 `YYYY-MM` | `2026-11` |
| 记录类型 `importKind` | ❌（默认打卡） | 四选一 | `attendance` / `leave` / `overtime` / `outgoing` |
| 文件 | ✅ | `.xlsx` / `.xls` / `.csv`，≤10MB | `飞书打卡2026-11.xlsx` |

### 操作步骤

1. 进入「人事管理 → 考勤导入」
2. 点击「上传打卡表」
3. 选择文件，填写：
   - **考勤月份**：`2026-11`（必须与文件内数据月份一致）
   - **记录类型**：打卡选「考勤打卡」，请假选「请假记录」，以此类推
4. 点击「上传并解析」

### 解析结果

上传成功后，系统返回：

```json
{
  "batchId": "uuid-xxx",
  "importKind": "attendance",
  "status": "pending_review",
  "totalRows": 520,
  "matchedRows": 498,
  "conflictRows": 15,
  "notFoundRows": 7,
  "mapping": {
    "工号": "employeeNo",
    "姓名": "employeeName",
    "上班打卡": "checkInTime",
    "下班打卡": "checkOutTime"
  },
  "preview": [
    {"row": 1, "工号": "E001", "姓名": "张三", "上班打卡": "09:00", "下班打卡": "18:30"},
    ...
  ]
}
```

**字段含义**：
- `totalRows`：导入表总行数
- `matchedRows`：成功匹配到系统员工的行数
- `conflictRows`：与系统已有记录**冲突**的行数（如打卡时间不一致）
- `notFoundRows`：**未匹配**到系统员工的行数（工号/姓名对不上）

---

## 四、第三步：核对差异行

点击「批次详情」，查看所有行的匹配状态：

| 状态 | 含义 | 操作 |
|---|---|---|
| `matched` | 系统已有且一致 | ✅ 无需处理，确认时自动写入 |
| `conflict` | 系统已有但不一致 | ⚠️ **必须裁决**（见下） |
| `not_found` | 系统无对应员工 | ⚠️ 建议核对工号/姓名，或跳过 |

### 差异行裁决

对每一行 `conflict`，三选一：

| 裁决选项 | `resolution` | 说明 |
|---|---|---|
| 采用导入值 | `adopt_import` | 用飞书/钉钉的数据覆盖系统 |
| 保留系统值 | `keep_system` | 忽略导入表，保留系统当前记录 |
| 人工填写 | `manual` | 手动输入最终值（如修正后的打卡时间） |

**操作方式**：
1. 点击差异行 → 「裁决」
2. 选择处理方式
3. 若选「人工填写」，输入最终值：
   ```json
   {
     "resolution": "manual",
     "finalValue": {
       "employeeNo": "E001",
       "checkInTime": "09:05",
       "checkOutTime": "18:30"
     }
   }
   ```

> ⚠️ **所有 `conflict` 行必须裁决完才能确认批次**，否则确认按钮会拒绝。

---

## 五、第四步：确认写入正式考勤

1. 所有差异行裁决完毕后，点击「确认批次」
2. 系统把暂存数据写入**正式考勤记录**
3. 确认后批次状态变为 `confirmed`，**不可撤销**

### 常见问题

**Q1：上传报错「仅支持 .xlsx/.xls/.csv」**  
A：检查文件扩展名，飞书/钉钉默认导出就是 `.xlsx`，若被改过名需改回。

**Q2：上传报错「文件不能超过 10MB」**  
A：大企业月度打卡表可能超限，拆分成上下半月两个文件分别上传。

**Q3：解析失败「表头识别不出」**  
A：系统内置别名表（见下表），若你的表头不在别名里，需手动改列名或联系开发扩展别名。

**打卡表头别名**：
- 工号：`工号` / `员工工号` / `员工编号` / `人员编号` / `工号/编号` / `employeeid` / `employeeno`
- 姓名：`姓名` / `员工姓名` / `人员姓名` / `名字` / `name` / `employeename`
- 日期：`日期` / `考勤日期` / `打卡日期` / `出勤日期` / `date`
- 上班打卡：`上班打卡` / `上班打卡时间` / `上班时间` / `首次打卡` / `上班1` / `checkin`
- 下班打卡：`下班打卡` / `下班打卡时间` / `下班时间` / `末次打卡` / `下班1` / `checkout`

**请假表头别名**：
- 假别：`假别` / `假期类型` / `请假类型` / `假期种类` / `类型`
- 开始日期：`开始日期` / `起始日期` / `开始时间` / `请假开始`
- 结束日期：`结束日期` / `截止日期` / `结束时间` / `请假结束`
- 请假天数：`请假天数` / `天数` / `时长`
- 审批单号：`审批单号` / `单号` / `申请单号` / `实例编号`

**Q4：`not_found` 行怎么处理？**  
A：说明工号/姓名在系统里找不到对应员工。建议：
1. 核对工号是否输错（如 `E001` vs `001`）
2. 若是新员工还没建档，先去「员工管理」建档，再重新上传
3. 确认批次时 `not_found` 行会**自动跳过**，不影响其他行写入

**Q5：确认后发现导错了想撤回**  
A：确认后不可撤销。补救办法：
1. 手动去「考勤记录」删除错误数据
2. 或等待下个月上传正确数据覆盖（若系统支持 `adopt_import` 裁决）

**Q6：同一月份重复上传会怎样？**  
A：系统按文件 SHA-256 判重，同月份同一份文件会被拒绝。若需重新导入，先「作废」原批次，或改文件内容（哪怕加个空格）再上传。

## 六、最佳实践建议

### ✅ 推荐做法

1. **每月固定时间导入**：建议每月 1-3 号导入上月考勤，避开发薪日高峰
2. **先核对再确认**：解析后先看 `conflictRows` 和 `notFoundRows`，裁决完再点确认
3. **保留原始导出文件**：万一导入出错，可追溯原始数据
4. **四类记录分开上传**：打卡、请假、加班、外出各传一次，避免混在一张表里
5. **新员工先建档**：导入前确保所有员工已在系统建档，减少 `not_found`

### ❌ 避免踩坑

1. **不要改导出文件的表头**：系统靠表头别名识别，改了就识别不出
2. **不要跳过裁决直接确认**：`conflict` 行未裁决会被拒绝，且可能掩盖真实差异
3. **不要重复上传同月份文件**：会被 SHA-256 判重拒绝，除非作废原批次
4. **不要在文件里加合并单元格**：可能导致解析器读不到完整数据

## 七、API 接口速查（开发/高级用户）

| 操作 | 方法 | 端点 | 权限 |
|---|---|---|---|
| 上传并解析 | `POST` | `/api/hr-import/batches` | `hr:attendance:manage` |
| 批次列表 | `GET` | `/api/hr-import/batches` | `hr:attendance:manage` |
| 批次详情 | `GET` | `/api/hr-import/batches/:id` | `hr:attendance:manage` |
| 裁决单行 | `POST` | `/api/hr-import/rows/:rowId/resolve` | `hr:attendance:manage` |
| 确认批次 | `POST` | `/api/hr-import/batches/:id/confirm` | `hr:attendance:manage` |
| 作废批次 | `DELETE` | `/api/hr-import/batches/:id` | `hr:attendance:manage` |

**上传请求示例（curl）**：
```bash
curl -X POST http://your-domain/api/hr-import/batches \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -F "periodMonth=2026-11" \
  -F "importKind=attendance" \
  -F "file=@飞书打卡2026-11.xlsx"
```

## 八、技术支持

- **权限问题**：联系系统管理员开通 `hr:attendance:manage`
- **表头识别失败**：把你的导出文件表头截图发给开发，申请扩展别名表
- **数据差异争议**：以系统内正式考勤为准，导入表仅作参考
