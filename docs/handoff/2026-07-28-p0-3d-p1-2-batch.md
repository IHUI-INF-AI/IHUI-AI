## 3. 关键修复(4 项 P0 段)

### 3.1 scheduler-worker case 'budget-alert-check' 缺失

**问题**:`budget-alert-service.ts` 创建后,scheduler-worker.ts 没有对应 `case`,导致 BullMQ 入站后落入 `default: throw new Error("unknown scheduled job")`,定时任务全失败。

**修复**:`apps/api/src/workers/scheduler-worker.ts` 添加:

```ts
case 'budget-alert-check': {
  await checkBudgetAlerts(job.data);
  break;
}
```

**验证**:`pnpm --filter @ihui/api typecheck` exit 0;运行时 30/30 mock 验证 budget-alerts 端点返回真实数据。

### 3.2 seed step 11 缺失

**问题**:`ai-cost-records-seed.ts` 创建后未注册到 `seed/index.ts`,`pnpm db:seed` 不会执行该 step。

**修复**:`packages/database/seed/index.ts` step 11 注册 ai-cost-records-seed + aiBudgets upsert 流程。

**验证**:`pnpm --filter @ihui/database seed` 后 `SELECT COUNT(*) FROM ai_cost_records` 返回 420-1260 条;`SELECT COUNT(*) FROM ai_budgets WHERE scope='user'` 返回 3 条(其中 1 条 dailyTokenLimit=50_000 故意触发 critical 告警)。

### 3.3 top-users 端点 `ne(null)` → `isNotNull`

**问题**:`apps/api/src/plugins/ai-cost.ts` GET /api/admin/ai/cost/top-users 端点用 `ne(users.id, null)` 过滤,postgres-js 编译为 SQL `<> NULL`,永远 false 返回空数组,管理员页面 Top Users 表永远为空。

**修复**:`ne(users.id, null)` → `isNotNull(users.id)`,postgres-js 生成 `IS NOT NULL` 标准 SQL。

**验证**:`curl http://localhost:8801/api/admin/ai/cost/top-users?limit=10` 返回 3 个用户(3 个 seed 用户,均含真实成本数据)。

### 3.4 budget-alerts 端点 `skipResponseSanitization`

**问题**:`response-sanitizer` 中间件对所有响应做字段名脱敏,字段名含 "token" 的(如 `dailyTokenLimit` / `dailyTokenUsed`)被遮蔽为 `***`,admin /api/admin/ai/cost/budget-alerts 端点返回的预算配置变成 `{"dailyTokenLimit": "***", "dailyTokenUsed": "***"}`,无法查看真实配额。

**修复**:`apps/api/src/plugins/ai-cost.ts` budget-alerts 路由的 preHandler 添加 `request.skipResponseSanitization = true`,admin 路由可信上下文跳过整端点脱敏。

**验证**:`curl http://localhost:8801/api/admin/ai/cost/budget-alerts` 返回真实配额字段(1 条 critical + 2 条 warning 告警,数字可见)。
