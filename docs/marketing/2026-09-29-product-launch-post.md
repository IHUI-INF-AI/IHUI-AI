**正文**:

> 先交代背景:这篇文章本身,就是用 IHUI-AI 自己的"多平台发布"能力发出来的。工具好不好,让它自己证明。

### 一、IHUI-AI 是什么

IHUI-AI(智汇AI)是一个 Apache 2.0 开源的 AI 平台,基于单一 monorepo 覆盖 8 个端:Web、API、AI-service、桌面端、浏览器扩展、移动端、小程序、CLI。

核心能力:

- **176 个大模型统一调度**:OpenAI / Claude / Gemini / 通义 / DeepSeek / Kimi / Ollama 本地模型等,一套接口随便切
- **Agent 编排三栈**:LangGraph(编排)+ MCP(工具协议)+ A2A(Agent 互联)
- **RAG 知识库、Agent 市场**:知识库问答、智能体创建与交易
- **完整商业层**:钱包、积分、订阅、支付、AI 教育模块
- **工程规模**:542 张数据库表、4393 个 API 路由、700+ 测试文件、5 语言 i18n(zh-CN / zh-TW / en / ja / ko)

### 二、它解决什么问题

AI 工具的日常现状是割裂的:聊天用一个工具、知识库用一个、写稿用一个、发内容再开三个后台逐个粘贴。账号、订阅、数据分散在各处。

IHUI-AI 的思路是把这条链路装进一个系统:从 AI 对话、Agent 编排、知识库,到内容生成,再到**发布分发**,全程不出平台。而发布,正是这次要重点讲的部分。

### 三、多平台发布:让产品自己发自己的推广文

#### 1. 30+ 平台适配器,两种接入形态

代码里目前注册了 38 个平台适配器(保守说:30+ 常见平台),覆盖掘金、CSDN、知乎、小红书、B站、抖音、微信公众号、WordPress、Medium 等。接入分两类:

- **开放平台 API 直连**:微信公众号、WordPress、Medium 等走官方接口,支持 Markdown / HTML,部分平台支持图片、视频
- **浏览器自动化**:掘金、CSDN、知乎、小红书等没有开放写作接口的平台,走受控的浏览器会话

#### 2. 扫码登录:绑定账号不用翻 cookie

在 Web 端「发布 → 发布账号」页:

1. 选平台、点扫码 → 服务端拉起该平台登录页并截图二维码
2. 用户扫码,前端轮询任务状态(waiting_scan → scanned → success)
3. 登录态 cookie 自动**加密入库(AES-256-GCM)**,全程不经手明文

不方便扫码的场景,也支持手动粘贴 cookie(接受 JSON、`k=v; k2=v2`、cookies.txt 三种格式),以及从外部浏览器 / CDP 会话检测已有登录态。凭据覆盖更新时旧密文会压入历史记录,可回溯。

#### 3. 发布治理:把"发着发着被风控"当工程问题解

这类工具最容易死在平台风控上,IHUI-AI 内置了一层发布治理:

- **风险评分 + 冷却机制**:每个账号有风险分与自动冷却,操作过频先停一停,而不是硬冲
- **设备图谱 + 归属判定**:同一用户名下的多平台账号不会被误判为"账号关联"——这是很多多开方案自己踩的坑
- **结果可回传**:发布任务返回 `published_url` 与平台内容 ID,发布历史、日历、看板页面齐全

#### 4. AI 辅助写作:闭环的最后一环是发布

平台内置 AI 对话与文本生成能力,写稿前让模型起草、改标题、调结构,成稿后直接进入发布流程——"构思 → 成稿 → 多平台分发"在同一个系统里完成,不用在五六个标签页之间搬运内容。

### 四、与同类工具的差异

对比蚁客、新媒体管家、Buffer、Hootsuite 这类内容分发工具:

| 维度 | 常见分发 SaaS | IHUI-AI |
| --- | --- | --- |
| 开源 | 闭源,按月付费 | Apache 2.0,可自托管 |
| 凭据 | 存在第三方服务器 | AES-256-GCM 加密,存自己的库 |
| 能力面 | 只做分发 | 分发只是其一,同系统还有 176 模型对话、Agent、知识库、教育模块 |
| 端 | Web | Web / 桌面 / 扩展 / 移动 / 小程序 / CLI |

一句话:**不是又一个发布工具,而是一个自带发布能力的开源 AI 平台。**

## ③ 发布备注(给负责人,不随文发布)

### 建议首发顺序:掘金 → 小红书 → CSDN

| 顺位 | 平台 | 理由 |
| --- | --- | --- |
| 1 | 掘金 | 三个候选中唯一经实测全流程发布打通的;用 ② 版 |
| 2 | 小红书 | `web_session` 字段已齐;用 ① 版种草文案 |
| 3 | CSDN | 还差凭据键,补齐并处理登录墙后发;用 ② 版 |

平台间发布间隔建议 ≥ 2 小时,错开投放,避免被判批量发帖。

### 各平台发文前检查清单

- **通用前置**:登录 Web 端 → 「发布 → 发布账号」页(`/publish/accounts`),确认各平台账号 verify 状态为 connected。上一轮确认:三个平台各差一个键——**掘金补 `signatureId`、CSDN 补 `UserSecret`、小红书 `web_session` 已齐**。发文前先补齐再 verify。
- **掘金**:
  - 发布后文章先进入"审核中",**站内搜索搜不到是正常现象**,不是失败。成功判据 = 发布任务返回 `success=true` 且拿到 `published_url`,再到「我的文章」看审核状态。
  - 发文前顺手清一下草稿箱(校准探针跑过会留标题带「勿发布」的测试草稿,入口 `juejin.cn/creator/content/article/drafts`)。
- **小红书**:
  - 支持 md/html/image/video。首次绑定后**先小流量试发一篇**,确认登录态"够写"再发正式文(掘金实测过"verify 通过但写不动"的形态,小红书此点未实测)。
  - 小红书对营销内容与站外链接敏感(平台通用规则):① 版正文里官网只出现一次、放在"官网"提示处,其余靠评论区补充;标题不要出现"推广""优惠"类字眼。
- **CSDN**:
  - 注意 **verify 通过 ≠ 能发布**:CSDN 曾实测扫码导入的 cookie "够读不够写"(verify connected 但发布撞登录墙)。首次正式发布前,先在浏览器对该账号**人工重新扫码登录一次**补全写权限。
  - 补齐 `UserName` / `UserToken` / `UserSecret` 三键(差 `UserSecret`)。

### "本文由本产品自身发布能力发出"这个自证卖点怎么用

1. **文末固定一句**:② 版结尾已内置("你在掘金、CSDN、小红书看到这篇文章,是同一次操作分发出去的");小红书 ① 版用"我这条笔记就是用它发的"轻量带过。

4. **发布时务必删除本文件顶部的「⚠️ 草稿(未发布)」标注行**,只复制对应平台的正文部分。
