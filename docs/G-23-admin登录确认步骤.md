# 生产 admin 登录确认步骤（G-23 收尾单页）

> 用途：2026-10-28 离线取证曾写"库里现役 admin 散列对仓内所有登记处（备份文件 / 服务环境块）都不匹配
> ⇒ 需要你验证手里那把钥匙还能开门"。**这条结论已于 2026-10-30 被推翻**：当时拿"备份文件原始内容"直接
> 比对，而 `admin-password.txt` 末尾带一个 `0x0a`（LF），把换行算进口令 ⇒ `len` 读成 10、恒定脱靶，属
> **未 trim 造成的假阴**（同日另一会话拿错凭据源撞登录，是同族的第二起）。2026-10-30 复核：权威源
> `admin-password.txt` trim 后（`len=9`）与库内 argon2id 散列 `verifyPassword=true`，真机登录 + 2FA 全链路
> `status=0` 签出令牌，服务 env 块也已是同值（两侧 `len=9 sha=b338624a13cf`）⇒ 分支 A 成立，无需轮换。
> **全程不需要、也不应该在任何聊天/文档里写出口令明文。**

> **读取口径（照此做，别再复发病）**：把口令文件内容用于任何比对 / 登录 / 写环境块之前，必须剥掉尾随换行
> （`readFileSync(p,'utf8').trim()`，与 `scripts/check-credential-health.mjs` 的 `readFileSyncOr()` 同一语义）；
> 只认 `len` 不认尾字节会把真口令判成假脱靶。权威源**只有一个**：`D:\DevEnv\secrets\admin-password.txt`
> （仓内 consumer：`deploy/win/ihui-deploy.ps1`、`scripts/check-credential-health.mjs`、
> `scripts/e2e-monitor-panels.mjs`）。同目录带日期命名的留痕（`ihui-admin-new-*.txt`、`admin-mfa-secret.txt`
> 等）零引用、会过期，已就地标注 `stale_at`，**不得据其撞登录**——`/auth/login/username` 有"15 分钟 5 次
> 即锁 15 分钟"的预算，拿过期枚去试 = 自己制造故障。要判"口令对不对"用离线哈希比对，不打接口。

## 第 1 步 · 真机登录验证（2 分钟，你自己做）

1. 浏览器打开 `https://www.aizhs.top`（或本机 `http://127.0.0.1:8801`）。
2. 用 `admin` + **你认为现在的现役口令**登录管理后台。
3. ⚠️ **只试一次，失败就停**：账号锁定策略是 15 分钟内 5 次失败 ⇒ 锁 15 分钟，反复试会把问题
   从"口令不对"升级成"账号锁死"。

## 第 2 步 · 按结果二选一

### A. 登录成功 ⇒ G-23 彻底结清，只需核对档案

2026-10-30 实测走的就是这一格：权威口令能登录（离线 `verifyPassword=true` + 端到端 `status=0`）。
原先这里写"仓内两处记录是陈旧的，需要换新"已不成立——两处（备份文件 / 服务环境块）现读都是当前值。
若将来口令确实换过，再按下面两步同步：

- 把现役口令写入权威备份（PowerShell 7，不回显）：
  ```powershell
  Read-Host '粘贴现役口令' -AsSecureString | ForEach-Object {
    $plain = [System.Net.NetworkCredential]::new('', $_).Password
    [System.IO.File]::WriteAllText('D:\DevEnv\secrets\admin-password.txt', $plain)
    $plain = $null
  }
  ```
- 写完后跑回归（应绿）：
  ```powershell
  node D:\IHUI-AI\scripts\check-credential-health.mjs
  ```
  这一步同时核对服务环境块 `IHUI-DEPLOYLOOP\Parameters\IHUI_ADMIN_PASSWORD`。**2026-10-30 现读：该格已
  是 ✅ ok（服务侧与权威源同为 `len=9 sha=b338624a13cf`），本文原先写的"现在那条 RED"已不成立**；若日后
  它再翻红，修法同样是把 `IHUI_ADMIN_PASSWORD` 更新成现值——不修则部署环健康门禁每轮白烧 1–2 次失败登录
  （耗锁定预算）。

### B. 登录失败（401/提示口令错误）⇒ 需要轮换一次，agent 可代跑

**不要在失败后继续重试。** 把下面这条发给 Loomy 代执行即可（会打印一次性新口令，请立即保存到
密码管理器并同步写入上面两处）：

```
按 PROJECT_PLAN G-23 票面五步执行生产 admin 轮换：
备份旧散列 → db:migrate → reset:admin-password --generate --force --yes
→ verifyPassword 离线复验 → 失败则用留痕散列回滚
```

器物侧护栏已内置：`NODE_ENV=production` 必须显式 `--force`、必须 `--yes`、触发器保护自动禁用又
恢复（2026-09-14 生产实测路径）、成功后只打印用户名/邮箱，散列不入库。
