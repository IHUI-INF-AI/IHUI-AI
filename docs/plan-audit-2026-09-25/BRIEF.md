# 任务书:PROJECT_PLAN 未认领票的 HEAD 实现面对账(只读审计)

## 背景(你可能不知道的前提)

- 仓库 `G:\IHUI-AI`,pnpm monorepo + Turborepo,8 端:`apps/api`(Fastify+Drizzle)、`apps/web`(Next16+React19)、`apps/ai-service`(FastAPI+LangGraph)、`apps/miniapp-taro`(Taro4)、`apps/mobile-rn`(RN+NativeWind)、`apps/desktop`、`apps/extension`、`apps/cli`。共享层:`packages/{shared,app,ui-react,types,design-tokens,api-client,database}`。
- `PROJECT_PLAN.md` 是唯一任务台账。里面**已知存在两类失真**,这正是本次审计要查的东西:
  1. **幽灵待办**:功能早已在 HEAD,但条目仍挂 `- [ ]`(昨天一批刚翻勾过 23 行)。
  2. **虚假已做**:票面写着"已入库 + 实测 N 例全绿",但实现物在全仓任何 ref 上从未存在(已知实例:`packages/shared/src/chat/index.ts:71-80` 注释点名的 `voice-note` / `prompt-drafts` / `history-projection` 三个模块)。
- 另有并发会话在改同一份台账,**行号会漂**;请按票编号定位,不要依赖行号。

## 你要做什么

读 `.ihui-agent/tmp/plan-audit/batch-<N>.md`(你的批次,内含若干张票的票面原文),对**每一张票**给出三态判定之一:

- `A-确未开工`:HEAD 里找不到该票点名的实现物,也没有任何功能性接线。
- `B-部分开工`:有真实落地件,但票面验收条件未全部满足(必须点名**已落哪几件、还欠哪几件**)。
- `C-已在库该翻勾`:票面描述的功能在 HEAD 已完整存在(给出接线点证据),挂 `- [ ]` 属台账漂移。

## 判据硬规则(违反即结论作废)

1. **一律判 HEAD,不判工作区**。共享工作区常年滞后 HEAD,按磁盘读会产出与事实相反的结论。
   取内容用 `git -c safe.directory=* show HEAD:<path>`;列文件用 `git ls-tree -r --name-only HEAD`;找符号用 `git -c safe.directory=* grep -n -I -F "<tok>" HEAD -- apps packages sdks scripts`。
2. **命中 ≠ 实现**。`git grep` 命中在 `.md`、注释、测试夹具、i18n 语料里的,不算落地。必须读到**注册点/接线点/渲染消费点**(组件被 import 且被渲染、路由被注册、字段被读写)才算。
3. **否定式结论必须换落点**。要下"没有 X"的判定前,至少再试 3 种命名形态(camelCase / snake_case / 中文文案字面量 / 文件名变体),并优先用 `git ls-tree` 按目录枚举而不是按名字猜。
4. **每条判定必须附可复现证据**:原样可跑的完整命令 + 该命令输出的关键片段(逐字 ≤3 行)。我给不出可复现命令的结论,一律不得写进报告。
5. **判 A/B 时给出落点清单**:要改哪些具体文件(绝对到仓内相对路径),并说明为何落在该处(遵守仓库"共享层优先"规则:能沉 `packages/*` 的不得在端内重实现)。
6. **判 A/B 时给出验收命令**:可跑的 `pnpm --filter <pkg> typecheck` / `node --test <path>` / `node scripts/check-*.mjs` 等,能证伪的才算验收。

- 禁止再派子代理。
