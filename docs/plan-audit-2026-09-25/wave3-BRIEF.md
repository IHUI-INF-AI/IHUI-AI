# O60r 任务书:逐张裁决活文档双态行(只读取证,不写仓库)

## 背景(为什么有这轮)

`PROJECT_PLAN.md` 是本仓唯一任务台账,多会话并发共写。上一轮对账量出:HEAD 副本上
**同一票编号"未勾 `- [ ]` + 已勾 `- [x]`"并存 = 30 张票,未勾行合计 90 行**。
后果不是美观:`- [ ]` 那一行会被下一轮派单当成"还没做",于是把已完成的活重做一遍
(本仓最高频的"两套真相"事故)。已登记为台账 O60 残余①,要求**逐张裁决**,不许批量翻勾或批量删行。

你这一路只负责**取证与裁决**,**不改任何文件、不碰 git 写操作**。裁决由主代理串行落进台账。

## 硬口径(每条都必须遵守)

1. **一律判 HEAD,不判工作树**:`git show HEAD:PROJECT_PLAN.md`。共享工作树常年滞后 HEAD,
   行号与内容都以 HEAD 为准;报告里的行号必须是 HEAD 版行号(主代理落盘时会自己重新定位)。
   取 HEAD 版:
   `git -c safe.directory=* show HEAD:PROJECT_PLAN.md > /dev/null`(可读,不许写回)。
   用 `nl` 打行号:`git -c safe.directory=* show HEAD:PROJECT_PLAN.md | nl -ba | sed -n '2400,2470p'`
2. **不采信台账自己的说法**。台账写"已修/已接/已入库"只当线索,每条结论都要有当次实测命令与输出。
3. **判"实现已存在"必须同时证明它被消费**("造好没装车"是本仓常态):组件在库但生产零 import、
   函数在库但零调用点,都算**未闭环**。判定用 `git grep -l/-c ... HEAD`,并给出命中清单。
4. **禁止把"命中数>0"当成"已实现"**。要看命中落在什么文件:文档/台账/审计脚本里的命中不算实现。
5. 判"未开工"前,换 2-3 个同义关键词再搜一遍(`git grep -iE 'a|b|c' HEAD -- apps packages scripts`)。

## 四类裁决(每张票的每一行都要给一个)

| 判决 | 含义 | 建议动作(写进报告,主代理执行) |
| --- | --- | --- |
| `保留未勾` | 票面确有实打实的欠项没做完 | 不动勾选态;在行尾追加"还差 X(实测:命令+读数)" |
| `翻勾` | HEAD 里实现**且被消费**,只是台账没勾 | 该行改 `- [x] ✅(2026-09-25)`;若同编号已有 ✅ 孪生行,则本行改判 `裸副本` |
| `裸副本` | 与另一条同编号登记逐字同题、只缺勾选态/前缀 | 保留编号文字,行尾追加指针句(格式见下) |
| `旧文取代` | 被后续同编号登记就地改写取代的旧表述 | 同 `裸副本` 处理,指针句注明"现行判定见 L####" |

**指针句统一格式**(照抄结构,把方括号内容换成实测值):
`**[O60r 判:<裸副本|旧文取代>]** 本行正题逐字存活于 L<行号> 的同编号登记(那行已勾),不重复计账、勿照本行派单;现行判定以 O60r 报告与该行复跑命令为准。`

**为什么不能整行删**:守门 71(`scripts/check-plan-line-loss.mjs`)对含 `G-x/Dx/Px/Wx/守门 NN`
编号的登记行做"整行消失即拦"。所以只改写、不删除;改写时**必须保留该行的编号文字**。

## 已知的坑(上一轮都踩过,别再踩)

- **全角括号在 JS 正则里不是分组**:`（进行中）?` 的 `?` 只管最后一个全角字符 ⇒ "可选标记"判据
  静默变成"必须含字面前缀"。批量判定时**必须逐 ID 打印命中数**,不能只给总数。
- **命中 0 先怀疑尺子**:任何"零命中"结论之前,先用一个**必然存在**的串验证搜索本身有效
  (例如 `git grep -c "PROJECT_PLAN" HEAD`)。
- **`- \[[x ]]\[` 这类正则里的空格**:行首状态标记是 `- [ ]`(中括号内一个空格),写成 `- \[ \]` 才对。
- 台账里同一票常分散在 2-4 处(优先级段 + 专项段 + 收口段)。要**全量搜该编号**,不要只看一处。

## 输出(严格)

写到你任务书指定的那**一个**文件,除此之外不写任何路径,不建目录。格式:

```markdown
# O60r 裁决 — <票号列表>
## 票 <ID>
- 台账位置(HEAD 行号):L1234 `- [ ]` / L2345 `- [x] ✅(...)`
- 复跑命令与实测:
  - `git -c safe.directory=* show HEAD:PROJECT_PLAN.md | sed -n '1234p'` → …
  - `git grep -l "<实现特征>" HEAD -- apps/...` → 命中:…(逐条列出,含"零命中"也要写)
  - 消费点证明:`git grep -l "<组件名>" HEAD -- <各端目录>` → …
- 判决:L1234 = <保留未勾|翻勾|裸副本|旧文取代>;依据:<一句话,必须引用上面某条实测>
- 建议改写文本(仅"裸副本/旧文取代/翻勾"时给整行成品,保留原编号与原文字)
## 汇总
| 票 | 未勾行 | 判决 | 一句依据 |
```

最后必须有一节 **`## 我这路没做完 / 需主代理复核`**,如实列出轮次耗尽、判据存疑、
需要动别的会话在飞文件的项。**报告文件写完才算交付**;没写完就交回 = 零交付。
