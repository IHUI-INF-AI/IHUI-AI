# 票：converge 前移 HEAD 不落工作树 ⇒ push 门恒评陈旧树

- 状态：OPEN
- 登记：2026-11-07
- 归属：本线只登记现象与判据，**不含实现方案**

## 现象

`scripts/git-sync-converge.mjs` / `scripts/union-converge.mjs` / `scripts/object-space-land.mjs` 用 `commit-tree` + `update-ref` 推进 `refs/heads/main`，语义是 **worktree-preserving**：只写对象库与 ref，不写索引、不写工作树。

因此每轮 merge 之后，`HEAD` 已经包含对侧新提交的全部内容，而工作树仍停在上一轮（甚至更早）的树。二者差异量等于该轮合入的对侧改动面。

### 实测（2026-11-07，本机）

| 时刻 | refs/heads/main | 备注 |
|---|---|---|
| 15:53:41 | `2a0a2283` | 工作树最后一次对齐的目标 |
| 16:19:37 | `d51cbae7bd` | round3 merge，合入 `968f22d4f7` 等 3 笔；改 11 文件 |
| 16:56:05 | `128b1d2278` | 又一轮自动前移 |
| 17:03:42 | `5129f5aef5` | 再一轮 |

- 16:19:37 之后：10 个路径的**磁盘 blob 逐一等于 `2a0a2283:path`**，而 `HEAD:path` 已是新 blob ⇒ `git status` 恒有 10 项 ` M`；其中 `scripts/tests/check-ops-patrol.test.mjs` 的 mtime 停在 11-04，证明**没有任何进程写入过**，` M` 完全由 HEAD 前移产生。
- 远端同期每 4–6 分钟快进一次（`24de8f5b14` 16:15:44 → `968f22d4f7` 16:17:20 → `e3fc2b1ac4` 16:21:41 → `991bac4981` 16:28:37）。
- 17:0x 时 `origin/main..HEAD` = 528 笔。

## 由此导致的 5 类假红

1. **`Cannot find module`**：脚本文件在 HEAD 里存在，但被陈旧工作树呈现为删除，node 直接解析失败（299/300/301 均踩过）。
2. **缺水印（47p）**：inject 写的是工作区，HEAD blob 仍缺；push 档判 HEAD 面，于是「修了还红」。
3. **跨端漂移（302p）**：镜像侧 star 与端内页面的对照基线取自工作树，工作树落后于 HEAD ⇒ 读数与 HEAD 不符。
4. **受管块不同步（306p）**：`gen-knip-taro-entries --check` 比对工作树，生成物在 HEAD 已同步而工作树未同步时判红。
5. **298 磁盘旧档臂**：`check-staged-downgrade.mjs` 的工作树臂把「工作树 == 某祖先 blob 而 HEAD 已更新」判成「旧档回写」，与真正的回写事故（`§` 那批 801 个 `D`）同形不可分。

## 判据缺口

「门评的是**树**还是**工作树**」这件事本身**没有单一口径**：

- 47p / 298 / 306p 的部分臂读工作树或索引；
- 47p 的 push 档、IG 读 HEAD 面；
- 299/300/301 直接 `import` 工作树里的脚本。

同一轮 push 里，各门读的面不同，却共用同一句失败话术（「旧档/缺水印/不同步」），导致归因必须逐门反推。
