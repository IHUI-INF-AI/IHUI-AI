# 票：merge 提交的「新增行」判据只对第一父（通用形态普查）

- 日期：2026-11-07
- 归属：本侧（判据面），已修门 234；其余五门判定「不属同型」或「已内建跳过」
- 触发现场：把 `origin/main`（含 RP-40/41/42/43 四条待办行）并入本侧时，门 234 的 A1 报
  「新增行缺交代 4 枚」。四条行在两父里逐字存在（`git show origin/main:PROJECT_PLAN.md`
  可见），却被算成**合并方新增** —— 因为 A1 的基准面只读 `HEAD`（第一父）。

## 一、病灶（已修，门 234）

改前的基准面实现（`scripts/check-plan-fields.mjs`，HEAD 版 L356-L369）：

```js
  if (face !== 'head') {
    try {
      const identity = epochMark ? idNorm : (s) => s
      base = new Set(
        parseTaskRows(readPlan(root, 'head'))
          .filter(isOpenRow)
          .map((r) => identity(r.raw)),
      )
    } catch (e) {
      return { ok: false, why: `基准面(HEAD)取不到 ⇒ A1 未判定:...` }
    }
```

`readPlan(root, 'head')` 恒取 `HEAD:PROJECT_PLAN.md` ⇒ 合并提交下"新增"的相对面只有第一父。

修法（提交 `e26e18f69f`）：
- 单亲（`.git/MERGE_HEAD` 不存在）⇒ 走原分支，**逐字节不变**（用改前版本对同一夹具跑过，输出逐字相同）；
- 合并态 ⇒ 对 `HEAD` + `MERGE_HEAD` 的每一父求并集，任一父同文件逐字已有的开行不进基准面；
- 父提交读不出（坏对象）/ `MERGE_HEAD` 为空 ⇒ **fail-closed 判未判定（exit 2）**，不许退化成「没有新增」；
- 夹具 6 条（`scripts/tests/check-plan-fields.test.mjs`）：二父带来的行通过 / 自写新行仍红 /
  不整面放行（回归）/ 单亲逐字不变 / 坏对象未判定 / 空 MERGE_HEAD 未判定。26 pass / 0 fail。

## 三、派生的通用判据（供后续门复用，不写实现）

1. 任何以「新增」为红的门，必须显式声明**相对面**：`parent(s)` 而非 `HEAD`；
2. 合并态的相对面 = 全部父提交的**并集**（任一父已有 ⇒ 不算新增）；
3. 相对面取不到 ⇒ 未判定（exit 2），不得回落成"没有新增"；
4. 单亲路径必须有"改前/改后逐字相同"的回归夹具，防止合并支持漂移单亲语义。

## 四、已知未覆盖

- `IG` 跳过 merge：合并提交里对判据面的改动目前无门审（失效方向是"漏判"，不是"误红"）。
- `47p` 的 push scope 含第二父文件：属推送语义，非误判；若将来要区分"谁写的"，应新增维度而不是改 scope。
