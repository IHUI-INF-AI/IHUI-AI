# face-reader 债务台账未随生产代码同步（3 条存量红）

## 现象

`node --test scripts/tests/face-reader.test.mjs` 在 main 与 cut9 上**同样**红 3 条（main `833071424e` 43 项 / 40 过 / 3 红；cut9 `256be1a65c` 45 项 / 42 过 / 3 红），即与 302p 提速无关。cut9 新增的 2 条（`IHUI_FACE_TREE_SNAPSHOT` 轮内快照、漂移门路径面）全过。

## 3 条红（债务清单未登记的「只减不增」断言）

1. **裸 git 派生的生产文件数只减不增** —— 未登记的实参至少含 `scripts/git-guardian.mjs`、`scripts/lib/push-receipt.mjs`；这两处直接 `spawn git`，未走 face-reader 取数层。
2. **自拼 `cat-file --batch` 却不走本层的门，数量只减不增** —— 有门自己拼 batch 协议，绕开统一取 blob 层。
3. **判「远端在哪」只许走层** —— 直接读跟踪 ref 判断远端存活性；跟踪 ref 会被清理层删掉，属于不可靠探针。

## 根因

三条断言都以「基线清单 + 只减不增」守护债务，但生产侧新增了未登记的用法（上列文件），断言把「新增债务」判红；修复方向是**把债务补登记并把用法迁到统一层**，不是放宽断言。

## 建议处置（逐条）

1. `scripts/git-guardian.mjs`、`scripts/lib/push-receipt.mjs` 的 git 调用迁到 face-reader 层；迁不动的写进债务清单并注明理由与到期日。
2. 自拼 `cat-file --batch` 的门改为走 `face-reader` 的 blob 取数 API；保留 batch 的调用方需在清单登记。
3. 远端探测统一走层（层内已有 `delete-tracked-ref` 清理风险提示），门内不再直读跟踪 ref。

## 验收入口

- 门：`node --test scripts/tests/face-reader.test.mjs`（3 条由红转绿）
- 相关：`node scripts/check-cross-end-parity-drift.mjs`、`node scripts/check-remote-availability.mjs`（若涉远端探测）
- 不在本票范围：302p 提速（`256be1a65c`）已合并，与本 3 条无关。
