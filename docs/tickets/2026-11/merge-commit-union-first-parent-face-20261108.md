# 票：合并提交上仍有 31 道门用「并集/首父」口径，未迁到双父差集

状态：OPEN　开票：2026-11-08

## 一、现象

合并提交（两个及以上父）落地时，注册表里 31 道「按改动面判」的门仍按**并集**（`HEAD^..HEAD` 全量）
或**首父**（只比 `parent[0]`）取面：

- 并集口径：把 main 侧全部改动铺成本次「新增面」，门报出大量与本次改动无关的红/未判定；
- 首父口径：只比第一父，import 进来的第二父改动完全不进判面，反过来会漏判。

这 31 道门与「门体同代自检 / 判面显式声明」不是同一层问题：后者解决的是「门体是哪一代」，
前者解决的是「这一代门该拿哪两份树去比」。

## 二、正确口径（双父差集）

对齐 `push-scope` 的做法：判面取 `merge-base..HEAD` 的**本枝真实改动**，
即 `diff(merge-base, HEAD)`，而不是 `diff(parent[0], HEAD)` 或两次差集的并集。
对合并提交：`merge-base(parent[0], parent[1])` ⇒ 两端各算一次，取本枝侧集合。

## 三、范围与验收

1. 在册 31 道门逐条改成「双父差集」口径，判据内容不动，只换取面；
2. 新增回归用例：构造一枚两父合并提交，第二父新增 N 个文件 ⇒ 该门不得把 N 件报成本枝新增面；
3. 迁完后从本票移除对应条目；本票清零（清单只许缩短）。

## 四、与本次 B2 落地的关系
