# 第三方方案许可证与可行性审计（微信接入方向）

- 审计日期：2026-11-25
- 审计对象：本仓在微信接入方向上评估过的 9 个外部项目
- 本仓基线：Apache-2.0 商业仓（根目录 `LICENSE` 为 Apache License 2.0，`NOTICE` 已存在；入站第三方内容按 `config/third-party-provenance/` 台账机制登记）
- 审计性质：许可证与可行性文档审计；第 9 节附带隔离 venv 的实机证据，代码/包均不入仓

## 二、审计方法与边界（本次执行约束）

- 信息来源仅限各项目官方仓库、官方文档、PyPI/npm 元数据与公开 issue/索引；取不到证据的字段一律写「未能证实」，并注明还缺什么证据。
- 未下载、未安装、未运行任何第三方二进制或 DLL（仅限第 1–7 节的项目）。
- 未注入、未挂接 `Weixin.exe` 或任何微信进程（仅限第 1–7 节的项目）。
- 未通过 pip/npm 将任何第三方包装进本仓（第 9 节的 `wechatauto-replica` 例外：已在外部隔离 venv 安装并实机验证，未入仓）。
- 第 9 节 `wechatauto-replica` 的实际验证发生在隔离 venv 与本机 `sns.db` 上；该包读取 `Weixin.exe` 进程内存中的 SQLCipher 密钥，属于审计对象本身的机制，不是本仓代码注入。
- 未把任何第三方源码片段粘进本文档；本文只引用许可证名称、官方功能清单与版本矩阵等公开描述。
- 许可证兼容性判断为审计口径，不构成法律意见；正式商用前需由法务按具体分发形态复核。

### 9. wechatauto-replica（本地 DB sidecar 依赖）

**许可证事实**

- PyPI wheel `wechatauto_replica-1.3.0.2-py3-none-any.whl` 的元数据与随包许可证文件均标注 Apache-2.0；本次只审计元数据与源码边界，不构成法律意见。
- 权威链接：PyPI 项目页；本地审计副本 `C:\caches\temp\wechatauto-replica-audit`（未入仓）。
- 查证日期：2026-11-25。

**机制与边界**

- 不是 DLL 注入：`WeChatDB` 通过读取 `Weixin.exe` 进程内存取得 SQLCipher 密钥，再解密/读取本地 `sns.db`；会接触进程内存与本地数据库，属于强隐私操作。
- 本机 4.2.0.13 实测：20 个库密钥通过页 1 HMAC 校验，`sns.db` 读出 705 条朋友圈；`MomentDB` 可给出图片 URL、点赞名单、评论结构、作者 wxid 与完整正文。
- 图片二进制仍受平台票据限制：qpic URL 加 `Referer` 可返回 200，但过期票据会返回 120×120「暂时无法查看」占位图；sidecar 已拒绝写入占位图并计入失败，不伪造真实照片。

**允许的使用形态**

- 允许：独立 Python sidecar + 外部 venv + 本地 stdout/JSON 契约；默认关闭，`BRIDGE_DB_SIDECAR=on` 显式开启；不把源码或 wheel vendor 进仓，不随商业产物分发。
- 不允许：把包源码复制进 Apache-2.0 仓、默认开机读取、上传导出数据、把 DB 结果伪装成 UIA/OCR 结果。

**结论与理由**

- 有条件可行：许可证为 Apache-2.0，具备独立 sidecar 的许可基础；但机制涉及进程内存读取，必须保持默认关闭、显式授权、本机离线、只读、不伪造。它是朋友圈结构化字段的补充路线，不替代 UIA/OCR 的聊天与后台静默能力。

### 8.3 三条规则

**R1 第三方目录 / SPDX 头候选**

- 候选:路径位于 `vendor` / `third_party` / `third-party` 目录下,或文件正文携带 `SPDX-License-Identifier:` 头。
- 放行条件(两条同时满足):许可证属于允许集 {Apache-2.0、MIT、BSD-2-Clause、BSD-3-Clause、ISC};路径能在台账 `config/third-party-provenance/*.json` 的 `roots` 中找到登记。
- 许可证取值:文件自带 SPDX 头优先;无文件头时回退台账条目的 `license.spdx`;两者都取不到判红。允许集之外(含 AGPL、GPL、LGPL、CC BY-NC、OFL 等)或未登记均判红。

**R2 被拒项目标识的代码形态**

- 射程源码扩展名:`.ts`、`.tsx`、`.js`、`.mjs`、`.py`、`.ps1`。
- 被拒标识:wcferry、WeChatFerry、pywechat、pyweixin、wx4py、WeChatPadGo、weflow、AstrBot、chatlab。
- 只在导入 / `require` / 动态 `import` / Python `import` / 直接调用 / 成员访问形态下判红;注释、文档文案、UI 描述里的同名提及不算入件。

**R3 传染 / 非商业许可原文**

- 非 `docs/licensing` 面出现 GNU AFFERO GENERAL PUBLIC LICENSE、SPDX 声明为 AGPL、CC BY-NC(-SA) 文本或 Creative Commons Attribution-NonCommercial 表述,判红。

### 8.4 白名单口径

白名单在脚本 `WHITELIST` 常量逐条登记(前缀或精确路径 + 适用规则 + 放行理由),按规则分别豁免,不整条关闭规则:

- `docs/licensing/`(前缀):本审计文档所在面,被拒项目事实只作选型参照记录,不进代码面(R2 / R3)。
- `scripts/check-third-party-license-boundary.mjs`、`scripts/tests/check-third-party-license-boundary.test.mjs`:本门自身,判据字面量与自测夹具必然携带 SPDX 头、被拒项目名与 AGPL/NC 原文,不是入件(R1 / R2 / R3)。该豁免只因「检测器必须包含被检测的字面量」这一自指事实成立,不适用于任何其它文件。
- `scripts/provenance-ledger.mjs`、`scripts/tests/provenance-ledger.test.mjs`:既有台账守门,自测夹具字符串携带 SPDX 头,非第三方入件(R1)。
