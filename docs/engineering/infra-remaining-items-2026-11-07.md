# infra 线剩余项清单（2026-11-07）

> 只列**未做 / 未接门**的项。已落地：B1–B4（`396e7d260f` test-health 信封判据、`8124db1739` cdn-watchdog 进程/端口归属、`7f07a967d1` 防火墙看门狗 exit 3、`19211ac70f` 四处真吞错）；并发安装锁只出脚本与文档，未激活。
> 每项四栏：**剩余什么 / 为什么现在不动 / 触发条件 / 归属谁**。

## 1. cAdvisor 去 privileged + docker.sock 换 proxy

- **剩余**：`deploy/saas/docker-compose.yml:125` 的 `privileged: true` 与 `:138` 的 docker.sock；`admin-api` 的 `:98` 读写直挂改 socket-proxy 白名单。方案/验证/回滚已在 [`deploy/saas/CADVISOR-HARDENING-PLAN.md`](../../deploy/saas/CADVISOR-HARDENING-PLAN.md)，本次不改。
- **为什么不动**：需生产窗口。本机无 docker、无等价负载，盲改会把"指标变少 / 客户容器生命周期失效"藏进灰度期才暴露。
- **触发**：拿到生产变更窗口，且改前指标基线快照（metrics 族 + Prometheus 30min 序列）已留档、回滚演练过一次。先做阶段 A（去 privileged，风险低），阶段 B（socket proxy）另开窗口。
- **归属**：部署/运维席执行；安全席复核回滚判据（"指标/接口与改动前等价"，不是"容器起来了"）。

## 2. weekly-security-audit 四个候选升级点（现在保持降级）

| 位置 | 现状 | 为什么仍降级 | 改判红的触发条件 |
| --- | --- | --- | --- |
| `119` `pnpm run typecheck \|\| echo ::warning::` | 类型错误只 warning | 存量类型错误未清零，直接红会逼人 `--no-verify` | 主干 typecheck 连续 14 天零 warning，或 typecheck 已是阻塞门 |
| `124` `pnpm run lint \| tee ... \|\| true` | lint 不判红 | 存量 eslint 告警未清 | 主干 `lint:strict --max-warnings 0` 可过（存量清零） |
| `129/131` `license-checker ... \|\| true`（GPL 仅 warning） | 许可证只出报告 | 禁止许可证清单要法务给，仓内自定会误伤 | 法务给出"禁止许可证清单"并确认阻断授权；或出现一次 GPL 依赖误入发布包 |
| `202-213` `gh issue create ... \|\| true` | 建单失败不判红 | token 权限与审计 SLA 未定，红会把"没权限"当成"有漏洞" | 审计 SLA 要求必须留 issue（或出现一次高危发现无人跟进） |

- **归属**：前三条安全席；许可证一条法务/产品；Issue 权限归仓库管理员。
- **注意**：四处都是**判据型**降级，不是吞错；判断依据见下节（报告步不该提前 exit，判据在第 8 步）。

## 3. `|| true` 巡检降级区（判为降级，不改）

- `68/70/71/73` `pnpm audit ... || true`：**只出报告**。判据在 `84-108` 统计步与 `218-237` 第 8 步（unjudged ⇒ exit 2，high/critical ⇒ exit 1）。报告步提前 exit 会让 tsc / eslint / license 全部跳过 ⇒ 一次红门只剩半份证据。
- `174/178` `cat ... || echo "（无）"`：汇总正文缺报告时写"（无）"，红绿仍由第 8 步判。
- `198/224` `cat ... || echo unjudged`：显式三态值；`224` 起 unjudged ⇒ `exit 2`，不存在"静默绿"。
- **触发改红**：出现"报告缺失但第 8 步仍绿"（即 unjudged 没有被消费）——那时先补判据，**不要单点删 `|| true`**。
- **归属**：安全席。

## 4. deploy/win 其余脚本二次扫描结论

扫描面：28 个 `.ps1` + 6 个 `.mjs`，`SilentlyContinue` 146 处（21 个 `.ps1`）、空 `catch` 60 处，按"失败方向"分类：

- **a) 清理/临时文件（无害，不动）**：`Remove-Item` / `New-Item` / `.tmp` 删除等。代表：`deploy-lock-common.ps1:467/477/524/555`、`deploy-window-common.ps1:137`、`ihui-deploy-loop.ps1:166/256/611/666/737/876`、`ihui-pg-backup.ps1:630/664/707`。删不掉临时文件不影响判据。
- **b) 可选传感器 + 保守回落（安全方向，不动）**：`api-listener-freshness.ps1:74`（netstat 失败 ⇒ `undetermined` exit 0，已显式）；`ihui-deploy.ps1:1460/1615`（构建标记读不出 ⇒ 判 stale 重建）；`ihui-api-bluegreen.ps1:53`（日志写失败不回写判据）。
- **c) 三处残留（建议补票，不在本轮修）**：
  1. `ihui-firewall-hardening.ps1:240` `Restart-Service TermService -ErrorAction SilentlyContinue`：注册表已改 53389，但服务可能没重启；此时 WAN 封 3389/53389、LAN 只放 53389 ⇒ RDP 断而脚本仍报绿。**触发**：下一次 RDP 端口迁移/加固执行前，或出现一次"RDP 不通但脚本绿"。**归属**：部署/运维席。
  2. `ihui-canary-gray.ps1:162` 只判 `Get-Process -Id` 存在、不判启动时刻 —— 与 `deploy-lock-common.ps1` 记过的 pid 复用同型；会把复用的 pid 当成灰度实例，`Stop-GrayProcess` 有杀错进程风险。**触发**：灰度实例重启或机器重启后的第一次巡检。**归属**：部署席（修法同 C2：StartTime ≤ pid 文件写入时刻）。
  3. `ihui-deploy.ps1:1473/1485` 构建标记 / 失败冷却写盘静默失败：标记失败 ⇒ 下一轮重建（安全方向）；冷却失败 ⇒ 持续失败时每轮重建（刷日志/告警配额）。**触发**：出现连续失败 > 2 轮/小时。**归属**：部署席。
- **d) 已显式降级（保持）**：`ihui-monitor.ps1:869-874` 磁盘维已从 `catch {}` 改成"未判定"日志，不折成 ok，也不再新增告警身份（新增身份属新能力，需另行授权）。

**结论**：除 c) 三处，其余 `SilentlyContinue` / 空 catch 不是吞错，是清理或保守回落；本轮不扩大改动面。
