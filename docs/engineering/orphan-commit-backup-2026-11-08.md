# 悬空提交备份台账(2026-11-08)

## 这份台账是什么

提交面 `30a`(`scripts/check-commit-loss-guard.mjs --blocking`)在 2026-11-08 报出 77 枚不可达提交。
处置办法不是给门写纸条,而是**把对象真的指住**:每枚建一条 `refs/backup/orphan-2026-11-08/<短sha>`,
ref 一旦存在,该提交与其闭包里的 blob 就不再被判为不可回收,`git fsck` 也不再算作 `unreachable`。

**边界(务必照此执行):**

- 命名只用 `refs/backup/orphan-2026-11-08/<短sha>`;**不得**出现 `ack` / `reviewed` / `lost-commit` 之类字样
  —— 那类引用是"声称已复核"的伪造证据,本台账建的是真备份。
- 这批 ref **不推远端**,只在本机防 `gc` 回收。
- 本台账只登记"建了什么 ref、为什么建",**不构成**任何提交归属或内容已落地的判定。

## 判定口径

- **内容只存在于它身上**(任何可达提交都没有等价 blob / patch-id)→ 必须建 ref,否则对象会被回收;
- **内容已被可达提交取代**(patch-id 或 blob 在 `main` / `release/*` 有等价物)→ 不需保留,但 ref 已建则保留即可。
