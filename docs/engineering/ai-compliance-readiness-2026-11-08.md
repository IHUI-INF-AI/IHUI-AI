# AI 生成合成类合规就绪核查（2026-11-08）

- 核查对象：OPPO 软件商店已存在应用 `AI丨智汇社`（appid **36548762**，包名 `zh.ai.sq`，审核不通过）
- 核查性质：**只读盘点**。未改代码、未提交、未推送、未构建产物。
- 触发原因：OPPO 驳回 3 条——①生成合成类算法备案缺失且《合作协议》不完整；②AI 生成内容显式标识证明缺失；③大模型/算法承诺函缺失（模板 id=10005）。
- 判定用词：**有 / 缺 / 不确定**。不确定 = 仓内与本机均取不到证据，不推断成“有”。

---

## 0. 一句话结论

**按现状会被国内各店集体卡住。** 软著、ICP 备案、营业执照三件套齐备且主体一致，但“生成合成类算法备案 + AI 显式标识证明 + 大模型/算法承诺函”这一组 AI 专项资质**三项全缺**；这不是 OPPO 独家口径，华为/小米/荣耀/应用宝对生成合成类应用同样会要，只是驳回顺序不同。

| 项 | 判定 | 一句话 |
| --- | --- | --- |
| 生成合成类算法备案 | **缺** | 全仓与网盘均无备案号/证书；接口层自述不再展示虚假备案号 |
| 《合作协议》（与合作算法方，双方公章） | **缺** | 仓内与网盘均无该合同；网盘只有劳动合同与用户协议 |
| AI 生成内容显式标识 | **部分有（APK 缺）** | 小程序/web 有文字标注；RN APK 主聊天页无任何标识 |
| 隐式标识（文件元数据/内容 ID） | **缺** | 仅落库 `payload.aigc` 元数据块，未写入产物文件 |
| 大模型/算法承诺函（OPPO 模板 id=10005） | **缺** | 仓内无模板；网盘只有腾讯版承诺书，不是本模板 |
| 主体一致性 | **两件有、一件不可判** | ICP/软著/营业执照同为吉林主体；算法备案主体因无备案不可判 |

**谁能补**：机主/法人。两条路二选一：
1. **自备案**：网信办算法备案系统 `https://beian.cac.gov.cn/`，类型必须选“生成合成类”，审核状态必须为“通过”；
2. **合作模式**：提交合作算法方的算法备案（同样需“通过”）+ 双方盖章《合作协议》。

**判定：缺。**

| 核查点 | 结果 | 证据 |

| 网盘是否有与算法提供方的合同 | **无** | 网盘“合同/合同模板”目录只有劳动合同、实习合同、保密/竞业协议、`用户协议.docx`；无对外算法合作合同 |
| OPPO 驳回原文要求 | 双方公章、完整版 | [app-store-submission-ledger-2026-11-08.md](file:///d:/IHUI-AI/docs/engineering/app-store-submission-ledger-2026-11-08.md#L21)：“若为合作模式，请提供《合作协议》（即与算法提供方签订的合同，同时需加盖双方公章）及合作方的算法备案……目前提供的《合作协议》不完整” |

> 注意：驳回原文说“目前提供的《合作协议》**不完整**”，而仓内/网盘都找不到任何一份——说明此前提交的那份不在本机归档。**先找回已提交版本**，再决定补签还是改走自备案。

**谁能补**：机主/法务，与模型提供方签署完整版并加盖双方公章。

| web 聊天输入区 | [message-input.tsx](file:///d:/IHUI-AI/apps/web/src/components/chat/message-input.tsx#L1747-L1750) 显示“内容由AI生成，请核实重要信息”（`aiDisclaimer`） | 否 |

### 3.2 关键缺口：APK 主聊天页无标识

- [ChatScreen.tsx](file:///d:/IHUI-AI/apps/mobile-rn/src/screens/ChatScreen.tsx#L18) 自述“消息列表：FlatList 渲染气泡（user 右 / assistant 左）”，消息由本地 `renderMessage` 自绘（[L2227](file:///d:/IHUI-AI/apps/mobile-rn/src/screens/ChatScreen.tsx#L2227)），未引用共享 `ChatMessageItemView`。
- `apps/mobile-rn/src` 内检索 `aiGenerated` / `AI生成` **零命中**（仅两处与合规无关的“AI 生成”图片注释）。
- 结论：OPPO 要求的“应用内显式标识的截图/视频”**在当前 APK 上拍不出来**。

### 3.3 门 47 是不是同一件事

**不是。** 门 47 是**源码文件溯源水印**（文件头 `[IHUI-AI-PROVENANCE]` 载荷覆盖），判定器在 [check-watermark-coverage.mjs](file:///d:/IHUI-AI/scripts/check-watermark-coverage.mjs#L455-L485)，与 AI 生成内容标识无任何关系。仓库里那条“门47水印欠账”不能用来证明 AI 显式标识。

### 3.4 谁能补

- **工程侧**：把共享屏 `ChatMessageItemView` 的标识行接进 RN 主聊天页（或在该页最小化补同一行），保证 APK 截图可见。
- **工程侧**：图片/视频产物上加可见角标或水印（当前只有文字标签，字节层无标识）。
- **运营侧**：补 APK 实机截图/录屏（聊天回答下方标识 + 图片生成结果标识），打包上传【特殊行业资质】。

## 8. 方法与限制

- 仓内证据：全仓 Grep（`算法备案`/`网信算备`/`承诺函`/`合作协议`/`AIGC_LABELING_ENABLED`/`aiGenerated`）与关键文件精读；行号见各表。
