# R77 — serde 结构总目录：1436 个结构、22 个同名不同 arity

## 1. 为什么这轮先做目录

R75 用"arity + 形状双闸"从池里重建了 277 个结构的字段表，R76 证明了一个池只是分片。于是下一步本该是"合并多池把 under 的 1072 个补齐"。

这条路径本轮试了两次，都因为成本不可接受而没有产出读数：

| 尝试 | 结果 |
| --- | --- |
| `probe59`（每模板回溯 8 个名字块，各 K 值独立切分） | 跑满 15 分钟 CPU 1245 s 未收敛，判为不可用 |
| `probe59b`（按块缓存切分，块间不粘连故可分离切分） | 已写出，同样长时间无输出，本轮停掉 |

这两次失败本身是一条判据：**多块合并的计算边界不是算法正确性问题，而是每模板 × 8 个 K × 长池的乘积**。在拿到"合并后哪些结构真能收口"的读数之前，不能声称该轴可行。

因此本轮转向一个不需要切分、模板直读、因此不可能因为切分算法出错而失真的成果：**全量结构目录**。

## 2. 读数

`.rdata` 全段枚举 `struct <Name> with <N> element(s)`，按结构名归组：

| 读数 | 值 |
| --- | --- |
| 模板总数 | **3186** |
| 不同结构名 | **1436** |
| 只出现一次的名字 | 804 |
| 出现多次的名字 | **632** |
| 只带一种 arity 的名字 | **1414** |
| **带多种 arity 的名字** | **22** |

出现次数最高的一批全是目录/凭据类结构：`JwkSet` ×16（arity 1）、`RefreshResponse` ×16（3）、`PersonalAccessTokenMetadata` ×16（5）、`ErrorDetail` ×15（1）、`ErrorEnvelope` ×15（1）、`RuntimeRegistrationResponse` ×15（3）、`Helper` ×15（**2 / 4 / 5**）、`RSAKeyParameters` ×14（3）。

## 3. 22 个同名不同 arity

这是本轮最有信息量的一块：**同一个结构名在镜像里被编译成了不同字段数的版本**。

| 结构名 | arities |
| --- | --- |
| `Helper` | 2, 4, 5 |
| `CreateArguments` | 2, 3 |
| `FsCopyParams` | 3, 4 |
| `FsCreateDirectoryParams` | 2, 4 |
| `FsGetMetadataParams` | 1, 3 |
| `FsReadDirectoryParams` | 1, 2 |
| `FsReadFileParams` | 1, 3 |
| `FsRemoveParams` | 3, 5 |
| `FsWriteFileParams` | 2, 4 |
| `InitializeResponse` | 2, 4 |
| `JwtHeader` | 1, 2 |
| `ListArgs` | 2, 3 |
| …（共 22 个，全表落模块常量） | |

这批名字有一个共同的外部特征：**几乎全是 `Fs*` 系（文件系统 MCP 工具参数）与 `Helper` / `ListArgs` / `CreateArguments` 这类泛型工具结构**。`Fs*` 那一族出现两个 arity，最可能的原因是**同一工具在两种协议版本 / 两种 transport 上各有一份参数结构**——这解释了为什么它们的池内容也不同（R75 的 11 个多副本冲突里有 `ActivePermissionProfile`、`QuickDial` 等，与本轮 22 个不重合，是两类不同现象）。

本轮不做归因，只登记"同名不同 arity 存在"，并把它变成可执行断言：`ARITY_VARIANTS` 里任何一项只要 `len < 2` 或重复，`validate_catalog()` 就抛。

## 4. 与 R75 的自证

R75 的 277 个重建结构必须**全部**能在本目录里找到，且其 arity 必须在目录声称的 arity 集合内。测试逐条断言：

- `missing == []`（277 个全部在目录里）
- 每个 `STRICT_STRUCTURES[name][0] in arities_of(name)`

这一条把 R75 与 R77 焊在一起：R75 若因切分出错而凭空多出一个结构名，R77 的目录会立刻暴露它。

顺带确认了几个关键结构：`ThreadStartParams` arity **27**、`TurnStartParams` arity **28**、`JwkSet` arity **1**、`ConfigRequirementsToml` arity **46**。

## 7. 诚实边界

1. **目录只含"serde 打印过的结构"。** `#[derive(Debug)]` 但未走 serde 的 struct、以及没有 `expecting` 文案的结构（部分新版本 serde 用 `Serialize` 侧文案）不在目录里。所以 1436 是**下界**。
2. **22 个同名不同 arity 未归因。** 只能确认"存在两个版本"，不能确认是协议版本差异还是泛型实例化。
3. **多块合并轴未拿到读数**（见 §1），本轮不声称它可行或不可行。
4. **132 个 `2147` 计数未与 R62 的 `arity_clean`（1922 条）逐条对账。** 两表的判据源不同（R62 从 `clean_single_N` 家族取，本轮从模板取），交叉对账留待后续。

## 8. 覆盖进度

| 轮次 | 成果 | 结构覆盖 |
| --- | --- | --- |
| R65 | LEA xref 归窗 | 44 |
| R75 | 池 arity+形状双闸 | **277**（字段名 814） |
| **R77** | **模板全量目录** | **1436（arity 全覆盖，字段名 277）** |

按名计：**1436 / 1436 = 100% 结构名与 arity**；**277 / 1436 = 19.3% 有字段名**。这两条要分开说——目录完整不等于字段名完整。
