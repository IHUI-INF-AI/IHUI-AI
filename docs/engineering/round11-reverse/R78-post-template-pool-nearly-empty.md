# R78 — 模板后的池几乎无量：前池版选择只漏掉一个结构

## 1. 要检验的方向选择

R75/R77 只读模板**前**的名字连排。这个方向是假设，不是证明：serde 模板后面的字节同样可能是名字池。若后面也常带字段名，那 R75 的 277 就是"只看了半边"的结果。

本轮量它。方法：对 3186 个模板，各取紧邻的**前块**与**后块**（上限 900 B 的连续 word run），各用 20k 字典 trie 切分，再分别用"arity + 形状"双闸判定；并做三种组合（前、后、前+后）。

## 2. 读数

| 组合 | 通过 arity 的 site 数 | 通过双闸的结构名数 |
| --- | --- | --- |
| 只前块 | **489** | **277** |
| 只后块 | 3 | 2 |
| 前 + 后 | 488 | **278** |

模板后带内容的分布：

| 读数 | 值 |
| --- | --- |
| 模板总数 | 3186 |
| 后面跟了一段 word run | **86**（2.7%） |
| 其中切出来全是字段形 | **3** |

## 3. 净收益：一个结构

`AFTER_ACCEPTED = ('ErrorEnvelope', 'FsReadFileResponse')`，其中：

- `ErrorEnvelope` 在 R75 已通过**前池**拿到 ⇒ 不算增量；
- **`FsReadFileResponse` 只有后池才有** ⇒ `ONLY_VIA_AFTER`，本轮唯一的净增量。

因此 R78 把结构覆盖从 **277 推到 278**，并把这 +1 精确归因到"后池"这一路。

## 4. 前池复现：与 R75 逐名完全相等

这是本轮最有价值的自证：本轮独立实现的前块切分，在 3186 个模板上产出 **277 个结构名，与 R75 的表 `set` 完全相等**（`before - r75 = ∅`、`r75 - before = ∅`）。

这说明 R75 的结果不是某次运行偶然，而是**判据本身稳定复现**。

## 5. 一个反直觉的读数

"前+后"的通过 site 数是 **488**，比"只前"的 489 **少一个**。原因：个别结构在前池单独恰好等于 arity，拼接后块后段数变成 over，反而被拒。而结构名数仍是 278（因为 `FsReadFileResponse` 只在后池成立）。

这个细节值得记：**双闸是"精确等于"，不是"至少包含"**。拼接带来的多余名字会破坏精确性。若将来要放宽成"≥ arity 且可选出 arity 子集"，必须另立判据，不能悄悄改 `==`。

## 6. 交付

- `apps/ai-service/app/core/struct_bidirectional_pool.py`
  - `BEFORE_ACCEPTED_COUNT = 277` + `BEFORE_MATCHES_R75 = True`（并在 `validate` 里与 `STRICT_STRUCTURES` 硬比）
  - `AFTER_ACCEPTED` / `ONLY_VIA_AFTER` / `BIDIRECTIONAL_GAIN = 1`
  - `AFTER_BLOCK_TEMPLATES = 3186` / `AFTER_BLOCKS_WITH_NAMES = 86` / `AFTER_BLOCKS_FIELD_SHAPED = 3`
  - `POST_TEMPLATE_POOL_RICH = False`
  - `validate_bidirectional_pool()` / `bidirectional_summary()`
- `apps/ai-service/tests/test_struct_bidirectional_pool.py`：9 例

## 8. 诚实边界

1. **后块上限 900 B**：更长的后池不会被读到。但 86/3186 的基数说明即使放宽，量级也不会变。
2. **"前+后"的 488 < 489 未逐例归因**：只记录了现象与原因假设（拼接破坏精确相等）。
3. `FsReadFileResponse` 只拿到"名字 + arity 能对上"，**其字段名表未落**（后池切出的具体名字未纳入 277 那套表）。
4. 本轮的 278 只是"可被双闸证明"的结构数，不是镜像结构总数（总数见 R77 的 1436）。

## 9. 对"抄全"的净影响

| 项 | R75 | R78 |
| --- | --- | --- |
| 有字段名的结构 | 277 | **278** |
| 有名字+arity 的结构（目录） | 1436 | 1436 |
| 前池方向的完备性 | 未验证 | **已验证**（只漏 1 个） |

这条读数的意义不在于 +1，而在于**把"只读前池"从假设变成了经测量的选择**，并量出它的代价恰好是 1。
