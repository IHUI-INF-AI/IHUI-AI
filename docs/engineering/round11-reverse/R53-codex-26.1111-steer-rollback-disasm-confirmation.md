# R53 — steer/回滚 因果方向 反汇编确证（R52 纠偏的证据升级）

- 日期：2026-11-18
- 对照物：`codex.exe` 26.1111.2228.0（Rust 主引擎，`app/resources/codex.exe`，382,514,992 B）
- 取证手段：**RIP-relative LEA 交叉引用扫描 + objdump 定向反汇编**（纯静态、秒级；绕开 R52 全量分析超时）
- 本轮性质：**证据升级**（把 R52 的因果结论从「strings 偏移推定」升级为「反汇编序列化块确证」）
- 改动：无源码改动（R52 已落地的纠偏正确）；新增取证报告

---

## 1. 取证方法（本轮核心，绕开 R52 的超时瓶颈）

R52 用 Ghidra headless 全量 auto-analysis 取交叉引用，382MB PE 在 1200s 内未完成。
本轮改用**轻量定向法**，两步：

### 1.1 RIP-relative LEA 交叉引用扫描（纯 Python，无第三方库）

objdump -h 取段映射（`.text` VMA=0x140001000 off=0x400 / `.rdata` VMA=0x1517d7000
off=0x117d6000），换算两串 VA，再线性扫 `.text` 段内 `REX.W 8D /r`（`48/4C 8D`
+ modrm `mod=00 rm=101` = RIP-relative disp32），算每条引用目标 VA 比对。

三处引用全部命中，`not_steerable` 与 `rollback_failed` 的 LEA **成对出现在同一代码区**：

| 引用点 | not_steerable LEA | rollback_failed LEA | delta |
|---|---|---|---|
| 区1 | `0x141AB6039` | `0x141AB612C` | 243 |
| 区2 | `0x148E17DA9` | `0x148E17E9C` | 243 |
| 区3 | `0x14BF484B3` | `0x14BF485B1` | 254 |

delta 243/243/254 恒定 ⇒ 二者被**同一代码区**引用（不是分散在各处的控制流）。

### 1.2 objdump 定向反汇编（确证语境）

反汇编 `0x141AB6000`–`0x141AB6180`：

```
141ab600b:  movb $0x7b,(%r8,%rax,1)      ; 写 '{'
141ab6031:  movb $0x22,(%rcx,%rax,1)     ; 写 '"'
141ab6039:  lea  0xfe91d6e(%rip),%rdx    # 0x151947dae  ← not_steerable
141ab6040:  mov  $0x19,%r8d              ; 长度 = 0x19 = 25（= 字符串长 + 引号包装）
141ab6049:  call 0x1430dba00             ; 序列化调用
141ab6081:  movb $0x3a,(%rcx,%rdx,1)     ; 写 ':'
141ab6101:  lea  ...,%rdx # 0x151947d64  ; 下一错误码
```

**这是错误码 JSON 序列化代码块**：逐字节写 `{` / `"` / `:`，LEA 取错误码字符串 +
长度 25 调序列化（`call`）。三处引用点全部同此模式。

⇒ 两串是**被同一序列化遍历引用的错误码表相邻项**，**绝非**「拒绝 steer → 触发回滚」的
控制流。

## 2. 结论升级

| 取证层级 | R52 | R53（本轮）|
|---|---|---|
| 两串关系 | strings 偏移恒差 25B（结构推定）| LEA 成对 + 同区 delta 243/254 |
| 引用语境 | 未知（Ghidra 全量超时）| **反汇编 = JSON 错误码序列化块** |
| 因果方向 | 字面义否证（rollback_**failed**）| **序列化块反汇编确证：无控制流因果** |

R52 的纠偏结论（「拒绝 steer ≠ 触发回滚」，`turn_steerability.py` 移除
`thread_rollback` 字段改报 `error_code`）**经本轮反汇编确证正确**，无需再改源码。
R52 报告 §5 的诚实边界「基于 strings 非反编译控制流」由本轮补上反编译层证据。

## 3. 方法论沉淀（可复用，治 R52 类超时）

对超大原生二进制（数百 MB）做单符号/单字符串取证，**不必全量 Ghidra auto-analysis**：

1. `objdump -h` 取段 VA/fileoff 映射（秒级）；
2. `grep -abo` 取目标字符串文件偏移，换算 VA；
3. 线性扫 `.text` 内 RIP-relative LEA（`48/4C 8D` + modrm `00 101`），算目标 VA 比对；
4. 命中后 `objdump -d --start-address --stop-address` 定向反汇编该引用点看语境。

全程秒级、零第三方依赖、可脚本化。本轮扫描脚本（scratch，已回收）：
RIP-relative 扫描 + 兜底 raw VA 搜索（确认错误码表经 LEA 间接引用、非内嵌 VA）。

## 4. 诚实边界

1. 本轮确证的是「两串属同一 JSON 错误码序列化块」——即它们是**并列错误码**，无
   控制流因果。这**确证了 R52 的否定结论**（拒绝≠回滚），但**未**确证
   `THREAD_ROLLBACK_FAILED` 的**正向触发条件**（什么操作启动回滚、回滚因何失败）——
   那需追 `0x1430dba00` 序列化调用方的上层错误分发逻辑，属另一轮；
2. `thread_rolled_back`（回滚成功事件）本轮未取交叉引用，仍只在 strings 层确证其
   独立存在（距 not_steerable 约 7405B）；
3. 反汇编未配 PDB，函数名已 strip（只有地址），`call 0x1430dba00` 的目标函数语义
   为「序列化调用」是据其参数形态（buf+str+len）推定，非符号确证。
