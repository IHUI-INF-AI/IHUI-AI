# R71 · 反汇编定序失败（field 已内联）+ `cwd` 归属被否证，Turn 候选归零

> 对象：`codex.exe`（OpenAI Codex 26.1111.2228.0，Rust PE）
> 前序：R70 记录 `TURN_LAST_NAME_CANDIDATE='cwd'`（未验证），并把「分片表无边界」否证。R70 §7 第 1 条给出唯一能定序的路径：反汇编 `Debug` impl 的 `DebugStruct::field` 序列。

## 1. 结论先行

1. **`DebugStruct::field` 被内联，调用点定序失败**（第 5 条否证 `inlined-debug-field-call`）。最小 x86-64 走查给出四个候选函数的 call 统计：

| 函数 | call 数 | distinct 目标 | 观测 |
| --- | --- | --- | --- |
| `merged` `0x145800120..0x145808ea8` | 376 | 219 | top 目标 `0x15174cbd0` 28 次，**只挂 1 个不同 name lea** |
| `turn_worker` `0x145772930..0x14577e0e7` | 369 | 184 | top 目标 30 / 29 / 29 / 29 次，**name lea 全为 0** |
| `turn_worker2` `0x145781900..0x1457864b0` | 187 | 58 | top 目标 29 次，name lea 全为 0 |
| `turn_worker3` `0x145875a20..0x14587a060` | 209 | 109 | top 目标 17 次，name lea 全为 0 |

   top 目标的地址（`0x1513fed80`、`0x15151b220`、`0x152da4888`、`0x152da4978`）全部落在**导入/GOT 区**，即 `FF /2 [rip+disp32]` 的间接调用；字段名不是这些调用的第二参数。⇒ **不可能靠 call 站点把字段名排成声明顺序。**

2. **内联后的证据形态已量到**：字段名 `lea` 与空串 `lea` 交替出现，相邻字段 `lea` 间距 **0x115（277 B）**；函数内**没有** `": "` / `{` / `}` 字面量（分隔符被折叠进常量或走 `write_str` 的立即数）。这解释了 R69/R70 一直切不出"边界"的根因：**这张表根本没有边界字面量，只有间距规律**。

3. **`cwd` 归属被硬否证**（R70 的候选归零）：`0x145804779` 的 lea 解析出的字面量是
   ```
   'cwdstruct GitDiffToRemoteParams with 1 element'
   ```
   即 `cwd` 与 `GitDiffToRemoteParams`（**arity = 1**，与模板 "1 element" 一致）在同一条合并串里 ⇒ `cwd` 是那个单字段结构的唯一字段，**不是 TurnStartParams 缺的第 28 名**。
   - Turn 缺口**仍是 1**，且**候选名单归零**（`TURN_LAST_NAME_FALSIFIED=True`，`CWD_OWNER_STRUCT='GitDiffToRemoteParams'`，`CWD_OWNER_ARITY=1`）。

## 4. 边界（诚实面）

- **顺序仍未定**：三类表（记录表 / 分片表 / 内联序列）都已实测，**都不含声明顺序信号**；内联序列的间距规律只说明"有 N 个字段"，不说明"谁先谁后"。
- **Turn 缺名候选归零**：`cwd` 归属已排除，本轮没有新候选；缺口 1 保持未知。
- **Thread 仍不可分**：43 名混合集合未动。

## 5. 下一步

1. **Ghidra 定点反编译**（`D:\DevEnv\ghidra_12.1.4` 已装、REA 6.4.0 已验证）：内联后只能靠**数据流**判序——`DebugStruct` 的 `&mut` 在每个 `write_str` 之后被连续传递，反编译能把这个传递链还原成语句序；这是目前唯一未用的重手段。
