# R87–R88 — 枚举变体表定位，并把最后一条替代路线实测关掉

## R87：hook 枚举的变体表

serde 把枚举变体名存成 `&'static [&'static str]`，即与 `FIELDS` 完全同型的 16 B `(ptr, len)` 记录数组。所以枚举这条路径可以用 R84/R85 同一判据测。

| 枚举 | 变体数 | 定位结果 |
| --- | --- | --- |
| `BlockDecisionWire` | 1 | 偏移 1 的窗口（薄） |
| `PermissionRequestBehaviorWire` | 2 | **13 份整条 run** |
| `PreToolUseDecisionWire` | 2 | 整条 run `0x151f9dc30` |
| `PreToolUsePermissionDecisionWire` | 3 | **未定位** |

**13 份**这个数字值得停一下：一张两字符串的表在 `.rdata` 里重复 13 次，是"同一个小枚举嵌进 13 个不同的序列化结构"的形状，而不是"一张表被大家共用"。地址分布从 `0x1519c3848` 一直散到 `0x152363318`，跨了 9 MB。

`PreToolUsePermissionDecisionWire`（`allow/deny/ask`）在 4005 条 run 里没有任何数组——与 R85 对 input 段得到的否定答案同型。

4 个中定位 3 个，`ENUM_ARRAYS_ATTESTED=True`（集合相等），`ALL_ENUMS_LOCATED=False`。

## R88：代码级字符串路线，实测关掉

R86 把池路线天花板定在 914/1436，并指出 500 个结构的模板邻域里没有字段名字节。当时留的最后一个候选来源是**代码级字符串比较**：手写 `serde_json` 会 `lea rdx, [field_name]` + `call get`，那么一个函数的 `lea` 目标集合就应该是它的字段名。

把 1,160,394 个 `lea` 站点与 1,139,013 个函数区间全量对齐后实测：

| 读数 | 值 |
| --- | --- |
| 至少有一个标识符 `lea` 的函数 | 17,649 |
| **函数标识符集大小，中位数** | **2** |
| p90 / 最大 | 4 / 88 |
| **已知字段表整体出现在单个函数内** | **1 / 316** |

**中位数 2 就把这条路判死了。** 一个 arity 5 的 serde 结构需要从同一段例程里 `lea` 出 5 个字段名；而典型函数只引用 2 个标识符（错误消息、单个 key、格式串）。这说明 `lea` 空间里载的是**逐个字符串**，不是字段表。

正控让这件事从"推断"变成"读数"：316 个由数组路线已经确定的字段表，只有 **1 个**能在任何单个函数里找到完整集合（`ErrorData`(3) @ `0x14b3656b0`）。如果代码级字符串真能承载字段表，这个数应该是几百。

于是 `CODE_ROUTE_VIABLE = False`。

## 三条路线，全部闭合

| 路线 | 结局 | 判据/读数 |
| --- | --- | --- |
| 池切分（模板前连排区） | **天花板 914/1436** | R86：empty=500，池里没有字节 |
| 模板 lea 配对（同函数） | **否证** | R82：3186 模板的 `lea` 命中 = 0 |
| 代码级字符串比较 | **否证** | R88：函数标识符集中位数 2，正控 1/316 |

这三条是这台二进制上"从字节里读字段名"的全部可行入口。三条都到顶之后，那 500 个 `empty` 结构的字段名**不以本链能读到的任何形式存在**——它们不是枚举、不是 derive 结构的字段表、也没有成组的代码字符串。

能拿到的就是这些：**316 个目录结构有字段表**（+ 5 个 hook schema 名在目录外），**hook 侧 9 个定义对象/段 + 3 个枚举变体表**在二进制里坐实。

- `apps/ai-service/app/core/hook_enum_binary_lookup.py`（R87）

  - `FUNCS_WITH_IDENT_LEA=17649`、`SET_SIZE_MEDIAN=2`、`SET_SIZE_P90=4`、`SET_SIZE_MAX=88`
  - `KNOWN_FIELD_LISTS=316`、`POSITIVE_CONTROL_HITS=1`、`CONTROL_SAMPLE=("ErrorData",3,"0x14b3656b0")`

## 诚实边界

1. 枚举定位命中的是**变体名集合**，不证明那 13 份副本逐字相同（只验证集合相等）。
2. `BlockDecisionWire` 单变体 ⇒ 一元素窗口无法定位，记薄证据，不计入认证。
3. R88 的"中位数 2"包含全量 17,649 个函数；若只看大函数（max 88）也仍远低于成表所需——但本轮没按 arity 分组统计，这个更强的说法不写进结论。
4. `lea` 表只含 rip-rel `lea` 到 `.rdata` 的站点；用 `mov`/`add` 取字段名的路径不在统计内。这是一个已知盲区，但没有理由认为它占主导（R82 已证模板亦无 lea）。
5. 三路线闭合是**在这台二进制 + 这套判据**下的结论，不是"信息论上不可能"——换别的取证工具（Ghidra 的函数级类型恢复）仍是另一条路，但那不是本链的判据，也不作承诺。
