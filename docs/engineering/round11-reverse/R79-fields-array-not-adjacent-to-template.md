# R79 — FIELDS 数组不在模板前面（否证 #7）

## 1. 要检验的假设

R75 发现 1244 个模板前面不是名字连排池，而是指针数据或零字节。R68 已证明 serde 的 `FIELDS` 是连续 16 B 胖指针数组。于是有一个很自然的希望：**那些"空池"模板其实就是紧跟在自己 FIELDS 数组后面的**。若成立，读数组即得字段名，而且记录序就是声明序（R72 只能靠 `lea` 拿顺序）。

## 2. 方法

对 3186 个模板逐个：在模板前 512 B 内、按 16 种字节对齐，向后每 16 B 取一条记录 `(ptr, len)`，合法条件 = ptr 落在 `.rdata` 内 ∧ 4 ≤ len ≤ 64 ∧ 指到的 len 字节全为名字字符 ∧ 文本字段形 ∧ **名字后面紧跟的字节不是名字字符**（首版判据）。取最长链，与模板声明的 arity 比对。

## 3. 读数

| 读数 | 值 |
| --- | --- |
| 模板总数 | 3186 |
| 前面有合法记录链 | **29**（0.91%） |
| 链长恰等于 arity | **5** |

5 条全落在 arity = 1：

| 结构 | 记录内容 |
| --- | --- |
| `CloudConfigTomlBundle` | `operationId` |
| `CloudRequirementsTomlBundle` | `platform` |
| `ConfigurationReasoning` | `update` |
| `ErrorDetail` | `platform` |
| `SkillDependencies` | `tool_result` |

## 4. 结论

**模板不紧跟 FIELDS 数组。** 若紧跟，命中率应是多数而不是 0.9%。所以那 1159 个无字段名结构的名字**不在模板邻域**——它们在哪里由 R68/R69 的 15k/17k 条记录 run 决定，必须走"数组优先"的反向归属，而不是"模板优先"的正向邻域读。

这 5 条**全部标注为未认证**（`ADJACENT_PAIRS_ATTESTED = False`）：每条都是 arity=1，一条相邻记录完全可以属于邻居结构，因此只作观测、不作重建。模块里把"把这 5 条升级为重建"写成了会抛错的操作。

## 7. 诚实边界

1. **首版判据有缺陷**：要求"名字后跟非名字字符"。真 FIELDS 的指针指向连排池，名字后面往往就是下一个字段名首字母，这条检查在 R80 里被证明会把真数组几乎全部拒掉。R79 的 29/5 是在这条偏严判据下得到的，**因此"模板不紧跟数组"这个否证本身也需要重新确认**——R80 用去掉边界检查的判据重扫，得到的结论仍是模板邻域无量（64 个匹配来自全 .rdata 扫描，不是邻域），但两条判据的命中率不能混用。
2. 只看前 512 B；更远处不扫描。
3. 只看 16 B 对齐的 16 种相位；FIELDS 若不在 16 B 对齐处会漏。

## 8. 与 R80 的衔接

R79 走的是"模板 → 数组"（正向邻域），失败。R80 走"数组 → 结构"（反向归属），成功 65 个。这一对失败/成功正好确定了下一条判据的方向：**必须以数组为主语**。
