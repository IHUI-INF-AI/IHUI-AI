# R89–R90 — 待办账收口：A2 结案、A7/A8/A11a 定账、A12 变成可执行

R88 之后我说"没有下一步建议"。这句话在"从字节里继续读字段名"这个方向上成立，但它把一批**不依赖 Ghidra、也不依赖字节**的待办一起搁下了。这轮把那些全部收掉。

## A2 — "7 个未解析片段"根本不存在

R63 记的是 23 段，早期笔记说"30 处 `type:object`，7 段是片段"。这轮把 30 这个数拆开了：

| 口径 | 计数 |
| --- | --- |
| `"type": "object"` 字面出现（全镜像） | **30** |
| 严格遍历后完整 schema（花括号配对 + `json.loads` + `type==object` + `properties` 非空 + `title` 非空 + 去重） | **23** |
| 差额 | **7** |
| 其中"残片" | **0** |

那 7 个是什么，上下文直接说明：每一个都紧跟在 `"required": ["hookEventName"]` 或 `"required": ["behavior"]` 之后，是被 23 段**完整收录的嵌套 `hookSpecificOutput` 子对象**。它们不是被切坏的片段，是同一份 JSON 里的内层对象。

所以 A2 的结论是 **`no-unparsed-fragments`**——不存在可回收的残片。这一项可以结案，而且是"零遗漏"式结案，不是"放弃"式结案。

R58 的三组数：**95 struct-variant families / 0 unit-variant / 209 tagged enums**。

在这 95 个族里，本仓 **60 个零副本、35 个部分覆盖**。最宽的六个：

| 族 | N | 状态 |
| --- | --- | --- |

**一个自纠值得留**：早先用裸子串扫 `ota` 读出 999 次，几乎全是 `quota` 里的。换词边界后是 12。`quota=4` 与 `ota=12` 并排放在表里，就是为了让这个差别看得见。

## A12 — 契约从表变成函数

A12 是 R64 定的两条"超越轴"之一：把已恢复的字段级契约变成**运行期能力**。这轮交了 `hook_contract_runtime_check.py`：

- 输入：schema title（或 event + direction）+ 载荷
- 三类违规可分：`unknown-schema` / `unknown-field` / `missing-required`
- `unknown-field` 与 `missing-required` **一起报**，不短路——修载荷的人要一次拿全清单
- `audit_all_schemas()`：把每段的 `required` 集合自己跑一遍，任何一段拒绝自己的必填集 ⇒ 恢复出的表内部不自洽，模块不可信
- `minimal_payload()`：给出能满足必填的最小合法形状

**明确不做类型校验**，这是刻意的：schema 里每个 property 都有 `"type"`，但 `oneOf`/`anyOf`/`$ref` 的解析只有真正的 JSON Schema 引擎做得对，半吊子实现会把合法载荷判红。这个函数只回答它能回答的问题——**键集对不对**。

`audit_all_schemas()` 的 23 段全部通过自己的必填集，这一条同时是对 R63/R64 提取结果的**内部一致性证明**。

## 剩余的三项，以及为什么不做

| 项 | 内容 | 为什么不做 |
| --- | --- | --- |
| A1 类型层 | 非 hook 字段的 Rust 类型 | 唯一候选数据 `r62/field_contract.json` 实测是**切分残渣**（`StandardErrorResponse` 的值是 `['tandard','Error','Responseerror_descriptionerror_uri']`，`Standard` 被切坏）⇒ 无可信输入 |
| A5 | `Message`(N=17) 真值 | 需 Ghidra xref |
| A9 | `default` 57 处生效语义 | 需 xref 或运行观测 |
| A10 | `app.asar` 30 chunk | R14 已证 loop 不在前端，边际收益低 |
| A3 | 262 处 internally tagged enum | R58 实测口径是 **209**；本轮 4 个 hook 枚举已定位（R87），其余 205 个需逐族 variant 取证，与本链"读字段名"不同轴 |

`A1` 这条我特别说明：不是"没做"，是**试了、发现输入是脏的**。把残渣当类型表写进仓库是造假，所以停下。

## 诚实边界

1. A2 的"0 残片"依赖我这一套严格判据；换一种配对实现（例如允许截断前缀的块）可能读出别的数，但那时读出的东西也不再是"完整 schema"。
2. A7 的 4,660 是 arity 之和，**不是**字段名数。任何引用这个数的地方都必须带这个限定。
3. A8 的 60/35 拆分按 `family_gap.out` 的 `ZERO` 标记判，该文件是 R58 的产物，本轮未重算族归属。
4. A11a 只是词频。一个词出现 57 次不等于遥测在跑——这是存在性判定，不是行为判定。
5. A12 未接进 hook 执行链。它是可调用的纯函数，接线是执行层的事，本链不碰执行层。
