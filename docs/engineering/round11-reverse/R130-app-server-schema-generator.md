# R130 —— 它自己就带了一份协议字典：`app-server` 的 schema 生成器

> 这一轮的价值不在"又读了一个文件"，而在于发现**不必再猜协议**。二进制里装着一台打印机，
> 一条命令就能把整个 JSON-RPC 协议打成 329 份逐字 JSON Schema。

## 一、怎么撞上的

为了补账本里 `codex_cli_surface` 这一格（当时 7 个子命令只跑过 `exec`），把其余六个都推到
help 面。六个全 `rc=0`：

| 子命令 | 事实 |
|---|---|
| `plugin` | 插件安装/列举面 |
| `review` | 代码评审面 |
| `login` / `logout` | 凭据面（刻意没跑真实副作用） |
| `mcp` | MCP 服务器管理面 |
| `app-server` | **自带 `generate-json-schema` 与 `generate-ts`** |

`app-server --help` 里那两行就是这一轮的杠杆。真跑：

```
codex app-server generate-json-schema --out <DIR>
codex app-server generate-json-schema --out <DIR> --experimental
```

产出 **329 个 JSON**（stable）与 **479 个**（experimental），体积 775,089 B / 957,557 B。

## 二、四封套与它的计数

协议不是一张平表，是四个封套：

| 封套 | stable | experimental |
|---|---|---|
| `ClientRequest` | 107 | 182 |
| `ClientNotification` | **0** | **0** |
| `ServerNotification` | 81 | 81 |
| `ServerRequest` | 9 | 11 |
| 合计 | **197** | **274** |

两个结论只有量过才成立：

1. **`ClientNotification` 两面都是 0**。它不是"这一批没生成"，而是这个封套把 method 保持为自由
   字符串，根本没有可枚举的方法表。把它读成"0 个方法"是错的，读成"缺失"也是错的。
2. **`ServerNotification` 两面都是 81**。通知面在实验旗标下**一个都没加**。新增全集中在请求面。

## 三、delta 恰好 77，且 stable-only 为 0

274 − 197 = **77**，与实际算出的 experimental-only 集合大小逐一相等。更重要的一格是
**stable-only = 0**：没有任何方法在实验面里消失。这排除了"旗标重写协议"的可能，
把它钉成"旗标只加不减"。

实验面新增的家族（按目录）：

| 家族 | 新增 |
|---|---|
| `project/*` | 8 |
| `remoteControl/*` | 8 |
| `process/*` | 6 |
| `thread/queue/*` | 6 |
| `thread/realtime/*` | 6 |
| `userVerification/*` | 5 |
| `environment/*` | 3 |
| `memory/*` | 2 |
| 单点 | `currentTime/read`、`rollout/compress`、`server/diagnostics` |

还有一个 `mock/experimentalMethod` —— 协议把自己的测试桩也当成面的一部分交付。

stable 面 34 个家族，`thread` 59 条最大，`item` 19、`account` 18、`plugin` 12、`fs` 10、
`turn` 8、`mcpServer` 7。家族表求和必须等于 197，这是 `validate_contract()` 的一条硬断言。

## 四、传输面

`--listen` 五档：`stdio://`（默认）、`unix://`、`unix://PATH`、`ws://IP:PORT`、`off`。
`--ws-auth` 两档：`capability-token` / `signed-bearer-token`。另有六个 `--ws-*` 旗标。
app-server 的分析默认**关**，要 `--analytics-default-enabled` 才开。

## 五、落成什么

`apps/ai-service/app/core/app_server_protocol_surface.py` + 测试 **25 passed**。
七条反向变异每条都钉一个"量出来才成立"的事实：

| 变异 | 该被抓住的理由 |
|---|---|
| 让 stable-only 变 1 | 那就叫"旗标会删方法"，与测量结果反 |
| 给 `ClientNotification` 塞一条方法 | 它结构上没有方法表 |
| 家族表丢质量（thread 59→50） | 求和不再等于 197 |
| 通知面两面分叉（81→80） | 通知面在旗标下不变 |
| delta 里混进 stable 方法或出现重复 | 77 这个数是集合大小，不是计数 |
| 默认传输被改成 `ws://` | 默认是 stdio |
| 两面文件数倒置 | 实验面必大于稳定面 |

## 六、诚实的边界

这一轮拿到的是**清单与方法表**，不是字段级契约。329 + 479 份文件里每个 object 的
`properties` / `type` / `enum` / `required` 是独立的一趟活，尚未开始。
另外 stable 面 107 条 `ClientRequest` 只做了家族归类，逐条参数形状未与 `--experimental` 面做差异比对。
