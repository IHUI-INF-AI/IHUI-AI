# 还没榨干的面 —— 一份诚实的空白清单

> 账本现在报 `159 / 159 = 1.0`、`complete = True`。但"第一档全绿"只说明**已发现的面都读过了**，
> 不等于"这台程序里没有剩下的东西"。这份文件把**已知未覆盖**逐条摊开，避免把 100% 读成终点。

## 一、账本口径先说清

`complete()` 的判据是两条同时成立：

1. `closed_tier_complete()` —— 每个已登记域 `covered >= total`
2. `semantic_faces_covered() == SEMANTIC_FACE_COUNT` —— 已发现的面全落过

它**不**声称：
- 分母是穷尽的（`semantic_tier_bounded = False`）
- 二进制里不存在尚未发现的面

所以 100% 是"对着这份账 100%"，不是"对这 382 MB 二进制 100%"。

## 二、账本自己记的三条不可达（有证据）

| 面 | 卡在哪 | 证据 |
|---|---|---|
| `source_reproduction` | 许可证禁止 | `LICENSE.txt` 1437 B 原文禁止反向工程、反编译、复现与分发衍生作品；R96 逐字读过。读契约不是该行为，复现实现才是 |
| `live_execution` | 没有可用端点 | R106 实测 `POST /v1/responses` 502、`POST /v1/chat/completions` 400/503。环境缺口，不是手法缺口 |
| `live_hook_firing` | 触发条件没找到 | R105 试了 5 种配法、R107 又 2 种，全部被静默接受且无任何反应；四个候选原因一个都没排除 |

第三条最扎眼：**hook 从未真实执行过一次**。协议、事件名、退出码语义、字段名都读到了，
但"它到底在什么条件下触发"仍是黑的。

## 三、读到了但没读透的（自认）

### 1. 协议字段级契约（最大一块）
R130 拿到 329 + 479 份 JSON Schema 的**清单**与方法表，`197 / 274` 条方法。
**hook 那 12 个家族已经做到字段级**（`hook_contract_schema.py` 23 段 schema、
`hook_field_name.py` 26 个逐字字段名、`hook_field_type_contract.py` 类型/必填面）。
剩的是**其余方法族**——`thread`(59)、`item`(19)、`account`(18)、`plugin`(12)、`fs`(10)、
`turn`(8)、`mcpServer`(7) —— 这些只有 method 名，没有一条字段级契约。

### 2. sqlite 的行内容
R131 读了六库的 schema 与行数，**没读任何一行内容**。
`threads` 的 `title` / `first_user_message` / `preview`、`logs.feedback_log_body`、
`memories.stage1_outputs.raw_memory` 里是什么，全空白。

### 3. 表格技能的两份依赖文档
`officejs.md`（8,866 B）、`artifact_tool_docs/API_QUICK_START.md`（26,274 B）、
`style_guidelines.md`（10,165 B）—— live 面与 artifact 面的操作语法全在这三份里，均未读。

### 4. 两个模板器物从未真跑
`create-template-skill.mjs`（30,865 B）与 `check_template_fidelity.mjs` 只读过源码。
根因是 `unzip` 在本机不存在（只有 `C:\Windows\System32\tar.exe`），两者都用 `spawnSync("unzip")`，
必然断。

### 5. 渲染腿整体不可用
本机无 LibreOffice，`render_docx.py` rc=1。所以 docx/pptx 的"看起来对不对"只能靠判据，
不能靠看图。这是本链最实质的验证缺口。

### 6. OOXML 三处未覆盖
`graphicFrame` 内部绘图区、`pic` 的 `srcRect` 裁切、组自身 `rot` —— R110/R111 都绕过了。
另一处：`c:tx` 在 `numLit` 版图表里不渲染（R108 读图发现 `Q1` 没出现），未深究。

### 7. `--receipt` 的 owner-private enforcement directory
30 个候选目录全 rc=2，没定位到。

### 8. `config.toml` 末尾的零宽水印
来源不明，未处理。

### 9. hook 的 `enabled` 真实存储位置
六个 sqlite 里**没有 hook 启用表**。这条线索仍悬着。

## 四、如果要继续，优先级这么排

1. **其余方法族的字段级** —— hook 12 族已完成（23 段 schema / 26 个字段名 / 类型契约）。
   剩：`thread` / `item` / `account` / `plugin` / `fs` / `turn` / `mcpServer` 这七族的字段级提取。
2. **sqlite 行内容** —— 读 `threads` 的 `title` / `first_user_message`，能反推它对"会话标题"的生成策略。
3. **三份表格依赖文档** —— 补完 live 面的操作语法。
4. **`unzip` 缺口** —— 装一个 `unzip` 或改器物用 `tar.exe -xf`，两个模板器物才能真跑。
5. **LibreOffice** —— 装上后渲染腿恢复，docx/pptx 才能看图验收。
6. **hook 触发条件** —— 唯一还需要二进制取证（disasm LEA xref）的面。

## 五、一句话结论

**可达面已读完；不可达面有证据；未发现的面不可判定。**
"百分百榨干"在本仓的定义是这三句同时成立，而不是"二进制里没有东西了"。
