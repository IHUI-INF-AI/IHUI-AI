# R75 — serde 结构字段表的 arity + 形状双闸重建

## 1. 本轮要解决的问题

R74 结束时，池 A 的 16 个候选名字**没有归属、没有位置**；R65 的 44 结构字段表是 LEA xref 逐结构手工归窗的产物，代价高、覆盖面窄。此前所有努力都在单个池、单个结构上打转，缺的是一套**能覆盖全镜像**的判据。

本轮换轴：不再问"这个池属于哪个结构"，而是问"**镜像里一共有多少个结构，每个结构有几个字段**"。答案在 serde 的 `expecting` 文案里——`struct <Name> with <N> elements`。

## 2. 判据

### 2.1 模板枚举

`.rdata` 全段正则扫描 `struct ([A-Za-z_][A-Za-z0-9_]{2,60}) with ([0-9]{1,4}) elements?`：

| 读数 | 值 |
| --- | --- |
| 模板总数 | **3186** |
| 不同结构名 | **1436** |
| 模板紧前字节可打印 | 1941 |
| 模板紧前字节为 `\x00` | 1244 |
| 其他 | 1 |

同一结构名重复出现，是同一份 crate 代码在不同 target / 不同 monomorphization 副本里各带一份字面量（`JwkSet` 16 处、`PersonalAccessTokenMetadata` 16 处、`RefreshResponse` 16 处）。

### 2.2 池切分

模板紧前那串 `[A-Za-z0-9_]` 连续字节，就是该结构字段名的**连排池**（无分隔符）。用 20,287 条 ident 字典建 trie 做最长前缀切分。

**第一道闸（arity）**：切出的段数恰等于模板声明的 N。

读数：**489 / 3186 sites 通过**。

但这道闸单独不可信——TurnStartParams 池 348 B 被切成 28 段，数目恰好等于 arity 28，而其中 `er` / `ic` / `Ti` / `er` / `For` / `Turn` 六段是 `serviceTierserviceTierForTurn` 被字典切碎后的残渣。**数量匹配可以被碎片凑出来**。

### 2.3 第二道闸（形状）

每段必须是字段形：camelCase / snake_case / 纯单词（首字母小写）。

两道闸同时成立：**277 个结构 / 452 sites / 814 字段**。

被第二道闸拒掉的 212 个 site（489 − 277，按名去重后计）正是碎片凑数的那一类，这一拒是判据有效的直接证据。

### 2.4 同结构多副本冲突

452 sites 覆盖 277 个名字，其中 77 个名字有多 site。这 77 个里 **11 个存在"arity 相同、字段列表不同"**——同一结构在不同副本上的池内容有出入。本轮**不拍板、不做多数投票**，原样登记为 `ARITY_CONFLICTS`：

```
ActivePermissionProfile, AppReview, PersonalAccessTokenMetadata, QuickDial,
TextElement, ...（共 11 个，逐条落模块常量）
```

## 3. 交叉校验：与 R65 已认证的 44 结构对比

R65 的字段表是另一条独立判据（LEA xref 归窗 + 结构声明窗口）产出的，与本轮模板池切分**没有共享任何中间量**——两条路互证才有意义。

| 读数 | 值 |
| --- | --- |
| 两表重叠结构 | 19 |
| **字段集完全一致** | **16（84.2%）** |
| 分歧 | 3 |

分歧逐条（arity 均相同，差异各 1–2 名）：

| 结构 | arity | 仅 R65 有 | 仅本轮有 |
| --- | --- | --- | --- |
| EnvironmentInfo | 10 | `cwd` | `map` |
| RolloutBudgetConfigToml | 6 | `enabled` | `glob_scan_max_depth` |
| TokenBudgetConfigToml | 7 | `enabled` | `bundle_ids` |

`enabled` 出现两次、`bundle_ids` 出现在 TokenBudget 上——两者都更像**从上邻池借来的名字**（这两个池与相邻结构连排）。`cwd` 与 `map` 的分歧则与 R71 的 `cwd` 否证同源：`cwd` 的归属结构是 `GitDiffToRemoteParams`（arity 1），不是 `EnvironmentInfo`。

这 3 条**不做平滑**，作为 `CROSS_CHECK_DIVERGENT` 逐条落模块，任何一条被"修正"都会让 `validate_reconstruction()` 失败。

## 4. 交付

- `apps/ai-service/app/core/struct_strict_reconstruction.py`
  - `STRICT_STRUCTURES`: 277 结构 → `(arity, fields)`，全部机器派生，零手敲
  - `ARITY_CONFLICTS`: 11 个多副本冲突名
  - `CROSS_CHECK_IDENTICAL` / `CROSS_CHECK_DIVERGENT`（3 条逐字）
  - `validate_reconstruction()`: 结构数 / 字段数 / 每结构 `len(fields)==arity` / 无重复名 / 每名字段形 / 冲突名与分歧名必须都在表内
  - `fields_of(name)` / `reconstruction_summary()`
- `apps/ai-service/tests/test_struct_strict_reconstruction.py`：10 例
  - 计数自洽、arity 自洽、形状、无重复
  - 已知结构抽样（`JwkSet` / `RateLimitSnapshot` / `TuiGlobalKeymap`）
  - 分歧必须被记录而不是被抹平（`EnvironmentInfo` 必须在分歧表里，且 `strict_len == r65_len`）
  - 两例为人造变异准备的正面断言（arity 不符 / 非字段形 → 必抛）

## 6. 诚实边界

1. **池给出的是"名字集合"，不是声明序。** 池是连排字符串，字节序不等于 `#[derive(Debug)]` 打印序；声明序仍只有 R72 的 25 名（Turn）/ 25 名（Thread）。
2. **arity 可被碎片凑出**（TurnStartParams 实证），所以单闸不可用；本轮成果全部经双闸。
3. **277 是"可被双闸证明"的下界，不是"镜像里结构总数"。** 1436 个结构中 1244 个 site 池为空（模板前是 `\x00` 或 fat pointer），这类结构本轮一个字段也拿不到。
4. **`map` 这类单字段语义未追**：形状合法 ≠ 语义正确。`EnvironmentInfo` 的 `map` 究竟是字段名还是切片残渣，未判。
5. 11 个多副本冲突未拍板，是"同一结构在不同副本上的池内容不同"，不是"判据失效"。

## 7. 与既有判据的关系

| 轮次 | 判据 | 结构数 | 字段数 |
| --- | --- | --- | --- |
| R65 | LEA xref 归窗 | 44 | 455 |
| R68 | fat pointer 16 B 记录数组 | 44 | 455+ |
| R69/R72 | visitor 键 + Debug 打印序 | 2（顺序） | 52 名 |
| R73/R74 | 池残渣贪心切分 | 0（仅候选） | 17 名 |
| **R75** | **模板 arity + 形状双闸** | **277** | **814** |

R75 的 277 结构里包含 R65 的 19 个（16 一致、3 分歧），也覆盖了 R73/R74 那两个池所在的相邻结构——R74 的 16 个可信候选目前仍无结构归属，但它们的名字已进入本轮的 ident 字典，参与后续任何池的切分。

## 8. 开放轴

1. **1244 个空池 site**：模板前是 `\x00` 或 fat pointer 的结构，字段名在别处（可能走 R68 的记录数组，也可能整体不在 `.rdata`）。这是 1436 里最大的一块未回收面。
2. **814 → 全量**：本轮 277 / 1436 ≈ 19.3%。提升途径一是把 1072 个 "under"（切出段数 < arity）的池补全——它们的字段名散在多个池，需要"多池合并 + arity 收口"。
3. **11 个多副本冲突的裁决**：需要第三种判据（而非多数投票）来定哪一份是真。
4. **池序 vs 声明序**：若能证明某结构池的字节序恰好等于声明序（可用 R72 已定的 Turn/Thread 做对照），则 277 个结构的顺序可一并拿下。
