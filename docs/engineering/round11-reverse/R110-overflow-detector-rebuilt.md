# R110 — 修：造一个真能抓住溢出的检测器

> R109 判定对方的 `slides_test` 漏报。这轮不是记下它坏，是**补上那个洞**。

## 1. 为什么它会漏，为什么我不走它那条路

它自述的方法是 **render with padding and inspect the margins**。

这条路有个结构性漏洞：**渲染器把内容裁剪在画布边界上**。内容再怎么越界，都被裁掉、不会渗进 padding 区 —— **padding 永远是干净的，检查就没事可看**。

我 R109 手上那份 deck 正是这个形状：文字从 11,000,000 EMU 起、宽 9,000,000，画布只有 12,192,000。渲染出来 "OFF" 贴在右边缘被切断 —— 但 padding 区干净，所以它报 clean。

**⇒ 不走渲染。走 OOXML 几何。** 那条路径上没有栅格器可以裁剪任何东西，算术是精确的。

## 2. 检测器做了什么

读包里的 `sldSz` 拿画布，读每张 slide 里所有 shape 的帧，**把 group 的坐标映射正确串起来**，再逐个比。

组变换是这里最容易错的地方。`grpSp` 自带 `a:off`/`a:ext`，还给子元素一套 `a:chOff`/`a:chExt` 子坐标系 —— 子元素的坐标是**写在子空间里**的。不映射、或者漏掉第二层嵌套，每个组内形状都会算到错的坐标上。

```
abs_x = group_off.x + (child_off.x - ch_off.x) * (group_ext.cx / ch_ext.cx)
abs_cx = child_ext.cx * (group_ext.cx / ch_ext.cx)
```

嵌套时逐层复合。这条我在测试里用精确值钉住：两层组算出来必须是 **17,000,000**，差一层就是别的数。

## 3. 同一批文件，两个检测器，两个结论

用 R109 亲手造的那三个 deck 跑：

| deck | 对方 `slides_test` | 我的检测器 |
|---|---|---|
| `in.pptx` | clean, rc=0 | **clean** ✓ |
| `overflow.pptx`（右越界） | **clean, rc=0** ✗ | **右越界 7,795,300 EMU** ✓ |
| `farout.pptx`（两侧越界） | **clean, rc=0** ✗ | **左 3,987,300 + 右 13,795,300 EMU** ✓ |

检测器实跑的原文输出：

```
== overflow.pptx
   clean: False | slides: 1 | shapes: 1
    1 shape(s) leave the canvas:
      ppt/slides/slide1.xml shape 2 ('OFF CANVAS TEXT') leaves the canvas on right by right=7795300 EMU

== farout.pptx
   clean: False | slides: 1 | shapes: 1
    1 shape(s) leave the canvas:
      ppt/slides/slide1.xml shape 2 ('WAY OUT') leaves the canvas on left, right by left=3987300 EMU, right=13795300 EMU
```

**这就是"修"的判据**：同一批输入，一个漏报，一个全抓到。

数值是 7,795,300 而不是 7,808,000，是因为扣掉了 1 pt（12,700 EMU）的容差。见下。

## 4. 容差：1 pt 以内不报

尺子会取整，越出不到 1 pt 的是舍入不是缺陷。`TOLERANCE_EMU = 12,700`（1 pt = 12,700 EMU）。

在 13.3 英寸的画布上，任何眼睛看得见的溢出都远超这个量级 —— R109 的探针分别超出 4,000,000 和 13,808,000 EMU，**是两个数量级以上的差距**，不是贴着容差边界讨价还价的case。

这条也做了变异守门：把容差强制为 0，同一个"只超 5,000 EMU"的 deck 必须从 clean 变成报 5,000。

## 5. 它不能做什么 —— 这条必须写明

**溢出有两层，我只做了第一层。**

1. **几何越界**：shape 的框出了画布。纯算术，精确，含嵌套组。**这一层我做了。**
2. **文本溢出**：框装得下，但里面的文字需要更多空间，溢出去或被裁。**依赖字体度量和折行，XML 算术预测不了。我做不到，也没有假装做到。**

如果只报第一层就宣布"整个 deck 没有溢出"，那就是在犯我用这个模块来修的那个错。所以结果类型**自带**它查了什么、没查什么：

```python
layers_checked     = ("geometric",)
layers_not_checked = ("textual",)
```

clean 的时候 summary 逐字说的是：

> No shape leaves the canvas across 1 slide(s), 2 shape(s). **Geometric overflow only -- text that overflows its own frame is not visible here.**

有测试钉这一句。**改掉这句诚实声明，测试会红。**

## 6. 落成

`apps/ai-service/app/core/pptx_overflow_detector.py`：

- `Canvas` / `Overflow`（带 `sides` / `total_emu` / `describe()`）/ `Report`（带 `layers_checked` / `layers_not_checked`）
- `read_canvas` / `slide_parts`（按数字序，`slide10` 排在 `slide2` 之后）/ `detect`
- `_Transform`（`apply` + `child_of` 逐层复合）
- `_walk`（组递归下探，容器节点也下探 —— **这正是我第一版写错的地方**）

`tests/test_pptx_overflow_detector.py`：**19 passed**，测试自带造包工具，不依赖临时目录。

覆盖：画布内 / 右越界 / 两侧越界 / **抓得住对方漏报的那一枚** / 亚 pt 容差 / 超容差别报 / 组缩放 / 组内不越界 / 嵌套两层精确值 / 无 `sldSz` 报错 / 退化画布报错 / 坏包报错 / 文本层未查的诚实声明 / slide 数字序 / 恒等变换；外加两条变异守门。

## 7. 修的第一版写错了，记在这里

第一版 `_walk` 只遍历**直接子级**：遇到 `p:cSld`（不是 shape、不是 grpSp）就 `continue`，**于是整棵树下都没被走到**，`shapes_checked = 0`，每个 deck 都"干净"。

**8 个测试同时红，逼出这个 bug。** 如果不是先写测试再跑，这个检测器会以"永远报 clean"的形态交付 —— 比对方那个漏报的更糟：它连错都不出。

修法是容器节点也下探。这条写进这里，是因为它正是这类工具最典型的死法。

## 8. 诚实边界

1. **只覆盖几何层**。文本溢出（框够大、字太多）看不见，需要字体度量，未做。
2. `graphicFrame`（图表/表格）取 `p:xfrm`，**但图表内部绘图区是否越框，未查**。
3. `pic` 的 `srcRect` 裁切（用图的一部分）**未处理**，按整图框算。
4. 旋转（`rot`）**未处理**，按未旋转的轴对齐框算 —— 旋转 45° 的形状，实际角点比轴对齐框伸得更远。
5. 组合里的 `flipH`/`flipV` **未处理**。
6. 只测了我自己造的包，**没有在真实 Office 产出的复杂 deck 上验证过**。
7. 容差 1 pt 是我定的，不是对方的判据。
