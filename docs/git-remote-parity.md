# 双远端一致性规范（origin / Gitee）

> 2026-11-27 机主令：本仓 `main` 同时写 `origin`（GitHub）与 `gitee`（Gitee），两边必须逐 sha 同源；不允许再出现一边已推送、另一边落后或分叉却按“完成”收尾。

## 1. 判定

一次“推送 / 收尾 / 完成”只有一个硬判据：

```text
local HEAD == origin/main == gitee/main
```

- 三个 sha 逐位相等，才算同步。
- 任一边 `behind`（远端有本地没有的提交）、`ahead`（本地有该远端没有的提交）、`diverged`（两边各有独有提交）都不算完成。
- 远端分支缺失、remote 未配置、网络不可达、对象补不齐，都不得记绿。

## 2. 唯一收尾出口

```bash
node scripts/git-push-converge.mjs --branch main
```

该器默认自动纳入本仓已配置的 `origin` 与 `gitee`，逐仓推送/核验，最后调用 `check-remote-parity.mjs` 做三方逐 sha 复核；任何一边不一致即 exit 1。

推送前还必须对全部远端做只读预检：任一边 `UNREACHABLE` / `BEHIND` / `DIVERGED` 时，本轮**一枚远端都不推**；推送中途失败立即停止，不再推剩余远端。这样不会出现“origin 推成功、gitee 失败”或反过来的单腿现场。

等价入口：

```bash
pnpm push:safe
pnpm sync:push
```

`sync:push` 先走 `git-sync-converge` 处理 GitHub 并发推进，再补跑 `git-push-converge` 覆盖 Gitee。

## 3. 只读复核

```bash
node scripts/check-remote-parity.mjs --branch main
```

退出码：

- `0`：三边逐 sha 相等。
- `1`：至少一边不一致（behind / ahead / diverged / 分支缺失 / remote 未配置）。
- `2`：未判定（网络不可达 / fetch 补对象失败 / 本地 HEAD 读不出）。

## 4. 出现分叉时的处置

1. 先 `git fetch origin main`、`git fetch gitee main`，取两边真 tip。
2. 用 `git merge-tree --write-tree --messages HEAD <remote>/main` 在对象层试合并；有冲突就停，禁止硬合并。
3. 无冲突才用 `git commit-tree` 造合并提交，`git update-ref` 带旧值 CAS 推进本地 `main`。
4. 再跑 `git-push-converge --branch main`，两边都推成功并复核相等后，才可宣称完成。

禁止 `git push --force` / `--force-with-lease` 作为常规收尾；禁止用 `reset --hard`、`pull --rebase` 处理分叉（本机历史事故已记录在 `AGENTS.md` §5b/§20）。

## 5. 明确禁止

- 禁止只跑 `git push origin main` 或只跑 `git push gitee main` 后宣称“已推送 / 已完成”。
- 禁止把“其中一边是 ALREADY / PUSHED”当成两边一致的证据；必须以 `check-remote-parity` 的三方 sha 为准。
- 禁止跳过 `check-remote-parity` 后口头报完成；若门禁不可用，必须明确报“未判定”，不得报绿。
- 禁止在一边落后时继续叠加新提交；先收敛两边，再继续。

## 6. 门禁接线

| 入口 | 作用 |
| --- | --- |
| `scripts/git-push-converge.mjs` | 推送后强制调用 `check-remote-parity`，不一致 exit 1 |
| `scripts/check-remote-parity.mjs` | 三方逐 sha 同源判据，支持 `--self-test` |
| `scripts/check-push-sync.mjs` | 提交前 origin 同步兜底；失败提示已改为双远端收尾命令 |
| `scripts/guardian-runner.mjs` 门 29 | 提交前提示双远端口径，禁止单腿 push |

## 7. 事故留痕

2026-11-27：站内消息三端详情提交先只推 Gitee，GitHub 因远端并发新提交被非快进拒绝；随后逐轮 fetch + 对象层合并 + 双推才收口。机主据此下令“彻底根治、杜绝、规范写清”，本文件与上述门禁即该令的落地。
