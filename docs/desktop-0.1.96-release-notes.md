# 桌面端 0.1.96 发版说明与回滚方案

- 版本：0.1.96（desktop-v0.1.96）
- 基线：origin/main（发版提交 `542e06e1`，含补丁提交 `38260195`）
- 关联问题：桌面端首屏「桌面桥版本不匹配（native ? / web 协议 1）：Command get_native_bridge_manifest not allowed by ACL。桌面入口已禁用，请更新桌面端。」

## 现象

智汇AI 桌面端 0.1.95 打开即出现暗红提示条，所有依赖本机能力的入口（托盘、画中画、窗口状态、文件、截图、键鼠）整体禁用；聊天与账号功能正常。

## 根因

Tauri 2 的命令 ACL 是三处登记缺一即失效：

1. `src/lib.rs` 的 `invoke_handler` 注册命令本体；
2. `src-tauri/build.rs` 的 `AppManifest::commands` 命令表 —— tauri-build 据此生成 `allow-<命令>` 权限条目与 `permissions/autogenerated/*.toml`；
3. `src-tauri/capabilities/default.json` 的 `allow-*` 白名单 —— 远程页（https://aizhs.top、https://www.aizhs.top）真正被授权的面。

`get_native_bridge_manifest` 这条 L07 桥握手新命令最初只做了 1 和 3（甚至只做了 1），漏了 2 ⇒ 生成的 ACL 清单里没有 `allow-get-native-bridge-manifest` ⇒ 远程页调用被拒（`not allowed by ACL`）⇒ web 端读不到 native 版本（显示 `native ?`）⇒ 判定协议不匹配 ⇒ `nativeBridgeFeaturesEnabled=false`，桌面入口整体禁用。

另有一个放大因素：修复代码合入后**版本号仍是 0.1.95**，更新器认为已是最新，已安装客户端永远拿不到修复 —— 这就是「源码已修、生产仍报错」的原因。

## 改动

提交 `38260195`：

- `apps/desktop/src-tauri/build.rs`：命令表补 5 条 `query_notification_permission`、`set_sleep_prevention`、`update_v2_sync_autostart`、`update_v2_stage`、`update_v2_restart`（`get_native_bridge_manifest` 已由 `d49975df` 登记）。
- `apps/desktop/src-tauri/capabilities/default.json`：同批补 5 条 `allow-*`，与 `native_bridge.rs` 的 `BRIDGE_COMMANDS` 对齐。
- `gen/schemas/*`、`permissions/autogenerated/*.toml`：按 tauri-build 重新生成。
- `tauri.conf.json`、`apps/desktop/package.json`：版本 0.1.95 → 0.1.96。

提交 `542e06e1`（CI 修复）：

- `scripts/desktop-cli-bundle.mjs`：构建 CLI 内置产物前检测 8 个 `@ihui/*` 包的 `dist/index.js`，缺失就整闭包 `turbo run build` 一次再继续。
- `.github/workflows/release-desktop.yml`：macOS/Linux 补 setup-node + pnpm install；“Install beforeBuildCommand deps”从 `--filter ihui-ai` 改为全量 `pnpm install --frozen-lockfile`。

> 背景：0.1.94 的 CI 三平台全部失败在 `beforeBuildCommand` 的 `Could not resolve "@ihui/api-client"` —— CI 是“纯 Rust 化”形态，不跑 packages build。不修这条，0.1.96 会原样复现。

## 回滚

- 版本回退：`D:\software\智汇AI\state.json` 的 `previous` 仍为 0.1.95，`versions\0.1.95` 目录保留，可直接切回；0.1.94 已被 cleanup 清除。
- 安装包回滚：重装 `智汇AI_0.1.95_x64-setup.exe`（历史 Release 资产）即可。
- 代码回滚：revert `542e06e1`、`38260195` 两个提交；不要回退 `d49975df`（它还包含画中画 1/4 与 devtools 编译修复）。
- tag 回滚：删除 `desktop-v0.1.96` 远端 tag 与 Release（`gh release delete desktop-v0.1.96`），避免更新器继续指向该版本。

## 已知边界

- **未做 Authenticode**：仓库缺少 `SIGNPATH_API_TOKEN` / `SIGNPATH_ORGANIZATION_ID` / `SIGNPATH_PROJECT_SLUG` / `SIGNPATH_SIGNING_POLICY_SLUG` 四个 secret；产物已用 CI 私钥做 Tauri updater 签名（`.sig` 有效，客户端可验签更新），但 Windows 首次运行仍可能提示“未知发布者”。补齐 SignPath 凭据后应重跑一次正式签名版。
- **应急签名通道已移除**：为绕开 GitHub 托管 runner 数小时排队，曾临时注册本机 self-hosted runner + `desktop-sign-only.yml`（只把仓库 secret 注入本机 tauri CLI 签名，不落盘私钥）；发版完成后 runner 已注销、`WIN_RUNNER` 变量已删除、临时 workflow 已从 main 移除（`18fc666c`）。后续发版仍以 `release-desktop.yml` 托管 runner 为准。
- **NSIS 模板漂移已修**：`scripts/desktop-nsis-ihui-patches.json` 登记了 18 段未落补丁的 IHUI 手改（含“仅升级时检查 0.1.92 旧进程”的 `HadExistingInstall` 守卫），Tauri CLI 2.11.4 的 `--check` 现可通过。
- **本机私钥不是信任的那把**：`~/.tauri/ihui-updater.key` 内嵌公钥 `57de57e5…` 与 `tauri.conf.json` 的 `plugins.updater.pubkey`（`d67ea113…`，keynum 61799D76DD050EA4）不配对，`release-desktop-local.mjs` 会以“孤儿钥匙”拒绝出包。正式 `.sig` 只能由 CI 的 `DESKTOP_TAURI_PRIVATE_KEY` 产出。
- CI 时长参考：0.1.93 全程约 70 分钟，其中 Gitee 同步约占 43 分钟；本次若 Gitee 同步失败，`upload_failed` 非空会让 job 判红，但不影响 GitHub Release 与 latest.json（两者先落地）。
- 桌面端主窗口加载远程站点，ACL 的 remote 面（`https://aizhs.top/*`、`https://www.aizhs.top/*`）是唯一生效面；本地 origin 通道不走该白名单。

## 2026-11-26 深夜复核：签名链阻塞与 feed 回滚

- 0.1.96 的 `.sig` 由 CI 私钥签出，key id `08dbb1a2`；按 minisign 预哈希（BLAKE2b-512 + Ed25519）实测：本机私钥公钥 PASS，`tauri.conf.json` 的官方公钥（A40E05DD769D7961 / pk d67ea113…）**FAIL**，两把钥匙公钥字节不同。
- 0.1.95 客户端二进制里，`https://aizhs.top/desktop-feed.json` 端点旁内嵌的是官方公钥 A40E05DD，故现有客户端会拒绝 0.1.96 的更新包。
- 处置：生产更新清单回滚到 0.1.94（main 提交 `692c097f`）；Release `desktop-v0.1.96` 标记 prerelease、正文加阻塞警示、删除 `latest.json` 资产，仅保留 exe 与 sig 供手动安装/留档。
- 恢复自动更新：找回官方私钥（A40E05DD）重签；或统一轮换 `plugins.updater.pubkey` 为 CI 密钥并出一次手动迁移包（旧客户端无法自动升级，需手动覆盖安装）。
