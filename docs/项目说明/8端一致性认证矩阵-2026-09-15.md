  3. 新增暴露 `packages/app` 并非 Agent 客户端而是消费者 App，其 `agent-chat` 为轻量入口——修正了"8 端都是 agent 客户端"的隐含假设。

## 4. 按优先级排序的可执行补齐建议清单（Top 10）

> 每条：缺什么 / 影响 / 方案 / 量级。优先级 P0 > P1 > P2。

**P0-1　packages/app 的 agent-chat 能力澄清与补齐**
- 缺什么：`agent-chat/AgentChatScreen.tsx` 无 native `streamChat`/`AbortController`（grep 零命中），#1/#2/#5/#6/#8/#10 全缺。
- 影响：消费者 App 内 Agent 入口实质不可用 / 体验割裂，认证不达标。
- 方案：先核实是否 WebView 承载 web 聊天（若是，则继承 web parity，标 ➿）；若-native，则复用 `@ihui/api-client` 的 `streamChat` + `AgentRuntimePanel` 组件对齐 mobile-rn。
- 量级：S（若 WebView）/ L（若 native 重构）。

**P0-2　移动/小程序/扩展端统一 ChatMode 五态切换器**
- 缺什么：仅 web/cli 有 `ask/build/plan/review/spec` 完整切换；mobile-rn/miniapp-taro/extension 仅有 ask/spec 独立页，无 plan/review/build 切换。
- 影响：模式不一致导致只读/计划/审查语义在移动端丢失，agent 行为漂移。
- 方案：在 `AgentRuntimePanel` 或顶部栏加 ChatMode 选择器，复用 `packages/i18n` 的 `chatMode.*` 文案；移动端复用 web `stores/mode.ts` 的 `WorkMode` 协议。
- 量级：M×3。

**P1-3　三端（mobile-rn/miniapp-taro/extension）工具卡片与终端输出对齐 web**
- 缺什么：plan steps / 工具调用 / 终端输出渲染弱（无 `AgentTraceViewer`/`ai-terminal-dock` 等价物）。
- 影响：工具执行不可观测，用户无法审批/追踪长任务。
- 方案：抽取 web 的 `timeline-store` + 工具卡组件为 `packages/ui-react` 共享组件，三端复用。
- 量级：M×3。

**P1-4　三端断线重连与 SSEError 分级**
- 缺什么：web 有 `useAgentSSE.ts:77-88` 指数退避；cli 有 `SSEErrorSeverity`；三端仅 `AbortController` 取消，无自动重连 + 错误分级。
- 影响：弱网/服务端限流（429+`retryAfter`）下体验差、易丢消息。
- 方案：在 `@ihui/api-client` 的 `streamChat` 内统一封装 `onError` + 指数退避 + `retryAfter` 尊重，三端复用（miniapp-taro 已有 `retryAfter` 解析，可直接接）。
- 量级：M×3（核心在 api-client 封装，S 级改动三端）。

**P1-5　i18n dead-key 清债（mobile-rn/miniapp-taro/extension）**
- 缺什么：三端存在 dead-key 漂移（见 `.ihui-agent/tmp/i18n-dead-keys-2026-09-14-*.md`）。
- 影响：5 语言 parity 名义达成但实际键级不一致，翻译空洞/残留。
- 方案：跑仓库既有 `scan-*-dead-i18n-keys` 脚本，删除/回填 dead key；纳入 CI 门禁防回归。
- 量级：S（脚本化批量）。

**P2-6　移动/小程序端上下文压缩状态感知**
- 缺什么：有记忆页但无 web `compaction-status-bar.tsx` 等价压缩提示。
- 影响：长对话超窗无感知，体验断裂。
- 方案：复用 web 的 `context-compaction-api` + 状态条组件。
- 量级：S×2。

**P2-7　cli 免费额度前端提示**
- 缺什么：`usage-ledger` 有，但无面向用户的免费额度/剩余提示。
- 影响：用户不知配额耗尽，调用静默失败。
- 方案：在 REPL/ACP 状态栏加配额条（复用 `cost-ledger-api`）。
- 量级：S。

**P2-8　三端权限历史面板**
- 缺什么：仅 web 有 `permission-history-panel.tsx`；mobile-rn/miniapp-taro/extension 仅审批弹窗。
- 影响：工具审批不可审计、不可回溯。
- 方案：抽取权限历史组件为共享 UI。
- 量级：S×3。

**P2-9　packages/sdk 增加 SSEError 分级封装**
- 缺什么：`streaming.ts` 仅解析，无 `formatSSEError`/`SSEErrorSeverity` 等价物。
- 影响：多语言 SDK 调用方需各自实现错误分级。
- 方案：在 TS SDK `streaming.ts` 增加 `SSEError` 类型 + 严重度枚举，多语言同步。
- 量级：M。

**P2-10　建立 8 端一致性 CI 门禁**
- 缺什么：无自动化矩阵校验（能力探测/矩阵漂移告警）。
- 影响：本次审计为人工快照，易随迭代再次漂移。
- 方案：将本报告矩阵转为 `tests/consistency-matrix` 断言（每端关键导出/组件存在性探测），CI 失败即告警。
- 量级：M（一次性 + 持续维护）。

---

## 5. 结论

- **完全达标端**：`web`、`desktop`（复用 web）。
- **引擎领先端**：`cli`（#5/#6/#8/#10 最完整，仅 #9 弱）。
- **需重点补齐端**：`packages/app`（消费者 App，agent 能力实质缺失）、`mobile-rn`/`miniapp-taro`/`extension`（#5/#6/#8/#10 弱于 web）。
- **形态合理差异端**：`packages/sdk`（引擎层，UI 能力不适用）、`desktop`（外壳）。
- **最高杠杆动作**：P0-1（packages/app 澄清）+ P0-2（三端 ChatMode）+ P1-4（统一 SSEError/重连封装于 `@ihui/api-client`）+ P1-5（i18n 清债），可在不重构各端的前提下显著提升一致性。
