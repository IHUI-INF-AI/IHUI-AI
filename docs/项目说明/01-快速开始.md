# IHUI-AI 快速开始

> 本文档帮助你在 10 分钟内完成本地开发环境搭建并启动全栈服务。
> 完整开发指南请参见 [docs/DEVELOPMENT.md](../DEVELOPMENT.md)。

---

## 1. 环境要求

| 工具 | 版本 | 说明 |
|---|---|---|
| Node.js | ≥ 20.10.0（LTS 20.x） | 全端 JS 运行时 |
| pnpm | ≥ 9.0.0（项目固定 9.15.0） | `corepack enable` 激活 |
| Python | 3.12+ | 仅 `apps/ai-service` 需要 |
| uv | 最新 | Python 包管理（`pip install uv` 或官方安装脚本） |
| Docker + Compose | ≥ 24 / v2 | 拉起 db / redis / 监控栈 |
| Git | 2.40+ | `core.autocrlf=false`，项目强制 LF |
| PostgreSQL | 15+ | 可本地安装或用 Docker |
| Redis | 7+ | 可本地安装或用 Docker |

### 验证安装

```bash
node --version   # v20.x+
pnpm --version   # 9.x
python --version # 3.12+
docker --version # 24+
```

---

## 2. 克隆与安装

```bash
# 1. 克隆仓库
git clone <repo-url> IHUI-AI && cd IHUI-AI

# 2. 激活 pnpm
corepack enable
corepack prepare pnpm@9.15.0 --activate

# 3. 安装 JS 依赖（workspace 联动）
pnpm install

# 4. 安装 Python 依赖（仅 AI 服务）
cd apps/ai-service
uv sync
cd ../..
```

---

## 3. 配置环境变量

项目有 4 个 `.env.example`，复制为 `.env` 后填入实际值：

```bash
# 根目录（全链路编排）
cp .env.example .env

# 后端 API（可选，独立测试时用）
cp apps/api/.env.example apps/api/.env

# 前端 Web（可选）
cp apps/web/.env.example apps/web/.env

# AI 服务（可选）
cp apps/ai-service/.env.example apps/ai-service/.env
```

### 必填关键变量（根 `.env`）

| 变量 | 示例值 | 说明 |
|---|---|---|
| `DOMAIN` | `localhost` | 站点域名 |
| `WEB_PORT` | `8801` | Web 端口 |
| `API_PORT` | `8802` | API 端口 |
| `AI_SERVICE_PORT` | `8803` | AI 服务端口 |
| `DATABASE_URL` | `postgresql://ihui:***@localhost:5432/ihui_dev` | DB 连接串 |
| `REDIS_URL` | `redis://localhost:6379` | Redis 连接串 |
| `JWT_SECRET` | 强随机 ≥ 32 字符 | `openssl rand -hex 32` 生成 |
| `CREDENTIALS_ENCRYPTION_KEY` | 强随机 ≥ 32 字符 | 凭证加密密钥 |
| `CORS_ORIGIN` | `http://localhost:8801` | CORS 允许来源 |

### AI Provider（至少配置一个，否则降级 stub 模式）

```bash
# 默认：StepFun
STEPFUN_API_KEY=your-key
STEPFUN_API_BASE=https://api.stepfun.com/step_plan/v1

# 备用：Agnes AI
AGNES_API_KEY=your-key
AGNES_API_BASE=https://apihub.agnes-ai.com/v1
```

> 全部为空时 AI 服务降级 stub 模式，**不可用于生产**。

## 4. 启动数据库与 Redis

### 方式一：Docker（推荐）

```bash
# 仅启动 db + redis
docker compose up -d db redis

# 验证健康状态
docker compose ps
```

### 方式二：本地安装

确保 PostgreSQL 18+ 和 Redis 7+ 已启动，并创建数据库：

```sql
-- PostgreSQL
CREATE DATABASE ihui_dev;
CREATE EXTENSION IF NOT EXISTS vector;  -- pgvector
```

```bash
# Redis 默认无密码，生产环境务必配置 REDIS_PASSWORD
```

### 应用迁移

```bash
# Docker 方式（compose 中 migrate 服务自动执行）
docker compose up -d migrate

# 手动方式（本地 Node + pnpm）
pnpm --filter @ihui/database db:migrate
pnpm --filter @ihui/database db:check
```

## 5. 启动全栈服务

### 方式一：一键启动（推荐）

```bash
pnpm dev
# 或
./start-all.bat  # Windows(零窗口:只唤醒 session 0 的守护任务,不本地派生任何进程)
```

> `start-all.bat` 只做一件事:`schtasks /Run /TN IHUI-DevStack`。该守护以 **LogonType=S4U** 注册,
> 跑在没有桌面的 session 0 —— 它的整棵进程树(含 tsx / uvicorn / pnpm 内部那些我们改不到的 spawn)
> 结构性无法在你的屏幕上产生窗口。自愈节奏不变(每 30s 体检,挂了立刻重拉),幂等:服务已在跑则空操作。
> 装/修这个任务:`pnpm dev:stack:autostart`(换机器或仓库移动后跑一次)
> 停止:`pnpm dev:safe:stop` · 体检:`pnpm dev:stack:check` · 日志:`.tmp-sync/dev-stack-*.log`

### 方式二：分端启动

```bash
# 终端 1：前端（Next.js）
pnpm --filter @ihui/web dev
# → http://localhost:8801

# 终端 2：后端 API（Fastify）
pnpm --filter @ihui/api dev
# → http://localhost:8802

# 终端 3：AI 服务（FastAPI）
cd apps/ai-service
uv run uvicorn app.main:app --port 8803
# → http://localhost:8803
```

### 方式三：Docker 全栈

```bash
docker compose up -d
# 启动 api + web + ai-service + db + redis + migrate + 监控栈
```

## 7. 常见问题

| 问题 | 解决方法 |
|---|---|
| `corepack` 命令不存在 | Node 16+ 自带 corepack；低版本需 `npm i -g corepack` |
| pnpm 版本不一致 | 运行 `corepack prepare pnpm@9.15.0 --activate` |
| 端口被占用 | `taskkill /PID <pid> /F`（Windows）或 `lsof -i :8802`（Linux）查找占用 |
| DB 连接失败 | 确认 `DATABASE_URL` 中 host/port/user/password 正确，PostgreSQL 已启动 |
| AI 服务无响应 | 检查 `AI_SERVICE_URL` 是否正确，Python 依赖是否安装完整（`uv sync`） |
| Windows 路径问题 | 项目强制 LF，确保 Git 配置 `git config --global core.autocrlf false` |
