# 台账登记格式结构化设计（侧车权威 + 行内投影）

- 日期：2026-10-22　起草：Qoder 席（IHUI-AI）
- 决策人：机主（2026-10-22 批准：成功标准=人机两侧都要、分两步走；强制时机=立即强制所有席位；方案=C）
- 影响面：`PROJECT_PLAN.md`（唯一任务台账）、`scripts/lib/plan-task-index.mjs`、`scripts/live-doc-edit.mjs`、`scripts/plan-tasks.mjs`、`scripts/check-task-claims.mjs`(门 109)、`scripts/plan-tasks.mjs --gate`(门 130)、`scripts/union-converge.mjs`、`scripts/merge-live-doc.mjs`、`scripts/check-plan-line-loss.mjs`(门 71)、新增一件守门

## 0. 立因与现状读数（HEAD `ae71232df9`，2026-10-22 现读）

| 读数 | 值 | 意义 |
| --- | --- | --- |
| 未勾登记行 | 237 | 台账主体 |
| 其中正文含 `归属:` | 61 | 归属信息目前**只存在于散文里** |
| 其中含 `等环境/等拍板/需真机…` 类词 | 33 | 等待条件同样只在散文里 |
| 其中含「不可执行」 | 1 | **现有判据无任何模式命中它** ⇒ 被读成"现在可做" |
| >400 字的长行 | 91 | 今早已压 161 枚、再压 3 枚后剩下的量 |

事故经过（本设计要防的那一类，不是假想）：同日把 161 枚长行按 §1 压到 ≤400 字，切掉了行内的"归属:…"句子，派单口径当场 48 → 100（owned-elsewhere 34 枚 + waiting-env 12 枚 + waiting-human 6 枚被读成"现在可做"），而门 71/109/130/203/229/234 **全绿**。账面可以错一倍而守门不吵——这就是"判据吃自由文本"的代价。

## 1. 权威源：侧车必须进仓

- 落点 **`scripts/data/plan-fields.jsonl`**（tracked，JSONL，行级 append，按主键去重）。
- **不放 `.ihui-agent/state/`**：那里是 gitignored 留痕面，A 席写的字段 B 席看不见 ⇒ 判定随席位漂，违反 §0.1「数字一律现读」与 §0.6 单一真相源。既有"行内注记会被归并洗掉 ⇒ 留痕出仓"的经验只适用于**留痕**，不适用于**判据输入**。
- 记录形态（键复用 `compositeKeyOf`，零复算）：

```json
{ "key": "G-123#标题前24字", "owner": "union-converge 落地闸持有人",
  "waiting": "none|human|env", "blocking": "等容器运行时", "next": "补 avatar-spec 三端接入",
  "evidence": ["node scripts/x.mjs --flag"], "reviewBy": "2026-12-31",
  "updatedAt": "…", "updatedBy": "席位短名" }
```

- 不变量：**侧车只增不删**。要删记录 = 走器物并同步把旧行逐字写进既有 `plan-row-drop.jsonl`（沿用已验的抗回潮杠杆）。
- 无主键行用 `"T:" + 行文本 trim 的 sha1` 兜底键。**但兜底键只用于投影与守恒断言，不得作为归属权威**：这类行仍走 `prose` 桶并报名——因为行本体重写一次，`T:` 键就换一个人，侧车会留下孤儿记录（孤儿计数由新门报数，不判红）。

## 2. 判据：先侧车、再散文、且自报靠什么判

`dispositionOf(line)` 保留为兼容出口，新增 `dispositionOfV2({ line, fields })` 返回 `{ bucket, source: 'fields'|'prose'|'none', conflict, undetermined }`：

1. 侧车命中 ⇒ `bucket` 直接给，`source='fields'`（权威）。
2. 侧车缺 ⇒ 回落现有四桶正则，`source='prose'` **并计数报名**：`派单面仍靠散文判定 N 枚` —— 这个数字就是迁移进度尺。
3. 两侧矛盾 ⇒ 以侧车为准、`conflict=true`，由新守门按差值棘轮拦**新增**（存量只报数，§12e）。
   `conflict` 的准确定义（实现时纠正了本条第一版）：**只有散文自己表了态**（判出非 `actionable` 桶）且与侧车不一致才为真。
   `actionable` 是散文的兜底值，等于"没说"；拿它当一侧去比，会让每一次正常迁移都被门喊成冲突——门一吵就会被当噪声跳过，正是 §12e 记过最多次的那一型。
4. 词族补洞：`不可执行｜排后` 已收进 waiting-env 交替项。**补洞前先量两个数**（2026-10-22 现读，未勾行）：
   词面命中 `不可执行`=1、`排后`=1、`等静默窗口`=0（⇒ 该词**不加**）；
   而**因补洞改判的行数 = 0**（那两行本就带"归属:"标记，早已判非可做）。
   即：这一条是把散文判据修正确，不是改账面；交付与提交信息都必须引用"改判 0 枚"这个现读数，而不是含糊说"只影响两行"。

**刻意不做**：认领租约 `（进行中@日期/持有者）` 继续留在行文本。理由：门 109 的 CL1–CL4 棘轮锚点就是行文本多重集，且租约必须让并发席位一眼看见；搬进侧车等于同时改十条逐字节判据的输入面。

**把已立却没牙的规矩做成器物**：`assertRowRewriteConservation(旧行, 新行, 旧字段, 新字段)` 单源一份（新 `scripts/lib/plan-row-conservation.mjs`），返回违规列表；`live-doc-edit`、`strip-stale-*`、`scrub-declared-removals`、压缩类器物一律 import 它，禁止各写一份。断言三件：主键不漂（`keyOfRow`）、租约形态不变（`claimMarkOf`）、归属桶不变（`dispositionOfV2`）；任一不成立 ⇒ 拒写/拒落，**不许"先落了再补"**。

## 3. 强制点：写盘闸 + 提交门，只咬新写的人

- **写盘闸**（`live-doc-edit.mjs`，新 env `LIVE_FIELDS_FILE`）：新增或改写未勾行必须同批给侧车记录；写盘前由渲染器生成行内标头并替换已有标头 ⇒ **人不手写标头**。
- **提交链新门**（经 `gate-registry-insert.mjs` 取号，`stagedTriggers=['PROJECT_PLAN.md']`）判两件事：①本次提交新增/改写的未勾行是否侧车在位；②行内标头是否 `== renderFields(fields)` 逐字一致。档位=**差值棘轮、锚点=该文件 HEAD 自身违规数**；存量缺字段只报数。首装档位按 §0.2：存量归零前不得 blocking ⇒ 先 `warn`，存量清零后同批改 blocking。
- 人眼那半（投影）：`〔归:union-converge 落地闸持有人｜等:容器运行时〕`，固定顺序、固定分隔符、上限 48 字；`waiting='none'` 时只印 `归:`，无 owner 时印 `归:—`。渲染器与解析器同文件（`scripts/lib/plan-field-line.mjs`），**双向唯一实现**，不许第二处再拼字符串。
- 命名冲突自查：门号从 HEAD 面取；AGENTS 与 README 必须同批点名（门 89 R4）。

## 4. 存量迁移：分片、守恒、可回滚

1. **抽取**：只读器物 `scripts/plan-fields-extract.mjs --dry-run` 从 237 行抽字段进侧车（**不改行文本**）。抽不出 owner/waiting 的行**不写入侧车**（留 `prose` 桶报名），不得猜。
2. **对账**：抽取后跑 `plan-tasks.mjs --open --dispatchable`，逐条点名桶发生变化的行；非零变化 ⇒ 整批不落（抽取只许"散文说不动的东西换个地方说"）。
3. **投影**：分批（每批 ≤40 行，同 `strip-stale-closed-rows` 的批量口径）把长正文缩成"标题 + 一句现状"，同时渲染标头；每批落地走对象空间 + `LAND_CLASH_SCOPE` 逐行声明，落地后拿**落地枚与其父**做逐行差分自证"只删不吞"。
4. **防回潮**：每批旧行逐字进 `plan-row-drop.jsonl`，由 `scrub-declared-removals` 挡滞后副本带回长版。
5. **不做**：不重写 2.4 万行、不做全量一次性切换、不引入新 DSL 解析器。

## 6. 测试策略（先写测试，后写实现）

- 每件器物/判据先落**失败用例**再实现；实现后做**变异自证**：把该判据摘掉，对应用例必须翻红（本轮已两次靠这条抓到假绿）。
- 侧车解析器：正反配对——有字段/无字段/字段与散文矛盾/兜底键/超 48 字标头/含 `｜` 的 owner 名。
- 投影：`render → parse → render` 幂等；`parse(render(x)) == x` 逐字段。
- 守恒断言：给"删掉归属句"的改动必须被拒；给"只缩短正文而不动判据"的改动必须放行（否则尺子无牙或过牙）。
- 迁移器：每批三条硬断言——行数不变 ∧ 射程外逐字节零漂移 ∧ `dispositionOfV2` 桶零变化，任一不过整批不落。
- 镜像测试按 §22c：只 import 源脚本 `__test__`，禁止在测试里复算判据。

## 7. 失败方向与回滚

- 取不到侧车 ⇒ **未判定**，不得当成"没有归属"（§0.3）；侧车 JSON 坏行 ⇒ 计数报名并 exit 2，零行不动。
- 新门一律"多要一次定向说明"，绝不"多放一次跳门"（§0.10）。
- 回滚顺序：`plan-fields.jsonl` 是纯新增件 ⇒ 回滚 = 撤门 + 删侧车文件，台账行文本无需还原；行内标头由渲染器生成，撤门后旧行照读（投影是可选外观，不是解析前提）。这条是刻意留的：**任何一步失败都不能让台账读不出来**。

## 8. 分期与验收

- **P1（判定与侧车，不碰存量行文本）**：`plan-field-line` / `plan-row-conservation` / 侧车抽取器 / `dispositionOfV2` / 新门 warn 档 / AGENTS 三处改。
  验收：`node scripts/plan-fields-extract.mjs --check` RC=0 且桶变化 0 枚；`node scripts/plan-tasks.mjs --open --dispatchable --exclude-inflight` 首行与抽取前逐字相同；新门 `--self-test` 与镜像全绿；门 89 `--strict` RC=0。
- **P2（强制与投影）**：写盘闸改造 + 新门升 blocking（前置=存量缺字段清零）+ 长行分批投影。
  验收：新增未勾行若缺侧车 ⇒ 写盘与提交两层都拦；`>400 字长行` 现读下降且门 234/109/130/203/229/71 全 RC=0；派单口径无不明增长（每批附前后两行读数）。

## 9. 明确不做

租约不搬进侧车；不做全量重写；不加"台账 DSL 解析器"；不给单端/单条补数字消账；不把只读尺子接进提交链（§12e）。
