# 取证与 QA 口径固化（L16）

本文件是「结论怎么写才算数」的唯一口径。任何对标结论、缺陷单、复盘，都按这里说的三档标注与挂账规则写；与本文件冲突的写法，以本文件为准。

## 一、三档证据强度（只准用这三档 + 未知）

**产品级闭环**——必须同时满足：有模型输出的原文片段、有对应的账本记录、能按账本里的命令复现同一条输出。三者缺一，降档。

**产品级静态 / 实跑**——源码、二进制、进程、端口、状态码、受控实测任一可直接观察的证据。能指着具体文件或具体进程说话，但拿不到模型原文。

**框架运行态**——只能看到进程、端口、日志、HTTP 状态码这一层，看不到业务语义。

**未知**——取不到上述任何一档。写“未知”，不写“大概”“应该是”。

禁止自造档位（如“准闭环”“基本确认”）。降档要写清降档理由，例如“只拿到 202，属框架运行态”。

## 二、四条硬规矩

第一条，**202 / 401 / refusal 不得写成闭环**。202 是受理不是完成；401 是鉴权失败不是能力缺失；refusal 是模型拒答不是产品不支持。这三类只能进“框架运行态”或“反例”，且必须在结论里点名它是哪一类。

第二条，**phase 状态机快照与模型输出分离**。快照只证明“当时界面/状态是什么样”，不得拿来当“模型说了什么”。两者同篇出现时必须分节，快照段落注明采集时间与文件名，模型输出段落必须引用原文片段而不是转述。

第三条，**每条结论挂可复核账本路径**。路径必须指向仓内已跟踪文件（`docs/benchmark-evidence/YYYY-MM/…`），不得指向本机临时目录（`analysis/` 之类不入库的目录只可作为过程稿，不能作为结论依据）。账本里要能读到：采集时间、执行命令、原始输出片段、判定档位。

第四条，**同一结论只留一条主账**。多处引用时写指针，不复制正文。复制正文的后果是两边漂移后无法判定哪条为准。

## 三、结论条目模板

```
结论：<一句话，可证伪>
档位：产品级闭环 | 产品级静态/实跑 | 框架运行态 | 未知
账本：docs/benchmark-evidence/2026-11/<file>.md#<anchor>
命令：<可复制的复核命令，或“无（纯静态源码取证）”>
原文：<模型输出原文片段 / 源码行号 / 状态码；按档位给对应证据>
反例：<若本条来自纠正，写明原结论错在哪>
采集：<YYYY-MM-DD HH:mm> by <席位>
```

## 四、复核流程

任何人要推翻一条结论，必须给出：新证据的档位、账本路径、可复现命令。只给观点不给证据的，不进入复核队列。

复核用到的机器判定入口：`node scripts/check-plan-row-length.mjs`（行宽）、`node scripts/check-plan-fields.mjs`（交代完整性）、`node scripts/check-plan-line-loss.mjs`（历史行零丢失）。口径类问题走本文件，机器类问题走对应门。

## 五、本轮的纠正账

本轮（2026-11-26）共纠正 47 处口径问题，逐条记录在 `docs/benchmark-evidence/2026-11/report-qa-2026-11-26.json`，字段含 `id / original / corrected / tier / ledger`。引用纠正结论时，账本指针指向该 JSON 的具体 id，不重述全文。
