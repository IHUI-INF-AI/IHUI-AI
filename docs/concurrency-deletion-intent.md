# 并发环境下的「删除意图」纪律

> 本文是 AGENTS.md「worktree/索引自愈」条款的**完整展开**。AGENTS.md 有 96,000 字节硬预算
> (按上下文注入比例实测推出,见 `scripts/check-agents-doc-size.mjs` 头注),只放结论;
> 事故实证、判据细节、验证方法全在这里。
>
> 定案时间:2026-11-04。触发事故:一次 85 件「零引用/迁移残留」清理,每轮被自愈器拉回。

---

## 1. 一句话结论

**在多席位共享工作树的仓里,"删除一个 tracked 文件"有两件事必须同时做到:**
① 让它别被自愈器复活(写**删除意图通知书**);
② 让它别被别的席位 `git add` 收编回来(过**提交侧两道闸**)。

只做 ① 不够 —— 2026-11-04 实测:通知书写好了,文件仍然被提交带回来了。

---

## 2. 事故链条(为什么需要这么多层)

### 2.1 第一环:healer 无条件复活

`scripts/heal-worktree-tracked.mjs` 每 2–6 分钟跑一轮,判据是三条同时成立:

```
工作树缺该路径  ∧  索引 blob == HEAD blob  ∧  HEAD 有该路径
```

这三条在两种成因上**同形**:

- ① 会话有意 `rm` 掉一个 tracked 文件(还没 `git rm`,索引仍记着它);
- ② 宿主清理层批量误删。

于是 healer 一律 `git restore --source=HEAD --worktree` 复活。后果:一次 24 件清理,每轮被拉回;
只能靠**对象空间提交**(`commit-tree` 直推)绕过工作树才落地。

同类事故 2026-09-24 已发生过一次(`heal-worktree-tracked.mjs` 老注释:"差点咬掉并发会话正在
收口的 4 个分类栏文件")。当时的解法是给**漂移层**加 mtime 窗口 —— 但"文件已被删"这一型
**结构上够不到** mtime 判据(`stat` 抛 `ENOENT`,没有 mtime 可读)。

### 2.2 第二环:TTL 反悔口

暂存删除意图账(`lib/staged-delete-intent.mjs`)会给"人主动暂存删除、标记却被 reset 摘掉"
留一条 `report-only` 证据,默认 TTL 2 小时。旧行为是**超 TTL 就 `safe.push`** —— 等于
"等 2 小时再替你删一次",重启了同一起事故。

2026-11-04 改判:`report-only` 是**证据**,不是过期作废的许可证。超 TTL 也只报数、
不回盘(`intentExpired` 桶现为纯报数档)。

### 2.3 第三环:提交侧收编(最隐蔽)

修好 ① ② 之后仍发生了:

```
8331e5460a  feat(attribution): 行级归因
  └─ 父提交正是修好 healer 的 54feeb4011
  └─ 却把 105a55a40c 删掉的 3 件 download/[platform] 未用副本当「新增」提交回来
```

**成因**:healer 在并发席位的工作树里早已把 3 件 restore 回去 → 该席位的 `git add -A`
把它们收编成"新文件" → 提交面看起来完全正常。
**healer 的通知书闸只管「恢复」,结构上够不到 `git add`。**

发现方式:`git log` 遍历 `105a55a40c..origin/main` 所有提交的 `A` 项,交叉比对
「在 `105a55a40c^` 存在 ∧ 在 `105a55a40c` 不存在」的路径 ⇒ 精确命中 3 件,无其他回流。

## 3. 通知书台账

**唯一真相源**:`scripts/lib/intentional-file-deletion.mjs`
**台账**:`scripts/data/intentional-file-deletions.jsonl`(入版本库 —— 换机/换克隆后同一路径
的删除仍有证据)

### 3.1 字段

| 字段 | 必填 | 约束 |
| --- | --- | --- |
| `path` | 是 | 仓库相对路径,正斜杠 |
| `reason` | 是 | **≥10 字**;不读成句就不算理由 |
| `until` | 否 | `YYYY-MM-DD`;到期自动失效,失效后恢复判据照旧(不是"登记一次永久免检") |

### 3.2 写入只走 CLI(防格式漂移)

```bash
# 登记(这是有意 rm 掉 tracked 文件的唯一正确姿势)
node scripts/heal-worktree-tracked.mjs --declare-deletion <path>... --reason "<≥10字>" [--until YYYY-MM-DD]

# 撤回(按 path 删行,其余行逐字保留、行尾顺序不变)
node scripts/heal-worktree-tracked.mjs --revoke-deletion <path>...
```

理由不足 10 字 ⇒ 打印用法并 **exit 2**。不要手改 jsonl:撤销时按行原样比对,手改会引入
`\r` 或键序漂移。

### 3.3 三态纪律

| 态 | 含义 | 调用方该怎么办 |
| --- | --- | --- |
| `absent` | 文件不存在 | 按零条目判,**并报出缺席**(不静默当空表) |
| `broken` | 文本存在但解不开 | **exit 2 / 只报不拦**,绝不放行 |
| `entries` | 过形状的条目 | 正常判据;`defective` 是被拒条目,逐条点名 |

## 4. 两道提交侧闸(同一判据,不各写一遍)

判据单源:`lib/intentional-file-deletion.mjs#judgeResurrection`

```js
judgeResurrection({ notices, addedPaths, today }) → {
  verdict: 'clean' | 'resurrected' | 'undetermined',
  hits: [{ path, entry }],
  why?: string
}
```

判据 = **本枚提交里相对 HEAD 为 `A` 的路径** ∩ 台账中**未过期**的通知书。

### 闸一:`safe-commit.mjs` Step 3b-2

- 取**本票声明面**(Step 2 刚 `add` 完,索引面就是本枚提交面);
- 命中 ⇒ 逐条点名 `reason` 与有效期 ⇒ **exit 1**。

### 闸二:`lib/pre-commit-hook.js` 0b 段 → `scripts/check-staged-resurrection.mjs`

- 取**索引面** `git diff --cached --diff-filter=A`(`--no-renames`,改名的新侧也算 `A`);
- 覆盖 `auto-commit-quiet` 的 `chore(auto)`、人工 `git commit`、各席位自拼 git 命令 ——
  **pre-commit 是唯一所有提交路径都会经过的地方**;
- 命中 ⇒ **exit 1 阻塞**;
- **刻意不设 `HUSKY_SKIP_*` 跳过键** —— 台账登记有误时唯一出路是 `--revoke-deletion`
  (§0.10:多要一次定向说明,不是多放一次回流)。

> 补充:`auto-commit-quiet` 的落地走 `safe-commit`(见其头注「落地一律走 safe-commit」),
> 所以它同时受两道闸管。

### 只拦新增,不拦修改

一个仍被别处 `import`、因而需要编辑的文件,不该被同名台账记录卡死。所以判据只认 `A` 态。

### 失效方向

| 情形 | 处置 |
| --- | --- |
| `resurrected` | **exit 1**,给两条出路(见下) |
| `undetermined`(台账坏档 / 读不到索引面) | **只报不拦**,exit 0 —— 判不出不是定罪的许可证 |
| 台账缺席 / 零条目 | 无判据,静默通过(不刷噪音) |

两条出路:

```bash
# ① 确实要把它用回来 ⇒ 撤回通知书,下一次提交即放行
node scripts/heal-worktree-tracked.mjs --revoke-deletion <path>

# ② 确认是误带进来 ⇒ 从提交里摘掉,工作树副本交给 healer 判据处置
git restore --staged -- <path>
```

## 5. 索引重置必须路径作用域

`safe-commit` Step 1 曾是 `git reset HEAD`(无 pathspec)。本仓多席位共用一个共享索引,
这一句会**清空别人的暂存**且零留痕。现存形态:

- `reset -q HEAD -- <声明集>`;**空集 ⇒ 拒绝执行并 exit 2**(不退化成全局清空 ——
  失效方向是多要一次定向说明);
- 清单超 200 条分批;载荷 >20000B 走 `--pathspec-from-file`;
- 清空前先取 `git diff --cached` 快照算 `foreignStaged = 活索引 ∖ 声明集`,
  **外来暂存原样保留并在日志逐条点名**;Step 3a 判据扣掉该快照后仍能抓真·意外件;
- 有外来件时 commit 改用**私有索引**(拷自生效索引、只摘非声明面、自证 == 声明集),
  活索引一个字节不动。

旧行为由 `auto-commit-quiet` 每 3 分钟触发一次(含失败重试),实测把并发席位的 `git add`
成批吞掉。

## 6. 自动化探针

`scripts/tests/intentional-file-deletion.test.mjs`(15 例)

| 用例 | 钉住什么 |
| --- | --- |
| T1–T5 | 三态:absent / broken / entries / defective(理由不足、`until` 非 ISO) |
| T6–T11 | `judgeResurrection` 六档:命中 / 过期不命中 / 台账外不命中 / 只认新增面 / 坏档 undetermined / 缺席 clean |
| T12 | 路径归一(反斜杠、`./`、重复斜杠)与去重 |
| T13 | 装车形状锁:断言 `safe-commit` 真调用、且不重抄台账解析 |
| **T14** | **台账 ↔ 树对账**:登记为"有意删除"的路径若仍在树里 ⇒ 红 |

**T14 是那 3 件回流的自动探针。** 基准取 `origin/main` 优先:本地 HEAD 常年落后远端,
拿落后 HEAD 对账会把"远端已删、本地还没拉到"读成回流,满屏假红后这条探针就会被当噪音关掉。

## 7. 端到端验证方法(临时仓)

在隔离仓里真跑生产 `safe-commit`,四档对照:

| 场景 | 期望 |
| --- | --- |
| A 只改别的文件,台账里有无关路径 | 放行(exit 0) |
| B 复活件被收编进提交 | **exit 1**,点名理由 + 两条出路 |
| C 撤回通知书后再提交同一件 | 放行(exit 0) |
| D 通知书 `until` 已过期 | 放行(exit 0) |

`check-staged-resurrection.mjs` 另有两档:

| 场景 | 期望 |
| --- | --- |
| 索引面新增命中台账 | exit 1 |
| `--json` | 永远 exit 0,输出 `{verdict, hits, addedCount, why}` |

## 8. 踩过的坑

### 8.1 台账建了但没回填 = 第二道防线形同虚设

第一轮建了台账文件与全套判据,但**只写了注释头、零条目**。于是通知书闸对所有存量删除
都不生效,只有旧的 TTL 机制在兜。真仓 `heal --check` 读 `intentExpired=51` 正是这个缺口的
表现 —— 那不是"修好了",是"另一条腿在撑"。回填后读 `intentDeclared=51`。

### 8.2 跨文件接口改动必须一次成对落地

改完 `safe-commit.mjs`(引用 `judgeResurrection`)、还没改 lib 的窗口里,**另一席位把工作树
那份提交上去了** ⇒ 远端 `safe-commit.mjs` 引用了一个不存在的导出 ⇒ 所有席位的 safe-commit
一 `import` 就 `SyntaxError`。

教训:并发环境里工作树随时可能被别人快照走,**中间态不能留在工作树上等"改完一起提交"**。

### 8.3 条款写进 AGENTS.md 会撞 96,000 字节预算

AGENTS.md 被客户端**逐字注入每一轮对话**,超预算会让新会话第 1 轮就被自动压缩。
2026-11-04 实测:三条长条款(共 4,180 字节)把文件从 95,590 顶到 99,770,超预算 3,770 ⇒
`check-agents-doc-size.mjs`(守门 207,blocking)当场红。

**纪律:AGENTS.md 只放结论式要点,论证与细节写进本文这种文档。** 加条款前先算字节:

```bash
node scripts/check-agents-doc-size.mjs          # 当前面
git show origin/main:AGENTS.md | wc -c          # 远端面(门默认判 HEAD,落后时会漏)
```
