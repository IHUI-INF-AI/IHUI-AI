## 〇、总结论（先看这个）

**没有做到"远超他们几年"。任何一个维度都没有。**

真实定位分三层：

| 层面 | 真实水平 | 量化判断 |
|---|---|---|
| **功能广度**（多端/多模型/垂直场景） | 局部领先于五家中的任何单一产品 | 领先幅度 = "人有我有 + 人无我有"，约 0.5~1 年的形态优势，但**不是护城河**——形态容易被抄，生态抄不了 |
| **核心深度**（coding agent 可靠性） | 落后 Codex/Cursor 约 **1~2 个产品代际**；落后 Trae/Qoder/WorkBuddy 约 **0.5~1 年** | 关键差距不在功能清单，在模型、数据飞轮、稳定性打磨 |
| **工程成熟度**（打磨/规模验证） | 落后约 1~2 年 | 单人(+AI) 项目 vs 数百人全职团队；已知问题：popover 溢出、workspace 上下文读取不全、CI secrets 悬空等收尾欠账 |

一句话：**IHUI-AI 是"一个人在一年内做出了这五家产品 2024~2025 年形态总和的功能面"，这个密度本身是五家都做不到的；但产品竞争力 = 模型 × 生态 × 稳定性，这三项都不是代码量能弥补的。** 下面逐项拆开证据。

## 一、五家竞品 2026-09 现状（检索交叉验证）

### 1. OpenAI Codex
- 模型：GPT-5.3-Codex → GPT-5.4 → GPT-5.5（2026-04-23 起默认），**自研 RL 训练的专用 agentic 模型**，SWE-Bench Pro / Terminal-Bench 2.0 行业第一，且"首个参与创建自身的模型"

## 三、逐维度差距（真实、不美化）

### 3.1 模型层：0 vs 1 的差距（最大差距，无解项）
- Codex 有 GPT-5.x-Codex（RL 训练、参与创建自身）；Cursor 有 Composer 2.5（自研、上下文遗忘率降 50%）；Trae/Qoder/CodeBuddy 背靠字节/阿里/腾讯的模型工程团队做任务分流路由。
- **IHUI-AI 是纯调用方**（18 家 provider 路由再广，本质是"别人模型的搬运工"）。补全质量、agentic 可靠性、长任务成功率的天花板由模型决定。这项差距**无法用代码弥补**，只能等开源模型追平或接入更强模型。

### 3.2 补全（Tab completion）：完全缺失
- Cursor 的 Supermaven（"近乎心灵感应"、留存第一的功能）、Trae 的 CUE、Codex 的 Tab——**日活刚需入口**。
- IHUI 的 web IDE（Monaco）与 CLI 均无 inline 补全实现。这是"编辑器形态 vs 对话形态"的分水岭：没有补全，IDE 就只是"看代码的地方"，用户每天打开的理由减半。

### 3.3 索引与上下文：有骨架，缺规模工程
- ✅ 有：tree-sitter AST + embedding 双通道、context_engine 压缩/召回/质检三层、codegraph。
- ❌ 缺：Merkle 增量同步（Cursor 5 万文件 3.2MB 增量）、团队索引复用（P99 4h→21s）、三层语义表征（CodeBuddy 函数级副作用/调用链/架构级）、Repo Wiki 持续同步（Qoder 已产品化，IHUI 有 `/repo-wiki` 路由但深度未验证）。
- ❌ 且 workspace 上下文读取不全（文件级读取缺陷）2026-09 仍隔离在网关层未修复——**自家核心上下文链路都还有未闭环 bug，谈"远超"不成立**。

### 3.4 云 Agent 与自动化：形态在，闭环弱
- ✅ 有：cloud_runs、automations、scheduler、n8n-agents、orchestration_hub。
- ❌ 缺：Cursor 的事件唤醒（订阅 PR/Slack 自动开工 + CI 自动修复推 PR）、Codex 的 Sites（app 内部署托管）、跨设备手机审批（Codex/MoveKit 已产品化，IHUI mobile 有推送但无 agent 任务审批闭环）。

### 3.5 记忆：概念全，验证零
- IHUI 的 memory_decay/meta_learner/multimodal_memory/dream_scheduler 概念上与 Codex memory（2026 预览）同频甚至更激进。
- 但 Codex 的 memory 是 300 万周活上的真实数据飞轮；IHUI 的全部记忆能力**没有可引用的线上效果数据**。按"禁空承诺"原则：概念领先 ≠ 能力领先。

### 3.6 生态：数量级差距
- Codex 90+ 插件包 / 60+ 应用集成；WorkBuddy 技能市场 100+ 技能；Trae/Qoder 有 agent/技能市场 + 开放生态。
- IHUI 有 MCP marketplace + CLI plugin market + 39 平台自媒体适配器——**自媒体是独有且真实的；但通用开发者生态（插件数、第三方接入、社区贡献）接近于零**。

### 3.7 稳定性与打磨：肉眼可见的欠账
- 对标产品每周发版、SOC 2/等保认证、企业 SLA。
- IHUI 已知未闭环：workspace 上下文 bug、CI secrets（部署从未真正成功）、桌面更新签名、popover 类 UI 打磨、build 间歇冻结（handle-probe 机制未明）。**这些不是功能差距，是"能不能被陌生人日常使用"的差距。**

### 3.8 交互与 UI 细节：广度惊人，密度不足
- 广度上 IHUI 的 agent 可观测（swarm 拓扑图、trace viewer、activity feed、usage ring）**不输甚至多于**五家（Cursor/Qoder 的面板都更克制）。
- 密度上：Cursor 的 mid-run steering、Qoder 的 Quest 独立窗 + 跨项目统一面板 + 交付清单、Codex 的浏览器内批注指挥——这类"高频交互的精雕" IHUI 均有对应物（interjection、spec-panel、内置浏览器桥）但打磨深度不足；无障碍、键盘体系、性能优化（虚拟滚动）无实证投入。
- 样式体系（design tokens 单一来源、像素级对齐 e2e 守门、双端视觉一致守门）是**超出独立项目常规水准的**，但仍是"工程整洁"维度，非"体验领先"维度。

## 四、IHUI-AI 真实的领先点（不夸大，每条可验证）

1. **多端矩阵广度**：web + 浏览器 IDE + CLI + Tauri 桌面 + RN 移动 + Taro 小程序 + 浏览器扩展 + 五语言 SDK，**没有任何一家竞品同时有这九端**（最接近的 Codex 是桌面+CLI+移动预览+JetBrains）。
2. **模型路由广度**：18 provider 含四路本地推理（Ollama/LMStudio/llama.cpp/Qwen），**开源可自托管 + 端侧本地模型全通**——五家全部闭源且 Codex 无本地部署选项（这是它官方自认的短板）。
3. **自媒体 39 平台一键发布 + 反风控体系**：垂直场景**独有能力**，五家均无。
4. **浏览器端工作区（FileSystemDirectoryHandle）**：纯浏览器内授权本地文件访问 + AI 上下文注入，无需安装——形态上五家都没有的差异化方案。
5. **MCP 协议覆盖全度**（stdio/HTTP/OAuth/aggregator/marketplace/export）。
6. **概念前瞻密度**：dream_scheduler（离线自进化）、compaction_quality（压缩自证）、metacognition、federated_learner 等——产品判断与头部同频，部分概念先于其产品化。

> 但注意：1/2/4/5/6 全部属于"**形态与概念**"维度——可被大厂在 1~2 个版本内复制；3 是唯一有真实壁垒的垂直能力。**用户量、数据飞轮、模型、生态这四项硬壁垒，IHUI 目前为 0。**

## 五、"远超几年"的最终裁定

| 维度 | 裁定 |
|---|---|
| 远超他们几年（整体） | ❌ 不成立。任何维度都未达到"超数年"——竞品在以周为单位迭代 |
| 局部形态领先 | ✅ 多端矩阵、本地模型路由、浏览器工作区、自媒体矩阵 4 项，约领先 0.5~1 年形态 |
| 概念同频 | ✅ 记忆/自进化/Spec 驱动/压缩质检等概念与 2026 头部对齐，说明产品判断不落后 |
| 核心深度落后 | ⚠️ coding agent 可靠性落后 Codex/Cursor 1~2 个代际（模型差距为主因）；落后 Trae/Qoder/WorkBuddy 0.5~1 年（团队规模与迭代频率为主因） |
| 工程成熟度落后 | ⚠️ 1~2 年（稳定性/合规/规模验证/生态） |
| 最该清醒的一条 | 五家的竞争力核心是**模型 + 数据飞轮 + 生态**，这三样 IHUI 均为 0；IHUI 的竞争力核心是**开源 + 自托管 + 多端 + 垂直场景**，这是真实但小的差异化，不足以支撑"远超"叙事 |

## 六、若要缩小差距的优先级（按投入产出排序，简列）

1. **P0 修自家核心链路**：workspace 上下文读取不全（网关层）、桌面签名/更新、CI 部署 secrets——"自家地基没封顶前不谈超车"。
2. **P1 补 Tab 补全**：接入开源补全模型（如Continue/Tabby 方案）打通 Monaco inline completion——这是 IDE 日活的最大单点。
3. **P1 索引规模化**：增量同步 + Repo Wiki 产品化闭环（已有路由，做深）。
4. **P2 评估外证**：跑一次公开基准（SWE-Bench Verified 子集）出真实数字——没有外部可比数字，一切"能力"叙事都无法对外自证。
5. **P2 打磨高频交互**：steering、审批、交付清单三件套做到 Qoder/Cursor 级顺滑。
6. **不追的项**：自研模型、computer use、云沙箱 PR 闭环——单人项目追头部基建是无底洞，不如把"开源 + 自托管 + 多端 + 自媒体"四个真实差异点做成护城河。
