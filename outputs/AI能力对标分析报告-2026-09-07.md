# IHUI-AI AI 能力对标分析报告

> 对标对象:OpenAI Codex、Cursor、字节 Trae(Solo)、阿里 Qoder、腾讯 WorkBuddy/CodeBuddy
> 基准日期:2026-09-07 · 方法:本项目源码实证盘点(apps/ai-service 396 个 Python 文件 ≈15.6 万行、58 个 router;apps/web 120+ 页面路由)+ 竞品公开资料交叉验证
> 原则:只写代码里确认到的、只下有证据的结论,不粉饰

---

## 一、结论先行(真实判断,一句话版)

**广度:本项目在"能力域覆盖数量"上超过全部 5 个对标产品的公开能力面——Agent 编排/MCP 双向/A2A/长期记忆/知识图谱/语音/评测/治理审计/成本台账,这些域很多竞品根本没有或只有雏形。**

**深度:在"核心 AI 编码闭环"上,落后 Cursor/Codex 约 2~3 年(等效工程深度),落后幅度最大的三处是:① 没有任何行内补全(Cursor Tab/Qoder NEXT 级别);② 没有自研前沿模型——完全依赖第三方模型经 LiteLLM 转发;③ IDE 级本地集成(diff 审查、LSP、编辑器内 agent)不存在——本项目是 Web 平台 + 桌面壳,不是 IDE。**

**"远超他们几年"的回答:在治理/合规/互操作/多端覆盖这几个维度,确实做到了部分竞品没有的东西(如 RBAC+审计+成本台账+prompt guard 全链路,CodeBuddy 有等保合规但无 A2A;Cursor 无企业治理细粒度);但在决定用户留存的核心编码体验上,不仅没有远超,反而是被碾压的一方。整体不是"谁领先几年"的关系,而是"错位竞争":竞品是垂直打穿的锤子,本项目是功能极全但每个功能浅一层的瑞士军刀。**

## 三、IHUI-AI 实际能力盘点(代码实证)

### 3.1 实打实有的(非占位,已抽查代码)

- **Agent 循环与编排**:`agent_loop_v2.py`(2025 行,含 plan/auto/default 三级 permission_mode、只读白名单强制、hook_engine 事件)、`agent_orchestrator.py`(1640 行)、`agent_teams.py`、`task_decomposer`、`dag_scheduler`、`orchestration_hub`、`team_orchestration` router。LangGraph 接入(checkpoint/stream/service)。
- **沙箱执行**:`sandbox.py`(729 行)真实实现 6 种后端:Local(白黑名单+超时)/Docker CLI/SSH/Modal HTTP API/Daytona/Singularity,含灾难性命令拦截(SandboxError 黑名单)。另有 `os_sandbox.py`、`exec_policy.py`、`container_runtime.py`、`cloud_run_store.py`。
- **代码库语义索引**:`codebase_indexer.py`(592 行)——tree-sitter AST 解析→按符号切片→1536 维 embedding→PG 向量检索,降级正则切片。`rag.py`(427 行)、`context_engine.py`(2014 行)、`context_recall`、`multimodal_embedder`。
- **MCP 全家桶**:client(`mcp_client`)、server(`mcp_server`)、stdio 桥、OAuth(`mcp_oauth`)、marketplace、directory、tool_aggregator(495 行)、export(把平台能力导出为 MCP server)——**双向支持这一点与 Codex 对齐,超过 Cursor(仅 client)和 Trae/Qoder**。
- **上下文管理**:`context_compaction`、`compact_with_llm`、`compaction_quality`、`token_compaction`、`session_summarizer`——压缩质量自证已有服务(按 GAP-PLAN 仍缺提交通道)。
- **记忆体系**:`long_term_memory`、`agent_longterm_memory`、`memory_decay`、`memory_extractor`、`memory_quality_eval`、`vector_memory`、`multimodal_memory`、`project_memory`、`active_forgetter`、`user_profile`——**记忆域的完整度(衰减/质量评估/主动遗忘/多模态)超过全部 5 个竞品的公开能力**。
- **PR 审查**:`pr_reviewer.py`(327 行,真调 GitHub API 拉 diff)+ `pr_review` router——存在,但深度无法与 Bugbot(自起云 agent 验证修复)比。
- **评测**:`eval_service` + `eval` router + `opencompass_scrape`(抓榜)——**有骨架,约 10 个函数量级,与竞品的 SWE-bench 榜单体系差一个数量级**。
- **前端渲染**:chat 组件含 react-markdown + KaTeX + mermaid + xterm 终端 + pdf.js;输入工具栏含模型选择器/mention/slash 命令/技能库/压缩状态条/高危审批横幅/全访问确认桥/提问对话框——agentic 交互要素齐全。
- **页面广度**:120+ 路由,含 agent-canvas/kanban/runtime/teams/workbench/step-recorder、a2a、cloud-agent、computer-use、deep-research、knowledge-graph/-rag/-base、memory-manager、mcp-store/-projects、models-pricing、spec、workflows、voice 相关等。

### 3.2 已知硬伤(有实证的缺口)

1. **workspace AI 上下文读取不全**:apps/api 网关层 file-level 根因未修(已确诊),这是"工作区感知编码"主链路上的活跃 bug——竞品对应能力是十亿级请求打磨过的索引管道。
2. **成本真网计价缺失**(GAP-PLAN 确认:需价表),`cost_ledger` 有台账无真价。
3. **自愈引擎 LLM 接入未完成**、MCP 超级工具聚合未接执行器、公网 MCP OAuth 无真网端点。
4. **桌面端 Tauri CORS `tauri.localhost` 未白名单**(待后端发版),更新器 .sig 依赖用户侧私钥。
5. 大量 120+ 页面中相当比例为半成品/占位(发布适配器 36kr/afun 等文件里有 placeholder 标记),广度泡沫明显。

## 四、逐维度差距分析(细致版)

### 4.1 核心编码闭环 —— **落后 2~3 年,最大短板**

- **行内补全:0 对 1。** Cursor Tab 日均 4 亿次请求、Qoder NEXT 用 AST 编辑轨迹训练。本项目没有任何编辑器内嵌能力——web 聊天框里贴代码不叫补全。此差距本质是"需要自研模型 + IDE 载体",工程上无法短期追。
- **IDE 集成:0。** Cursor 是 VS Code fork(扩展/键位/主题全兼容),Codex 有 VS Code/Cursor/JetBrains 扩展。本项目是独立 Web 平台,开发者必须"离开编辑器来用你",在开发者日常工作流里是致命摩擦。
- **Diff 审查体验:有但浅。** 竞品是编辑器内 chunk 级逐块接受/拒绝/回滚;本项目有 artifact-canvas 和 patch_engine,但无"光标处 inline diff + 逐 hunk 审"的体验。
- **上下文规模:中等。** codebase_indexer 架构方向对(tree-sitter+embedding),但未经过大型 monorepo(10 万文件级)实战调优;Qoder Repo Wiki/Cursor 索引在超大盘上的表现有多年数据积累。
- **后台并行 Agent:形似神不似。** 有 cloud_runs/cloud-agent/sandbox 多后端,但 Codex 靠容器缓存把中位完成时间降 90%、Cursor 8 并行+自动择优(多 agent 同任务评估选最佳)——本项目的 shadow_runner/ab_test 有影子,但无"同任务多副本自动评审择优"的成品闭环。

### 4.2 Agent 治理/安全/成本 —— **局部领先,是真实差异点**

- RBAC(`rbac.py`)、audit 中间件、input/response sanitizer、prompt_guard、command_policy.json、tool_input_scanner、llm_budget_governor、tool_budget_governor、differential_privacy、federated_learner——这套"企业级 AI 治理栈"在 Cursor/Trae/Qoder 公开能力里基本没有对位物;CodeBuddy 有等保合规但偏流程合规而非技术栈。
- 审批流(default/plan/auto 三级 + 高危横幅 + 全访问确认)与 Codex 的三档 approval 思路对齐,实现粒度(只读白名单 + hook 事件)不落后。
- 成本台账方向领先、**计价数据落后**(无真网价表)。

### 4.3 互操作(MCP/A2A) —— **广度领先**

- MCP 双向 + export(把自身变成 server 供他人调用)+ OAuth + marketplace,与 Codex 同级,超过 Cursor(仅 client)、Trae/Qoder(生态专区但非双向)。
- **A2A 协议是独有项**:5 个竞品均无公开 A2A agent-to-agent 互操作实现。`a2a_service` + router 存在,成熟度需真网验证。

### 4.4 记忆/知识域 —— **广度显著领先,深度未证**

- 记忆衰减/质量评估/主动遗忘/多模态记忆/项目记忆的组合拳,没有任何竞品公开做到这个完整度(Codex 2026-04 才出 Memory 预览,Qoder 有长效记忆系统)。
- 知识图谱(724 行)+ KG 查询 + 多模态 embedder:竞品无对位物。
- 但**未证实点**:这些服务缺少大规模真实使用数据回流(竞品的记忆系统有百万级用户反馈迭代),效果上限存疑。

### 4.5 多端覆盖 —— **广度第一**

- web/desktop(Tauri)/mobile-rn(Android 已打包 APK)/miniapp-taro/extension/cli 共 8+ 端。Codex 有 5 表面(CLI/IDE/云/桌面/手机遥控),Cursor 仅桌面 IDE。本项目 mobile 端具备但无"手机遥控 desktop agent 任务"的跨端接力(有 session_handoff 服务,成品度未证)。

### 4.6 UI/交互/样式 —— **互有胜负,总体处于下风**

- **胜**:agentic 交互要素全(slash 命令/mention/技能库/压缩状态/审批横幅/终端/画布/提问对话框);设计 tokens 单一来源 + i18n 5 语言 + 样式门禁(圆角/分割线/对齐 e2e 阈值 0.15px)工程纪律严于竞品;Markdown/KaTeX/mermaid 全。
- **负**:竞品是"编辑器即产品"——1000 万级用户打磨的键位流、Tab-Tab-Tab 肌肉记忆、Cmd+K 行内编辑、Agents Window 独立界面;本项目是"网页应用套壳",键盘效率、本地文件即时感、离线可用性(Trae 有断网本地补全)全面落后。WorkBuddy 的"在 QQ/飞书/钉钉聊天中用 AI"的贴身分发,本项目虽有 mobile/miniapp 但无 IM 原生入口。
- **样式质感**:自建组件库(packages/ui-react)无 VS Code 生态的 10 年主题/扩展沉淀,长尾体验(大文件滚动、万行列表虚拟化、多面板拖拽)必然粗糙。

### 4.7 模型硬实力 —— **最根本差距,无法用工程弥补**

- 5 个竞品中 4 个有自研/专调模型在能力前沿(Composer 2.5、GPT-5.x-Codex、NEXT、豆包 Seed Code、GLM)。本项目 = LiteLLM 转发 17 个 provider(anthropic/openai/gemini/zhipu/doubao/qwen 等,provider 文件实证),**永远是二手机型 + 转发延迟 + 无专调红利**。这是"几年"都追不上的维度,除非换赛道。

### 4.8 评测体系 —— **落后一个量级**

- 竞品:Trae SWE-bench Verified 榜一、NeurIPS Spotlight 论文、CCF-A 10+ 篇;Cursor 自建 CursorBench。本项目:eval_service 雏形 + opencompass 抓榜(是看别人的榜,不是上别人的榜)。

## 六、如果要把差距关掉,优先级排序(按杠杆率)

1. **修掉 workspace 上下文读取不全(apps/api 网关层)**——这是唯一已确诊的活跃 P0 bug,直接让"工作区编码"主卖点失效,任何对标都过不了关。
2. **成本真网计价接入**——cost_ledger 有壳无价,补价表即可闭环(自研工作量最小、可信度提升最大)。
3. **同任务多 agent 择优闭环**(对标 Cursor 多副本评估):shadow_runner/ab_test 骨架已在,补"评分→自动选优→回写"最后一公里。
4. **评测上桌**:用自家 sandbox + codebase_indexer 跑通 SWE-bench Verified 子集本地评测,哪怕 20 题,把"抓别人榜"变"自己有数"。
5. **不追的方向(明确放弃)**:行内补全、自研模型、VS Code fork——无模型训练资源与 IDE 生态,追是死路;维持"聚合平台 + 治理 + 多端 + 互操作"的错位定位才是活路。

## 七、一句话总结

**本项目在"AI 平台的能力广度、治理深度、互操作与多端覆盖"上做到了部分竞品没有的水平(A2A、记忆全链、8 端、MCP 双向导出是真实领先点);但在"AI 编码产品的核心体验——补全、IDE 内嵌、自研模型、大规模实证"上,与 Cursor/Codex 的差距是结构性的 2~3 年,且其中模型与补全两个维度靠工程手段永远追不平。诚实的定位是:不是"远超他们几年",而是"在竞品没打的侧翼领先,在正面战场落后"。**
