# IHUI-AI AI 能力对标报告：vs Codex / Cursor / Trae / Qoder / WorkBuddy

> 日期：2026-09-07 · 方法：仓库代码逐模块实证（ai-service 11.4 万行 + web + api + cli + 多端）+ 对标产品 2026 年 6-9 月公开资料交叉验证
> 原则：只写有文件证据或公开可查证的事实，不做印象分。

---

## 一、结论先行（真实回答"有没有远超他们几年"）

**没有。结论是：广度上部分维度领先，深度上落后 1~2 年，"远超几年"不成立。**

| 维度 | 真实评估 |
|---|---|
| 广度（端覆盖/功能面） | **领先**。8 端（web/desktop/cli/mobile/miniapp/extension/api/ai-service）+ MCP 双端 + 成本治理，功能面比任何单一竞品都宽 |
| 深度（模型/索引/沙箱/评测） | **落后**。无自研编码模型、无 Tab 补全、代码索引未经验证、无云端并行沙箱、无公开评测成绩 |
| 细致度（UI/交互打磨） | **互有胜负**。内置浏览器和 agent 可视化是亮点；编辑器级体验、对话分支、公式渲染是硬缺口 |
| 根本性差距 | 竞品有**为编码专门训练的前沿模型**（Composer 2.5 / GPT-5.5-Codex / Claude Opus 4.8），本项目依赖第三方 API 模型，这一层差距不是工程能追平的 |

## 二、本项目已实证的真实能力清单（不是规划，是代码里存在的）

### ai-service（apps/ai-service）
- **Agent 循环**：`agent_loop_v2.py` 多步工具循环（max_iterations=10，default/plan/auto 三权限）；`agent_graph.py` LangGraph plan→execute→summarize；`agent_teams.py` 多 agent 并行 fan-out + merge/best_of/consensus 聚合
- **MCP**：client + server 双端（`mcp_client.py`/`mcp_server.py`/`mcp_official.py`），stdio/sse/streamable-http 三 transport，OAuth（`mcp_oauth.py`，RFC 8414），市场 `mcp_marketplace.py`，跨 server 超级工具聚合 `mcp_tool_aggregator.py`
- **RAG/索引/KG**：`codebase_indexer.py`（tree-sitter AST 切片 → 1536 维 embedding）；`rag.py`（retrieve→rerank→generate）；`knowledge_graph.py`（LLM-NER 实体/关系）
- **记忆/压缩**：`long_term_memory.py` 跨会话记忆；`token_compaction.py`/`compact_with_llm.py`/`compaction_quality.py`（压缩质量自证：事实保留率+语义 cosine）
- **治理**：`llm_budget_governor.py` 预算门控/降级、`cost_ledger.py` 成本账本、`self_healing.py` 自愈引擎、`prompt_guard`/`tool_input_scanner`/`network_guard`/`rbac` —— **GAP-PLAN 里"可选增强未完成"的记录已过时，这些都已落地**
- **模型层**：22 个 provider，ModelSyncService 6 小时同步 999 条模型，LiteLLM 网关
- **流式**：SSE + 5 分钟事件重放缓冲（`routers/agents.py`）、Socket.IO 兼容层

### web 端（apps/web）
- **内置浏览器**（本仓库最硬的单点能力）：`work-panel/web-work-panel.tsx` + `cdp-browser-view.tsx`，embed-proxy 同源代理（剥 XFO/CSP）→ CDP WebSocket 截帧交互（鼠标/键盘/F12/1:1 视口）→ 截图 → 外部打开四级降级链。**对标产品中只有 Codex 的 in-app browser 和 Trae Solo 的浏览器预览可比**
- **Agent UI**：agent 市场/创建/编排（`agent-canvas`/`agent-kanban`/`agent-teams`/`subagents` 含 DAG 图/Swarm 拓扑视图）、工具调用卡片可视化
- **输入工具栏**：斜杠命令、@ 文件引用、提示词模板/Skill 库/插件市场/深度研究/上下文压缩、999 模型选择器（含积分倍数）、语音输入、上下文用量环、权限模式切换
- **工作区**：FileSystemDirectoryHandle 本地文件夹、文件树、workspace_context 注入、权限对话框
- **其他**：Ctrl+K 命令面板、5 语言 i18n、安全中心（2FA/登录历史/IP 白名单/会话管理）、admin 后台（ai-cost/ai-gc/ai-metrics）

### 多端与基础设施
- **CLI**（apps/cli）：对标 Claude Code/Codex CLI 的终端 agent，tui/subagent/tools/sandbox/plan/checkpoints/skills/memory/voice 完整模块
- **extension**：WXT 浏览器扩展，12 个 BrowserControlAction（`agent-control.ts`），是 web agent 的浏览器控制执行端
- **benchmarks/**：20 个真实编码任务（bug 修复/多文件重构/写测试，各带 verify.mjs），验收线 ≥80% —— 有 eval 体系，但没有公开成绩
- **packages/sdk**：105 个 /v1 端点封装，TS/Go/Python/Java 四语言

## 三、逐产品差距分析

### vs OpenAI Codex（2026 年状态：GPT-5.5-Codex，SWE-Bench Pro/Terminal-Bench 2.x 领先者）

| Codex 有、本项目没有/弱 | 差距定性 |
|---|---|
| **云端并行 worktree 沙箱**：每个任务独立隔离容器克隆仓库、agent 阶段断网防泄露、可同时跑 N 个互不干扰 | **P0 硬差距**。本项目的 `container_runtime.py` Docker 可用才隔离、否则本地回退，且无 git worktree 级并行任务体系；`agent_teams.py` 是同进程 fan-out，不是隔离沙箱并行 |
| **PR 评审闭环**：@codex 触发 PR review、CI 失败自动诊断修复、GitHub triggers 驱动循环 | **P0**。本项目无 GitHub PR/CI 集成层 |
| **自研编码模型** GPT-5.5-Codex 专门为 agentic coding 训练 | **不可追赶（模型层）** |
| Scheduled tasks / Automations / 移动端遥控 | 部分追平（mobile-rn 有 AgentRuntimePanel，但无 scheduled/automation 产品面） |
| Skills + Profiles + Computer Use（Mac/Windows） | 本项目无 computer use |

**本项目反而领先的点**：MCP 生态完整度（双端+OAuth+市场+聚合）强于 Codex 的"MCP server 集成"；内置浏览器交互深度（CDP 实时操作+F12）强于 Codex 的文档浏览级 in-app browser；模型自由度（999 模型 vs Codex 锁死 OpenAI 系）。

### vs Cursor（2026 年状态：Composer 2.5 自研模型、Tab 补全、Cloud Agents、Bugbot、Router）

| Cursor 有、本项目没有/弱 | 差距定性 |
|---|---|
| **Tab 补全模型**：预测下一个 diff/光标移动，多行整编辑 | **P0 硬差距**。本项目完全没有行间补全，这是 AI 编程产品的"地基体验" |
| **编辑器级流式 diff**：ghost text diff 流式应用、Cmd+K 内联改写、编译校验后才呈现（Shadow Workspace） | **P0**。本项目 diff-viewer 是**只读查看态**（`git show HEAD` 对比），无"AI 改→流式 diff→逐块接受"编辑流。web IDE 缺 Monaco 级编辑体验 |
| **代码库索引规模验证**：全仓 embedding 索引、@codebase 语义检索 | **P1**。本项目有 `codebase_indexer.py` 但无大规模（10万+文件）验证、无增量索引产品化 |
| **Auto Router**：按任务复杂度自动路由模型（Intelligence/Balance/Cost 三档） | **P1**。本项目有 llm_budget_governor 预算降级，思想接近但没有面向用户的路由产品 |
| **Bugbot PR 评审**、Automations（/automate 自然语言常驻自动化）、GitHub triggers | **P1** |
| **Agent 窗口/云端 subagents**、Jira 集成 | 部分差距 |

**本项目反而领先的点**：agent 编排可视化（Kanban/DAG/Swarm 拓扑）比 Cursor 丰富；多端覆盖（Cursor 有 CLI+mobile，但无小程序端）；成本治理颗粒度（预算门控+账本+配额+积分倍数）比 Cursor 的 usage pool 细；MCP 管理 UI 与市场。

### vs Trae / Trae Solo（字节：SOLO Coder/Builder，需求→编码→测试→预览→部署闭环）

| Trae 有、本项目没有/弱 | 差距定性 |
|---|---|
| **端到端部署管道**：一键预览/部署（Vercel 等）、15 分钟从需求到上线 | **P1 硬差距**。本项目 work-panel 能预览但不能部署 |
| **设计稿→代码**（Figma 转码，准确率 92%）、浏览器元素级圈选修改 | **P1**。本项目 CDP 能执行 JS 但无圈选编辑产品化 |
| SOLO 模式三栏驾驶舱（任务管理+对话+编辑器）多线程并行 | 本项目有 agent-kanban/teams 但缺统一"驾驶舱"产品形态 |
| Builder 一句话生成完整项目 | 能力等价物是 agent+workspace，但无 0-1 建站专用模式 |
| 免费+隐私模式 | 商业层差异 |

**本项目反而领先的点**：Trae 理解范围是"文件级/小型模块级"（超 10 万行全局解析弱），本项目有 AST 索引+KG+RAG 三路上下文（虽然未验证规模）；多语言 5 国语言 i18n；桌面/CLI/移动多端齐发。

### vs Qoder（阿里：Quest 模式、Repo Wiki、Spec-Driven、10 万文件级上下文）

| Qoder 有、本项目没有/弱 | 差距定性 |
|---|---|
| **Repo Wiki**：自动生成架构/接口/函数注释知识库，实时同步、多人协作 | **P1**。本项目 `knowledge_graph.py` 是实体/关系图，不是面向人的文档型 Repo Wiki |
| **Spec-Driven 工作流**：目标→需求澄清→架构 Spec→人工确认→并行分模块开发→测试+覆盖率+性能报告 | **P1**。本项目有 plan_mode 但无"Spec 文档→确认→并行执行"的强流程产品化 |
| 10 万文件/百万行深度检索（实测 10 万行 SpringBoot 100% 调用链解析） | **P1**。本项目索引无此规模实证 |
| Quest 云端异步任务（断点续传） | **P1**。且本项目 agent 会话用内存 SessionManager（`apps/api/src/routes/agent-runtime.ts`），**不落库**，重启即失——这是比 Qoder 更落后的点，必须先修 |

**本项目反而领先的点**：治理体系（rbac/prompt_guard/network_guard/预算门控）比 Qoder 公开资料所见更细；MCP 双端+OAuth。

### vs WorkBuddy（当前宿主产品）

| WorkBuddy 有、本项目没有/弱 | 差距定性 |
|---|---|
| **定时自动化产品**（自然语言→RRULE 定时任务、一次性提醒，用户侧 UI 配置） | **P1**。本项目无对等的用户侧 automation 面 |
| **分层记忆体系**（云画像+对话检索+项目记忆，自动写入/自动蒸馏 30 天日志） | 本项目有 long_term_memory/session_summarizer，但无"自动蒸馏+分层作用域"的产品化 |
| **Skill 生态闭环**（find-skills→市场安装→安全审计→自动积累回写） | 本项目有 skill-library/技能市场，但无安装前安全审计门禁和跨项目 skill 复用 |
| **Connectors/Experts 插件生态**（外部应用连接器+专家角色推荐） | **P2** |
| Artifact/内联可视化（SVG/HTML widget 流式渲染） | **P2**。本项目 artifact 仅渲染工具产物图片/文本，无可交互 widget |
| MCP App 面板、浏览器预览面板 | 本项目内置浏览器交互深度反而更强（CDP 级） |

**本项目反而领先的点**：后端工程化（999 模型同步、成本账本、分布式限流 Redis Lua、admin 后台体量）远超 WorkBuddy 这种轻协作产品；多 agent 编排、KG、自愈引擎是 WorkBuddy 没有的。

## 四、UI / 交互 / 样式专项对比

**本项目做得到的（有证据）**：
- 输入工具栏功能密度（斜杠/@/模板/Skill/附件/语音/上下文环/权限切换）超过 Cursor Chat 和 Codex web
- 工具调用过程可视化（`tool-call-card.tsx`、`agent-task-progress-pane.tsx`、DAG/Swarm 视图）—— 竞品中只有 Claude Code Agent Teams 级别的可视化可与之相比
- 内置浏览器四级降级 + CDP 实时交互 + F12，是全部 5 个对标产品中最深的浏览器集成之一
- Ctrl+K 命令面板、Shift+Tab 权限循环、Ctrl+1/2/3/4 模式切换的快捷键体系完整
- 5 语言 i18n（zh-CN/en/ja/ko/zh-TW）+ 主题系统 + 响应式移动适配

**硬缺口（对标全部落后）**：
1. **无编辑器**：web 端没有 Monaco/CodeMirror 级代码编辑面。Cursor/Trae/Qoder 的核心交互是"在编辑器里和 AI 共处"，本项目是"在聊天窗里指挥 agent"——交互范式差异，不是补丁能解决的
2. ~~**无对话分支/fork**~~ **勘误(2026-09-07 复核为误报)**：后端 branch 端点(2026-08-30,chat.ts)+api-client.branchConversation+前端 ihui:branch-message 事件全链路已存在,仅会话列表下拉无入口。
   **修复记录(commit 1e9b1d2c23,已推三仓)**：①KaTeX 公式渲染已接入(remark-math+rehype-katex);②Artifact 画布(html 产物 sandboxed iframe 预览|代码切换)已实现;③agent-runtime 会话 PG 持久化(新表 agent_runtime_sessions+write-through/惰性恢复)已落地,本地 PG 迁移已应用。
3. **无 KaTeX 公式渲染**：全仓无 katex/remark-math（react-markdown 生态一行依赖的事）
4. **无可运行 Artifact 画布**：Trae Builder/Cursor Canvas/WorkBuddy widget 都能交互预览，本项目只能看
5. **@ 引用只有文件级**：无符号/定义/文件夹级引用
6. **agent 会话不持久化**（内存 SessionManager）：交互层表现为刷新丢上下文

## 五、差距分级与行动优先级

## 六、"远超几年"的真实回答

- **能宣称领先的说辞**（有代码证据，可对外讲）：① 8 端全形态覆盖（web/桌面/CLI/移动/小程序/浏览器扩展）无竞品做到；② MCP 生态完整度（client+server+三 transport+OAuth+市场+超级聚合）为第一梯队；③ agent 编排可视化深度（Kanban/DAG/Swarm）领先；④ 治理与成本体系（预算门控/账本/配额/RBAC/注入防护/自愈）颗粒度超过所有对标产品公开可见的实现。
- **不能宣称的**：编码智能深度（模型层、Tab 补全、编辑器体验、大规模索引、公开评测成绩）全面落后，其中模型层差距**无法用工程追平**，只能靠接入更强第三方模型缩小。Trae（免费）/Cursor（$20）已把"编辑器级 AI 体验"的门槛抬到本项目需要 2~3 个专项（P0-2/P0-3/P1-4）才能追平的位置。
- **一句话**：广度是真领先，深度是真落后；"远超几年"对外不可讲，"单点超车（内置浏览器、agent 可视化、MCP、治理）+ 多端覆盖第一"是真实且站得住的定位。
