# 桌面签名 & 部署 Secrets 注入指引（2026-09-07）

> 这是**全项目唯一剩余的用户侧动作**。其余签名/部署链路已全部在本机闭环。
> 背景：GitHub 仓库级 secrets 从未配置 → release-desktop 签名失败 + 蓝绿部署从未成功。
> 本机 token 无 API 权限（实测 401），secrets 只能由你在 GitHub UI/CLI 注入。

## 1. 桌面更新签名（2 个 secrets）

新签名密钥对已于 2026-09-07 生成并实测签名成功：

- 私钥：`C:\Users\Administrator\.tauri\ihui-updater.key`（已加密保管，**勿泄露、勿删除**）
- 私钥密码：`C:\Users\Administrator\.tauri\ihui-updater-password.txt`（本机保管，不入库）
- 公钥：已写入 `apps/desktop/src-tauri/tauri.conf.json` 的 `updater.pubkey`（指纹 B5D7E67EA2B1DB08）

在仓库根目录执行（需要你登录的 `gh`，或到 GitHub 网页 Settings → Secrets and variables → Actions 手动添加）：

```powershell
gh secret set DESKTOP_TAURI_PRIVATE_KEY < "C:\Users\Administrator\.tauri\ihui-updater.key"
gh secret set DESKTOP_TAURI_KEY_PASSWORD < "C:\Users\Administrator\.tauri\ihui-updater-password.txt"
```

> ⚠️ 注意：`gh secret set` 按文件**原样**读取，请确保文件末尾无多余空行；网页添加时复制整个 base64 内容。

注入完成后：到 Actions 对最近一次失败的 `release-desktop` run 点 **Re-run**，即可产出带 `.sig` 的 0.1.x 安装包，自动更新 feed（latest.json）恢复工作。

## 2. 蓝绿部署（3 个 secrets）

```powershell
gh secret set DEPLOY_HOST "<你的服务器 IP 或域名>"
gh secret set DEPLOY_USER "<SSH 用户名>"
gh secret set DEPLOY_SSH_PRIVATE_KEY < "C:\path\to\你的私钥文件"
```

- 私钥文件需为 OpenSSH 私钥（`-----BEGIN OPENSSH PRIVATE KEY-----`），且公钥已加入服务器 `~/.ssh/authorized_keys`。
- 注入后 push 触发 `deploy/nginx/**` 变更或手动跑 blue-green-deploy workflow 即可验证。

## 3. 安全提醒

- 两个文件都建议移入你自己的密码管理器后删除明文文件。
- 若怀疑泄露：本机 `cd apps/desktop && npx tauri signer generate --ci -w <新路径>` 重新生成，替换 `tauri.conf.json` 的 `updater.pubkey`，并重注 secrets。**私钥/密码丢失 = 已发布客户端无法自动更新**（不影响安装包本身）。
