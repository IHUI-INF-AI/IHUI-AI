# 压缩质量回归评测集(compaction-eval / D122)

本目录是上下文压缩质量的**固定回归评测集**与首份基线的存放点。执行器在
`apps/ai-service/scripts/eval_compaction.py`,评测任务冻结在 `tasks.json`。

## 用法

```bash
cd apps/ai-service
./.venv/Scripts/python.exe scripts/eval_compaction.py             # dry-run(默认,零成本,不调 LLM)
./.venv/Scripts/python.exe scripts/eval_compaction.py --live      # 真跑(调 LLM,量真实答题正确率)
```

- dry-run:走**真压缩管线**(`app.core.context_compaction.compress_messages_if_needed`,
  与 `agent_loop_v2` 生产路径同源,ratio 档),零成本、不落库、不连生产。
  产出「压缩率」「事实保持率(压缩后上下文确定性可见性)」;回答判定列为「判不出(待真跑)」。
- `--live`:在压缩前后各调一次 LLM 回答 final_question,用结构化判分器出「通过/失败/判不出」。
  通道:env `EVAL_LLM_API_BASE` / `EVAL_LLM_API_KEY` / `EVAL_LLM_MODEL` 优先,否则免费 keyless
  通道(pollinations)。测试隔离:不落库、不连 8810/8811。
- 报告落在本目录 `outputs/compaction-eval-baseline-<日期>.md`,随改动一次提交交付。

## 评测集结构(tasks.json v3)

每任务:20 条消息(1 system + 19 轮对话),`context_limit=5200`(已实测稳定触发真压缩,
trigger=ratio、压缩后 tokens 下降、摘要结构合法);关键事实(3-5 条/任务)按 `turn` 声明位
放在对应消息**开头** —— 远层摘要只保留消息前 120 字符,事实落前缀内则确定性可见性可达上限,
落 120 字符之后则直接暴露截断丢失(两种落法都是合法设计,调整必须附当期数字)。
尾部 3 轮短确认,落在 keep_recent=6 保留区内,考「近窗免压」一维。

## 门禁(压缩策略改动必附当期评测数字)

任何影响上下文压缩行为的改动都必须重跑本评测并附当期数字,包括但不限于:

- `app/core/context_compaction.py` 的摘要/分层/保留/截断策略改动;
- `AGENT_COMPACTION_MODE` 档位(off/ratio/full)取值、默认值或解析行为变化;
- 触发/目标阈值(0.88/0.60)或 keep_recent 等跨端统一常量变化;
- TS 侧 `@ihui/context-compaction` 的同步改动(本评测 Python 管线与其逐语义对齐)。

验收基线:dry-run 全绿(结构校验/真管线触发/判分器三态) + 压缩率与事实保持数字。
基线报告见 `outputs/compaction-eval-baseline-2026-10-02.md`(压缩率 40.9%,事实保持 32/32)。

## 已知边界(如实登记)

- LLM 语义压缩档(`AGENT_COMPACTION_MODE=full`,`compact_with_llm`)在 dry-run 仅做可调用性
  验证(stub 摘要,明确标注模拟),其质量数字不进基线表;full 档离线质量评测属遗留项。
- dry-run 的事实保持率是**信息上限**,不是模型答题正确率;后者只有 `--live` 能量到。
  两种数字在报告中分开列示,不得混用。
- `--live` 依赖外部 LLM 通道可达性;通道不可达时回答判定为「判不出」,不冒充通过。
