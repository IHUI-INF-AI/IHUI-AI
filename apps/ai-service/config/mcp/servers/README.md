# MCP 动态注册受信配置目录(仓库受控来源)

本目录只放**受 git 版本控制**的 `*.json` manifest(一台 server 一份文件)。
`mcp_registry` 加载时会逐个 `git ls-files --error-unmatch` 校验,未跟踪/符号链接文件一律拒绝。

schema 最小示例(真实接入时新增 `{namespace}.json`):

```json
{
  "schemaVersion": 1,
  "namespace": "team",
  "transport": "stdio",
  "description": "团队内部只读检索 server",
  "command": "npx",
  "args": ["-y", "@acme/mcp-search"],
  "env": { "ACME_TOKEN": "${ACME_TOKEN}" },
  "tools": [
    { "name": "search", "tier": "read" },
    { "name": "update_index", "tier": "write" }
  ]
}
```

硬规则:

- `tools` 必须逐条显式声明 `tier: read|write`;远端出现未声明工具 → 整台拒绝。
- 远端 annotations 只能升级(read → write),不能降级。
- 本目录的 `env` 只允许 `${ENV}` 引用,禁止字面量值(含密钥);用户私密配置请放
  `~/.ihui/mcp-servers/`(该目录同样按本次架构的信任模型校验)。
- 可选 `commandEnv`:声明一个环境变量名;该变量存在非空值时覆盖 `command`,
  否则回落到 `command`。换机器/换安装路径无需改清单。
- stdio 二进制缺失在激活前即拒绝,错误码 `COMMAND_NOT_FOUND`,消息含期望可执行名、
  已查 PATH 目录、安装途径与环境变量覆盖方式,不抛裸 spawn/ENOENT。
- `namespace` 为服务器身份,重复即拒绝,绝不覆盖。
- 生效时机:进程启动时自动加载;管理员可 `POST /api/mcp/registry/reload` 重扫
  (无 body 路径参数),`GET /api/mcp/registry/status` 查看已加载来源/哈希/分级。
- 工具暴露名固定 `mcp__{namespace}__{tool}`;审计只记录来源路径、文件 sha256、
  工具名/分级与 env **键名**,不记录任何值。
