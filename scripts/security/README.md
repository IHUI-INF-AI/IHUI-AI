# 安全体系（scripts/security）

一套在本机与仓库内自持运行的安全能力：**采集 → 判据 → 阻断 → 归因 → 取证 → 上报 → 自愈**。
不依赖任何容器运行时（本仓明令禁用 Docker）。

## 一条命令看全貌

```powershell
node scripts/security/security-audit.mjs          # 十六面总审计（配置面 12 + 对抗面 4）
node scripts/security/security-audit.mjs --json   # 机器可读
```

| **服务与配置面**          | `check-service-baseline.mjs [--json] [--alert] [--baseline --confirm]`                                              | 账号面盯「谁能进来」，这一面盯**「门本身有没有被改松」**。三个面：nssm 环境变量 / 启停策略 / 对外监听端口。把 `IHUI_EDGE_SECRET_MODE` 从 `enforce` 改成 `observe`、把 `IHUI_WAF_MODE` 关掉、把 `Start` 从 `AUTO_START` 改成 `DEMAND_START`、在 `0.0.0.0` 上多开一个监听端口——四件事做完服务照常跑、原有判据照常全绿，防线已换了一副样子。<br>**三条设计纪律**：① **凭据值只存指纹**——`IHUI_EDGE_SECRET` 与 `IHUI_ADMIN_PASSWORD` 明文躺在 nssm 里，值只在进程内存存在，入基线的是 `sha256:16位`；② **端口只记「对外 + 固定段」**（`0.0.0.0` 且 `<49152`），RPC 动态段每轮换号记了就是每天假警；③ **关键开关有强制期望、不看基线**——基线可能就是在被改松之后建的。<br>**四处本模块实测踩到的坑（全部单测钉住）**：① `IHUI_EDGE_SECRET_MODE` 含 `SECRET` 字样，按 `SECRET` 脱敏会把它变成指纹、导致每轮误报 breach 且基线里看不到最关键开关的真实值 ⇒ 加 `SWITCH_SUFFIX_RE`（`_MODE/_ENABLED/_TYPE/...` 一律不算凭据）；② env 是**两层**结构（服务 → 变量），直接喂 `diffEnv` 只比到「服务名在不在」、**变量值改了完全看不见** ⇒ 必须 `flattenEnv` 拍平；③ `IHUI-API-ROUTER` 只监听回环，`observe` 是分层设计而非缺口，一刀切要求 `enforce` 会每轮误报 ⇒ `CRITICAL_ENV` 按「服务 + 键」逐条写；④ **采集全失败会被判成「关键开关全部缺失 ⇒ 被改松」**，把工具没取到数据报成有人在攻击 ⇒ `totalCurrent===0` 必须排在关键开关检查**之前**。<br>**端口按进程名分流**：微信开发者工具实测在几分钟内从 `11940` 换到 `38099`，按端口号拉黑追不上 ⇒ `OBSERVED_ONLY_PROCS` 按进程名排除，进 `observed` 单列（台账看得见、不参与 breach）。实测基线：17 项环境变量 / 12 项启停策略 / **3 个受管对外端口**（`5130` spoolsv、`8801` WEB-ROUTER、`8805` 沙箱 node），`2968`(Epson)、`38099`(微信工具) 归入仅观察。双挂 autoban（10 分钟）+ 独立计划任务 `\IHUI-Security-Service-Watch`（30 分钟），实测 `ok / 32 项一致 / 2651ms` |

| **证据链区间核验**        | `GET /__evidence/range?from=<seq>&to=<seq>`（公网）                                  | 单条编号只能证明「这一条在册且未改」，证明不了「这一整段连续」—— 中间被挖掉一段再补一段，每条单独看都合法。区间回执一次给出 `[from,to]` 内每条的 `seq/ts/prevHash/payloadHash/hash`，并由服务端**独立验一遍首尾相接**（`rows[i].prevHash === rows[i-1].hash`），核验者不必自己拼。<br>**三条纪律**：① **区间有缺口就如实报**（`gaps` + `complete:false`），绝不「过滤掉缺的」冒充完整 —— 数组拼起来看着整齐，中间少一条就等于链断过，这正是本单位最容易犯且最难被外部发现的错；② **跨度上限 200**（`RANGE_MAX_SPAN`），不设上限等于给扫描器一个免费的全量导出接口，上限的意义不是省资源，是让「导出全链」必须分多次、可被计数；③ **`payloadHash` 必须给** —— 自证公式里就有它，不给等于让第三方无法独立复核；它是 SHA-256，不可逆，给出它不会回显攻击者的 IP/UA/载荷。<br>**实测**：`from=280&to=290` → 200、`count:11`、`complete:true`、`broken:[]`、首尾可续接；挖掉一条 → `complete:false`、`gaps:[n]`；篡改一条 hash → 由本层独立报出断点（不是靠第三方发现）；`to-from>200` → 400 |
| **证据编号公开核验**      | `GET /__evidence/<EV-编号>`（公网）                                                  | 对外文案一直写着「编号可被任何第三方核验」，但此前只有内部 `verifyChain` 能验 —— 攻击者拿到 `EV-xxx` 无从核对。**承诺悬空比不承诺更糟**，因为它把一个没兑现的能力印在了对手会读的页面上。本件把这句话落到一个真端点：`https://www.aizhs.top/__evidence/EV-xxx` 返回四要素（`seq` / `prevHash` / `ts` / `payloadHash`）+ 声明 `hash` + 自证公式，**第三方不需要我们的任何源码，照公式自己算一遍就能确认这条记录没被改过**。<br>**为什么放在回源鉴权之前**：核验者就是攻击者本人，他没有边缘密钥。代价是拿不到那一层保护，所以端点内自己做三件事：① **自己过一遍 WAF**（否则它成了一条绕过 WAF 的公开路径，实测 `..%2f` 载荷在此处被 `path-traversal` 判 403）；② **只回哈希与时间，绝不回显 IP / UA / 载荷** —— 核验是证明「存在且没改」，不是把攻击内容再投递他一次；③ **读不到链文件回 503，绝不回 `found:false`** —— 「不知道」和「没有」是两件事，把取不到说成「查无此号」等于替篡改打掩护。<br>**三条形态纪律**：不存在的编号回 **404 且与路径不存在同形**（不给枚举者额外信号，实测 34B）；非法编号回 **400**（`../etc/passwd` 这类根本进不到查找）；**5 秒缓存**（282 条不必每请求读一遍，缓存久了又会让人质疑「看的是不是旧的」）。<br>**实测**：本地 `EV-493307C003` → 200 带完整回执；公网同路径 → 200/380ms；`EV-0000000000` → 404；第三方独立重算 `sha256(`${seq}|${prevHash}|${ts}|${payloadHash}`)` 与声明 `hash` 一致（改一位立刻对不上，较早的 `seq=234` 同样可自证）。拦截页 `已固定` 段同步加了核验入口行（`NOTICE_VERSION` 3 → 4），否则攻击者拿到编号也不知道去哪查 |

## 边界（写死，不要越）

- **只做阻断、取证、上报**。不对攻击源发起反向攻击或侵入（违法，且会把受害方变成加害方）。
- **归因止于 ASN / 云厂商**。把 IP 指认到自然人只能走云厂商滥用举报或公安协查，报告里不得出现猜测性指认。
- **不动生产**。防火墙改动必须可回滚（改前备份原规则到 `.ihui-agent/state/`）。**8801 必须不限来源放行**：`aizhs.top`/`www.aizhs.top` 经腾讯 EdgeOne 回源，出口 IP 不固定、无段可白名单；2026-11-24 16:4x 曾收窄为仅回环+内网，EdgeOne 回源立即 522、登录页挂掉，17:0x 回滚。拦截面 = WAF(enforce) + edge guard(enforce) + rate-limit 三道。降级手段是 `IHUI_WAF_MODE=observe`（改 nssm 环境变量后重启，只记不拦），排查误报时用，不要用 `off`。
- **对外文案四条红线**（`block-notice.mjs` + `notice-ledger.mjs` 单测钉住）：① 不冒充国家机关——可写「按国安级对抗标准建设」（本项目自定等级），**不得**写「我们是国家安全机关/国安局认证」，英文同样禁 `national security agency / FBI / CIA`；② 文案说"已取证"就必须真有记录（`ref` 落 `block-notice.jsonl` 并 10 分钟内入链），否则是空口威慑；③ 不写规则 id/阈值/端口/内部路径——那是把绕过说明送给对手；④ 说"第 N 次"就必须真数过（ledger 从日志尾部重建），否则重启后对老对手说"这是你第 1 次"——**一句假话就废掉整篇文案**。
- **本仓不引入任何容器运行时**。容器相关只做静态判据。

> **`IHUI-AI auto-evolve` 的预期形态（2026-11-26 实测定档，改回旧形态即属回归）**：`TimeTrigger` + `Repetition/PT1H`（**不写 `Duration`**）+ `S4U` + `StartWhenAvailable=true` + Action 直接钉 `D:\DevEnv\runtimes\node22-lts\node.exe "…\scripts\auto-evolve.mjs" --once`（WorkingDirectory=仓根）。四个「为什么」都踩过：① 旧定义是 `LogonTrigger`，无人登录时 `Next Run Time` 恒 `N/A` ⇒ **从不自动跑，而 `Last Result` 一直是 0**（派单不该等人登录）；② 旧定义 `InteractiveToken`，自动触发拿不到交互会话令牌（`id=101` / `2147943568`=`0x80070490`）⇒ 每小时都在触发、每次都起不来；③ 旧 Action 经 `auto-evolve-hidden.vbs` 间接启动，VBS 在 `IHUI_NODE_BIN` 为空时回落到裸 `node.exe` 交给 PATH，而本机 node 只在**用户** PATH 里、S4U 不保证继承 ⇒ 静默失败（`Last Result` 照样 0）；④ 写 `Duration` 会在窗口到期后永久停摆。**实测判据**：`Last Run Time` 是自动时刻（不是手动补跑）、事件 `id=201` 的操作是 node 绝对路径、台账 `.ihui-agent/state/auto-evolve-ledger.jsonl` 新增一条 `dispatch`、`Next Run Time` 已排到下一小时。


> **`<Repetition>` 里写 `<Duration>` 会让任务在一段时间后永久停摆（2026-11-25 实测踩到）**：新建 `IHUI-Security-Evidence-Intake` 时写了 `<Duration>P1D</Duration>`，`StartBoundary` 又是当天 00:00 —— 重复窗口等于 `[当天00:00, 次日00:00]`，跑到 23:58 就再也没有下一次，`Next Run Time` 静默退回 **`N/A`**，任务从此不再触发，而 `Last Result` 一直是 0、`Status` 一直是 `Ready`，**没有任何判据会报它死了**。正解是**不写 `<Duration>`**（= 无限重复，本机其余 5 个哨兵都是这个形态）；若确需有界，写 `P3650D` 这类远超服役期的值（`auto-evolve` 就是这么写的）。排查口诀：`Next Run Time` 变 `N/A` 而 `Status` 仍是 `Ready` ⇒ 先去查 `Repetition` 有没有 `Duration`。
>
> 同日还修了两个真故障：`IHUI-Pool-Local-Reextract` 的 `Last Result=1` 真因是 `reextract-hidden.vbs` 里写死了 `C:\Program Files\nodejs\node.exe` 与 `C:\IHUI-AI\...` 两个不存在的路径（仓库从 `C:\` 搬到 `D:\` 后没重跑生成器），重跑 `register-pool-sync-task.mjs --register-reextract` 刷新即 rc=0；`IHUI-AI auto-evolve`「2.9 天没跑」真因不是触发间隔，而是 `InteractiveToken` 在无人值守时拿不到该用户的交互令牌 —— 事件日志 `id=101`、错误值 `2147943568`(`0x80070490` = `Element not found`)，改 `S4U` + `StopOnIdleEnd=false` 后 `Last Result=0`、无 `id=101`（`sessionCommandTemplate` 是纯控制台命令，结构上不需要交互会话）。

> **为什么不给主机三查/态势单独建计划任务（2026-11-24 实测）**：新建的 SYSTEM 任务执行新脚本会永久停在"运行中"（6 分钟不退出，且看不到 node 进程），而同机既有 4 个 SYSTEM 任务全部 `Last Result=0` —— 差异只在"脚本是否已被 HIPS 学习过"，无界面会话里没人点"允许"。改为由已信任的 `IHUI-Attack-Attribution` 串行派发下游，子进程继承已信任的父子链；每次派发的 rc/耗时/末尾输出写 `.ihui-agent/state/downstream-dispatch.jsonl`。实测下游 869ms / 259ms，任务 `Last Result=0`。
